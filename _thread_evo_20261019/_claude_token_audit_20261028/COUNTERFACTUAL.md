# Claude 分工反事实：完整模型与敏感性

本文件所有移出比例、回执长度、失败率和返工预算均为**假设**。只有历史usage/价格折算、上下文长度、候选任务簇数量和冷写统计来自记录。没有实施新架构，没有观测新架构的实际节省或质量等价。外部GPT/Codex的模型Token费用按用户要求为0。

## 成本方程

`新Claude成本 = 原历史请求总额 - 移出请求的加权毛成本 + 冷写转移回补 + 新委托 + 回执读取 + 新验收 + 新增缓存过期 + 工具/系统变化 + 技术接管返工期望 + 质量回归返工期望`。

亦即“保留工作 + 新协调 + 读取 + 验证 + 缓存/上下文变化 + 异常返工”。本账本基线为 $514.733106165，将其归一化100。对每个请求，假设可移出份额 r，毛删除=sum(r×实际请求成本)。A保留所有A/B/C/D/G/H；B保留A/B/G/H；C保留A/G/H，最多试替部分B。历史G/H仍全保留，再加新委托/验收，是刻意保守，避免把旧协调可以全部复用当成免费。

**模型没有严格下界保证。** 保守/乐观只是下列参数组合；工程或质量事故可能比压力情景更差。所有点估计显示1位小数是为了便于复算，不代表预测精度。

## 三种架构的职责和计算单位

- A：原Claude核心职责不变，状态机处理等待/日志/格式/统计，仅在异常或阶段完成回执。111个阶段回执包是建模单位假设，不是实测将来通知数。
- B：Claude给研究目标、实验契约与艺术验收；Codex接工程、排障、调度、确定性处理；GPT创作/初评。历史C/D触发根任务中有161个任务簇，128个至少含2次工程请求；按128个交接包建模，不代表每一簇都能独立委托或都已通过质量验证。
- C：B上让GPT承担更多中间筛选/解释，Claude在关键设计、评分矛盾、失败和完整成品时介入。C/D/E/F有209个触发簇，176个至少2请求，按176包建模。低频不等于只看分数，整首门和矛盾门仍在。

包数还乘factor以模拟拆分/合并；同一个历史根可涉及不同子任务，真实包数需小范围实践标定。中间情景A/B/C有效包数分别111/128/176。

## 每个新包的成本

校准历史主会话输入中位数 `K=430392`。Opus读费为0.20/MTok，1h写为8/MTok，输出20/MTok。新文本按1h写入保守计价；一小时内重复引用新内容可能更便宜。没有假设每次K都普通全价输入。

- 委托（A为0）：每包一个Claude读前缀K + 输出800 Token的任务书 + 下一请求缓存写入该800 Token，即 `(0.2K + 20×800 + 8×800)/1e6`。
- 回执读取：每包 `0.2K/1e6 + 8×packet/1e6`，packet为表中token参数。
- 验收：每包输出600 Token，另以full_review概率重读12000 Token diff/结果，公式 `(20×600 + p_full×8×12000)/1e6`。验收思考/输出并未设0；超出该预算时收益会下降。
- 额外过期：每包以p_expiry概率让K从暖读变成1h冷写，增量 `p_expiry × K × (8−0.2)/1e6`。它是**相对原历史额外发生**的概率，不是总缓存未命中率。
- 工具/系统变化预算：A/B/C分别 $0.3/$2/$5，显式假设，实际要量测前缀变更影响。不是已发生的插件费用。
- 技术接管：每包以q_tech概率由Claude重新接手，单次$1.5，期望 `N×q_tech×1.5`。
- 质量事故：每包以q_quality概率发生额外Claude返工，单次$5，期望 `N×q_quality×5`。$5是情景预算，参考已查到事故/排障的量级；历史没有足够独立事故样本估计概率或尾部损失。
- 移出请求若承载大冷写，则相应写成本全回补为下一保留请求承担，不兑现这部分“节省”。不为删除历史、减少压缩或新会话短上下文预先加收益。

这些是折算预算，不是逐Token回放新会话。历史前缀内容会变，新增回执本身的重复读取也没有完整序列模型；包数倍率、额外过期概率和工具变化预算吸收部分不确定性，仍有不可建模残差。

## 结果返回多长：字符不是Token

中文300字回执先用250–600 Token作假设区间，1500字结构化报告用1200–3000；实际必须让目标Claude tokenizer或usage测量。这里没有把“字数÷固定常数”当实测。

| --- | --- | --- | --- |
| 300字短回执 | 250–600 | 0.0020–0.0048 | 每次还要读K暖前缀$0.0861，输出/验收另计 |
| 1500字报告 | 1200–3000 | 0.0096–0.0240 | 未必比摘要产生更好决策 |

B中间假设25%交付需要重读12000 Token。若提高到100%，仅该新增读取就多$9.216、净节省再下降1.79个百分点；若每包多2次暖Claude审阅响应且各输出1000 Token、写入2000 Token，128包另约$31.25、下降6.07个百分点，冷写另计。故“Claude完全重做审查”会吞掉收益。应回传短摘要、差异列表、通过/失败测试、输入输出hash、运行manifest与文件路径，按异常再读原文。关键艺术作品依然完整读。

## 成功、失败与返工敏感性

以B中间参数，一个成功交接包（不含保留的历史判断）新增委托约$0.10848、回执$0.09088、验证$0.036，共$0.23536；工具变化预算平均另$0.01563，额外过期期望$0.33571。若Codex技术失败但自行修复且只回最终结果，Claude模型增量可以接近0，耗时会增加；若要求两次额外Claude暖接触，每次前缀+400输出+400输入约$0.0973，共$0.1946，未含缓存过期。若Claude接手，按每次再加$1.5预算；质量回归按再加$5预算，并可能出现远大于此的尾部损失。

B中间q_tech=6%、q_quality=2%，相应期望$11.52/$12.80。将两者各提高1个百分点，总费用增约$8.32、净节省降1.62个百分点；C同变动约$11.44、降2.22个百分点。把质量事故单价从$5改成$20，B中间多$38.40、少省7.46个百分点；C多$105.60、少省20.52个百分点。这正是没有替代质量证据前不能承诺节省的原因。

Codex/GPT执行时间、排队、并发和限流无Claude Token单价，但必须进入验收：历史已有20秒全局提交间隔、跨模型误回收和传输恢复问题。建议影子任务设相同提交限制和截止时间，比较可复现性、错误恢复、变量保持、最终成品质量；目前无新架构计时样本，不能编造它更快。GPT调用多本身不是成本问题。

## 可执行的质量门（本次只建议，未实施）

冻结研究契约字段：模型ID、推理强度、联网/工具权限、渲染system/user请求、Bead完整输入、分段/小节、提示词与评委版本、采样/并发与提交条件。工程提交只许修改白名单传输/调度字段；所有语义差异显式列出。先对现存输入离线生成请求manifest做差异核对，再对历史认可样本/已知坏样本做盲判校准，最后才在用户批准的少量真实实验中检验非劣性。任何评委矛盾、整体倒退、契约不一致都暂停晋级并交Claude/用户。

若只实施一项，优先A式状态机；在已验证的工程子任务上逐步进入B。C应等工程和初筛非劣性证据充足后再考虑。当前没有架构被证明同时达到表中净节省与质量硬约束。
