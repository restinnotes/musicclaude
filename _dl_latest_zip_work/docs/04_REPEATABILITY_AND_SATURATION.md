# 04｜独立重复、方差、跨题与语义饱和：冻结执行设计

## 1｜什么叫每个模型独立重复 5 次

- 单次重复 = 相同 job 输入逐字不变，单独 `gpt2 ask` 新建独立会话；不能 `resume`，不能把先前输出加入新请求。
- r01–r05 是**最小采样**，不是饱和的证明；两个模型公平配对，同一 job 各 5 次。
- 原 16 个 job：A（6批，每批6条 E5），B（5 个站点），C（5 个站点）。因此主实验 16×2×5=160 次模型调用；A 有 36 个不同案例而不是 180 道题。
- 不允许对结果较差的一方单独追加重复数。先冻结评分标准，再看结果；不能根据哪一篇写得最漂亮决定应该拿哪篇评测。
- **提示词相同≠分布完全相同**：时间、服务版本/降级状态、模型采样随机性、批次内案例顺序仍可影响结果。两个模型交错执行，每轮交替首发模型，记录时间/真实路由/耗时/失败。无法控制的因素写成局限。

## 2｜三类任务分别测什么

**A／E5 现成关系的分类**：同一个 blind ID 看 r01–r05 的 verdict 分布与关键理由是否稳定，例如 3/5 restatement + 2/5 insight 必须标“不稳定”；不能压成多数“稳定重述”。历史 24 条 Claude 裁决只是非人工的校准参考，不等于真实正确性；统计跨题差异时以案例为单位，题内多次结果只用于估计该案例判词分布，不当作独立的总体样本。

**B／Thread-WHY 现成假说审核**：记录逐个 `hypothesis_id` 的 5 次 verdict 和相同/不同的错误理由。B 不负责生成全新 Thread 候选，因此这里的“饱和”只可指审查结论趋稳，不可声称新音乐理解饱和。

**C／E7 内容选择与表达**：区分（i）单次稿质量，（ii）同样 K 次机会的 best-of-K **候选**（F 可先盲选一份，若要当作质量优势仍需另一轮独立验收），（iii）核心上屏信息的跨次重现频度，（iv）K 增大带来的新增有依据语义单位。这四个指标不同，不能混为一个分数。best-of-K 的筛选标准和评审数据应隔离，避免由作者挑自己最得意的一份。

## 3｜如何定饱和/继续

- 先完成 r01–r05，再对**每个站点×模型**的 E7 稿做独立 semantic clustering：只把“听者新增的音乐关系或体验”算语义单位；相同关系换比喻不算新，无法在输入材料定位的新因果不算有效新增，优美 anchor 可另记语言价值。
- 针对 r04、r05 是否持续出现 **未在先前出现的高价值且有来源的单元**，检查所有五次，不是只检查最好的输出。存在这种增长 → 至少将该 station 的两模型一并扩到 r08。判断分歧、审稿顺序偏差和路由异常同样触发扩样。
- 在 r08 仍发现高价值新增或关键判断大幅摇摆 → 双模型扩到 r12。r12 仍继续明显增长就标记 `NOT_SATURATED` 并交主控决定是否继续，而不是设无限循环。
- `judge(F)` 是基于文本的代理审核，结论应提供源句短引、独立的语义 unit ID、首次出现的重复编号、每轮新增数量、无依据淘汰数量和冲突示例；不能单靠来源 ID 集合稳定就宣布语义饱和。
- 模型胜负可以在某一能力上先收敛，即便 E7 风格创意依然不断新增；饱和是另一条曲线，不要为了穷尽所有形容词一直生成。

## 4｜评审控制

- C 首次生成阶段隐藏旧 run124 当前段最终稿。D/G 在生成后独立构造，不可让模型看到私有 mapping 和作者名。
- D：旧 run124 与新稿的局部读者价值，*旧版是否具有更优跨站屏幕状态*不在 D 局部稿的比较内；D 的评分者仅另一模型，交换 A/B 文字顺序。分别报告两个模型相对于旧稿的变化，但不能直接以「不同评审者的 D 胜率」证明跨模型孰优。
- G：**直接比较 GPT-6w 和 GPT-5.6w** 在同一站点、同一重复号的 E7 稿，两个 GPT 都评一次并交换顺序；会出现匿名自评，故按评审模型分别展示并做敏感性分析，**不能把自评当完全独立证据**。若仍无法判定，标争议，不武断定生产模型。
- D/G 预先选择 r01/r05，若扩到 r08/r12 才新增相应固定序号。不得看谁写得好再选测试样本。
- F：C 多次稿的价值与新意边际评审，用另一模型审核，不访问作者身份；如果 prompt 或输出过长，分批但不得省略任一重复。
- 评审本身不等于人类真实听音体验；所有文本和已有历史标记都未经本轮谱/录音独立核查。

## 5｜怎么报告方差而不做伪统计

- 每题报告 `n_valid` 与各类 verdict 计数，不用“5/5”说成 100% 真准确。
- 模型之间比较按**案例/站点配对**汇总，避免把同一个音乐位置重复五次当五首不同作品；样本太小时明确不具总体统计外推性，优先展示矛盾和机制。
- 真实可用性另报失败率、pre-submit/ambiguous 类别、异常极短耗时，避免把基础设施故障记为认知质量差。
- 若 model r01 来自旧 pilot，其时间窗和失败周边环境必须公开；做敏感性分析时可分别包含/排除旧 r01。

## 6｜明确停止点

本 ZIP 只用于模型能力基线。最后由 T3/Muse 输出 evidence ZIP 给用户/ChatGPT，**不自主演化 prompt、不改生产路由、不启动完整新链**。所有无法作答的质量问题写入报告，不用新工程层掩盖。
