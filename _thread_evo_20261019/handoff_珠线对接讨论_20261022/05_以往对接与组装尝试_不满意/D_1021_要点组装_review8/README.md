2. 同一条线的 `Op61/3_成品_珠子逐字原句_F6_线A先查资料_7.67.md`：两版只差在珠子是逐字原句还是压成要点，可以对照。
3. `Op61/1_纯线_*.md`：只看线（第 2 步的产物）。

文件名末尾是盲评分数（GPT-6 + GPT-5.6，同一首曲子的稿子放在一起比）。不同轮次的评审松紧不同，**只在同一个文件夹、同一类稿子之间比较分数**。

## 现在的流程（A 路线，写线时不看珠子）

```
分段 ─┬─► 珠子 ─────────────────────────────────────────┐
      └─► 线：先写散文（N7：自己推动、不靠音乐、不编情节）   │
              → 具体化（C1：写他具体在想什么、怕什么、想要什么）
              → 凝练成机制要点（F4：每段一句加粗的机制 + ← 因为 + → 于是）
                = “F6”                                    │
                                                          ▼
                    组装：每段 = 线的要点 + 1–2 行珠子（压成要点，或逐字原句）
```

## 夜里得到的结论

1. **线的形态：要点比散文好，F6 最好。**
   - 两首曲子的盲评里，散文“一眼有内容”只有 4–6 分，F4/F6 有 9 分。
   - F6 和 F4 正面比较，F6 两首都排第一，更像人话，也更具体。
   - 例子：“想成长时最怕的不是改变，而是怕自己一变，原有的爱也变了。”“守得住体面，不等于换得回接纳。”
2. **直接从 P0 写成要点（F5）不行：** 短，但很空，“具体”只有 3.5–6 分。要先写散文把内容想透，再凝练。
3. **P0 最后一句“最后给我一篇鲜活的文章”会让模型在要点之后再补一篇散文。** 以后写要点时，要把这一句换掉，不能只在后面追加要求。
4. **“每段长短和内容相称”只靠散文提示做不到。** 加了这句，3 小节的段落仍写 100 多字；改成要点后，1–3 小节自然只剩一行。
5. **压缩损失现在有了基线。**
   - 先从原线抽出固定的因果步骤清单（每条线 40–53 步），再逐条核对。
   - 几种压缩都是约 80% 完整保留、约 20% 说弱、约 1% 丢失。
   - 之前那些“丢了 2 步还是 4.5 步”的差别，主要是评委粒度不一造成的噪声。
6. **线不适合“多跑几次再综合”。**
   - 综合版只相当于单次稿的平均水平：Op.60 8.20 对平均 8.20，Op.61 8.53 对平均 8.49。
   - 它比 4 选 1 的最好稿低 0.5–0.9 分，“具体”也最低。
   - 结论：线要多写几篇挑最好的，不要综合。珠子不一样，它每段独立，可以综合。
7. **组装：珠子压成要点（P）稳定好过逐字原句（V）。**

| | P 珠子压成要点 | V 珠子逐字原句 | 旧散文组装（对照） |
|---|---|---|---|
| Op.60 最好 | 8.53 | 7.57 | 8.47 |
| Op.61 最好 | 9.00 | 8.32 | 8.65 |
| 连贯 | 8.0–8.8 | 6.4–7.7 | 8.6–8.8 |
| 一眼有内容 | 8.6–9.1 | 7.9–9.0 | 7.2–7.4 |

   - 逐字原句常常偏长、带乐理说明，插在要点之间显得断断续续。
   - 压成要点后，读起来是一体的，原句里可感的画面也保住了，例如“胸口发紧，伸手只摸到冷冷的空”。
8. **A 路线的固有风险：** 线写的时候没看珠子，个别段落会和真实听感对不上。
   - 例：Op.60 线B 第 51–61 小节，线说“为了不再受伤而收回投入”，珠子几乎都在写“渴望升温、沉醉其中”。
   - 组装时，模型会主动避开矛盾的原句，并把矛盾标出来（`evaluations/asm2/*.conflicts.json`）。
   - 将来可以在组装前加一步检查：发现矛盾的段落，单独改线。

## 需要你决定的

1. **珠子能不能在成品里压成要点（改写），而不是只能逐字摘录？**
   - 评分和我自己读的感受都说明，压成要点明显更好。
   - 但这违反了之前“珠子只能逐字节选，不改写”的规则，所以要你定。
   - 折中方案：要点里只用原句的词和画面，不新增内容；评审里已经加了“珠子是否忠实”的检查，P 版得 8.2–9.0。
2. **线是否就按 F6 定下来？** 定下来之后，下一步是第 5 步：按视频时长再选择、压缩。
