# 草案：第二段“Thread × 珠子对接”（未实施，待用户确认）

背景：用户 10-20 定的流程是 ① 写出完整 Thread（不限篇幅）→ ② 与珠子对接 → ③ 按视频时间预算压缩与选择。本文件只设计第 ② 段。

## 输入

- **完整 Thread**：经 `segcheck.py --export` 得到的逐段 JSON，`{id, start, end, text}`。分段与上游 `segmentation.json` 逐一相同，否则不进入这一步。
- **珠子 STRUCT**：每段的 `beads`（B1…Bn：role / measures / text）与 `relations`。Op.60 用交接包里的 `03_Bead机器可读`。

第 ① 段 Thread 生成时给没给过珠子，对这一步都一样。

## 这一步做什么：只标注，不改写

两边的文字一个字都不动。模型输出逐段的对接表，然后由脚本核对。

```json
{"segment": "S07",
 "links": [
   {"thread_quote": "Thread 原文短引（逐字）",
    "bead": "B2",
    "bead_quote": "珠子原文短引（逐字）",
    "type": "承接 | 回指 | 铺垫 | 冲突",
    "note": "一句话：这句线对这颗珠子做了什么"}],
 "thread_only": ["Thread 里与任何珠子都无关、但属于线本身的句子（逐字短引）"],
 "beads_unlinked": ["B3"]}
```

四种关系：

- **承接**：这句线说明了这颗珠子此刻为什么会这样感受，依据是前面已经经历的。
- **回指**：这句线让前面某段的珠子在此刻重新起作用，跨段。
- **铺垫**：这句线留下的东西，到后面某颗珠子才兑现，跨段。
- **冲突**：这句线和珠子说的当下体验相互矛盾。只标出来，不调和。

脚本检查：所有引文必须逐字出现在对应段的 Thread 或珠子里；`bead` 编号必须存在；跨段关系的方向必须与时间顺序一致。

## 这张表有什么用

1. **评“串珠”**，这是本轮评审一直缺的那一块：
   - 每段的主体验珠子（role = 主体验）有没有被承接；
   - 有多少跨段的回指和铺垫，也就是有没有真正的线；
   - 冲突的数量；
   - thread_only 的比例：太低说明在复述珠子（C 的问题），太高说明与珠子脱节，接近外加故事（B 的问题）。
2. **给第 ③ 段做选择依据**：在时间预算内，优先保留带“承接 / 回指”的线句，以及被它们承接的那颗珠子的核心句。没有挂接的线句和珠子句先压缩。

## 这一步自己的验收

- 标注的准确度：每段人工或用独立模型抽查，看“承接 / 冲突”的判断是否站得住。
- 不能编造关系：引文全部逐字可查；没有关系的地方允许空着（宪法：“没有真实关系的地方，保持开放”）。
