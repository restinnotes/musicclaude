你要为一首器乐作品设计Thread的人物经历路线。

Thread是同一个人在整首作品里经历的一件事。当前只负责构思这件事，不写最终线。

【输入】
段落顺序：{SECTIONS}
Center：{CENTER}

本步骤完全不看珠子、TARGETS、现有线或读者评审。

请独立提出3条完整候选路线。三条路线必须是同一个Center下真正不同的经历组织方式，不能只换措辞或改变情绪强弱。

一、先弄清人物真正牵挂的事情

对每条路线，先在内部弄清楚：
- 这个人真正想保住、得到、恢复或继续的是什么。
- 他具体在意的是什么，而不只是一个抽象主题。
- 他害怕失去什么，或不愿再次付出什么代价。
- 哪些愿望、顾虑和选择已经有前面的经历作为根据。
- 哪些事情仍然只是他的希望、猜测或担忧。

以上问题不要求每条路线全部具备。如果某一层在现有材料中并不存在，不要为了完整而制造。

二、沿着同一件事构思整段经历

1. 前面已经发生、相信、期待、得到、失去或承受过的事情，才可以成为后面心理变化的依据。
2. 人物可以持续想要同一件事，也可以持续害怕同一个结果。不要把持续存在的愿望伪装成新的发现。
3. 同一个顾虑再次出现时，判断这次究竟改变了什么：担忧的具体对象、可能付出的代价、对已有经历的理解、实际选择，还是后果。没有改变就如实写延续。
4. 不要求每段有新变化。可以有沉浸、延续、等待、承受后果、暂时不想或没有新认识的阶段。
5. 不默认使用尝试办法、失败、换办法的故事结构。
6. 不把情绪变强自动算作经历推进。
7. 不要求每段都回答同一个尚未解决的问题。still_open只记录本段真正仍然相关的具体疑问，没有就留空。
8. 不要求每段的state都体现不同的生活切面。允许同一处境持续存在，重点是它在这次经历中实际承担什么作用。

三、事实边界

1. Center是组织整首作品的事情，不自动证明人物前史或他人的内心。
2. 不新增外部事件、第三人、对白、物件、地点或背景来推动发展。
3. 不凭空断定他人的需要、承诺、决定和隐秘心理。
4. 不把人物自己的希望写成对方已经发生的行动。
5. 有根据的事实不必机械降为猜测；依据不足的判断也不能写成确定事实。
6. 不为了让路线显得完整而制造终局决定或解决问题。

四、路线输出

每条路线包含：
- route_id
- situation：一句普通话说清人物正在经历的事情。
- segments：按段落顺序列出全部段落。
  - sec
  - state：1—3条，每条是具体的人物处境、愿望、顾虑、感受或选择，编号为S01.1等。不要写抽象分析标题。
  - delta_type：新变化、后果、实行已有想法、延续、回到旧处但有新增、暂时没在想之一。
  - delta：本段相对以前真正新增的内容，没有就留空。
  - depends_on：真正构成前因的更早state编号，没有就空。
  - still_open：本段仍然实际相关的具体疑问，没有就空。
- established：重要事实、认识、愿望或选择首次成立的位置，按首次成立顺序列出。

五、最终自检

逐条读每条路线：人物真正想要什么是否说得清；每次回到旧问题是否有不同作用；前面已经成立的事情是否被后面当作第一次发生；是否出现没有前因的新愿望或新恐惧；是否只是换词重复同一个问题。

不要为了让路线显得丰富而增加段落转折。也不要为了消除重复而删除真实持续的感受。

只输出JSON，字段名和结构严格如下：
{
  "routes": [
    {
      "route_id": "R01",
      "situation": "...",
      "segments": [
        {
          "sec": "S01",
          "state": ["S01.1：..."],
          "delta_type": "新变化",
          "delta": "...",
          "depends_on": [],
          "still_open": "..."
        }
      ],
      "established": [
        {
          "sec": "S01",
          "fact": "..."
        }
      ]
    }
  ]
}
不写最终文案，不评价候选，不输出JSON以外的文字。
