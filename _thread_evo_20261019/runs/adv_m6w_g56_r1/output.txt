我先给结论：这条流水线现在不是“最后的人话化还不够”，而是**语义在流水线中被反复重新生成**。前面先写出一个完整的人物逻辑，中间把它拆碎、重新因果化、再重新人话化；最后为了覆盖珠子，又在只看局部的情况下往里面补新的心理事实。于是每一层都声称自己只是在“整理/改写”，实际上都在改故事。

这能同时解释你现在看到的四类问题：重复、心理分析腔、前因不足，以及珠子反过来改写线。

我会大改。

# 一、诊断：问题究竟从哪里长出来

先说四个最根本的结构问题。

### 1. 你们只有最前面在优化“整条线”，之后都在局部优化

N05 写完整故事以后，真正影响最终内容最大的 N08、N10c、N10g，已经不是在看完整故事、重新判断整条路了。

尤其 N10c：

> “下面是……一条‘线’里的几段”  
> “请重写这几段，让它们接得上”

这一步只看到有问题的局部，却有权新增人物心理。

它不可能可靠地知道：

- 这个念头前面是不是已经成立过；
- 这个问题是不是已经解决过；
- 它现在新增的“委屈”“羞愧”“疼惜”“决定”前面有没有依据；
- 后面是不是还要再“第一次”发现一次同样的东西。

Op.61 的 S11→S13 是非常典型的状态机错误：

S11 已经有：

> “既然两边都属于他，坚持就不必再排斥柔软。”

到了 S13 又：

> “他忽然看清自己不必在怀念与骄傲间二选一”

不是语言重复，是**同一个状态转换执行了两次**。

你们现在没有任何一层维护：

> 这个认识什么时候第一次成立？成立之后还可不可以再次被当作新认识？

所以后面的局部优化根本不知道它正在“重新发现已经发现过的东西”。

---

### 2. 流水线里有太多“看似保持内容、实际上重新写内容”的转换

现在实际是：

**连续文章 → 分段文章 → 原子化关系图 → 再人话化 → 为珠子重写 → 为语言重写 → 为覆盖找回旧内容 → 逐字修改**

里面真正必要的表示转换很少。

尤其：

#### N06

> “原稿是基准：它的每一步推进都不能丢”

然后又要求：

> “每条是一个短句，只说一件事”  
> “一句说不完，就拆成两条”

先把一件自然的心理事实拆成数个原子。

接着 N08 又说：

> “压缩靠合并意思”  
> “一件事能用一句话说清的，不要拆成好几句”

于是 N06 负责拆，N08 负责再合。

这两层相当于做了一次有损往返转换。

而且 N06 不只转换形式。它还加：

- `kind`
- “提供理由”
- “说明”
- “限制”
- “动摇”
- “失效”
- “仍在起作用”

所以它实际上重新解释了一遍文章。

然后 N08 再把这些结构重新写成人说的话。

这正是为什么最后越来越像“把心理关系图念出来”。

---

### 3. “覆盖珠子”进得太晚，而且是以最危险的方式进入

N10c 是目前我认为破坏力最大的一层。

它看到的是**原始珠子**，而指令是：

> “补的是他经历里的原因、处境或感受的来由”

同时：

> “【已经接得上的珠子】靠的那几条的意思必须保留”

再加：

> “字数最多比现在多两成”

这形成了一个非常典型的“只增不减”压力：

旧意思不能丢 + 新珠子要接住 + 不能整体重构  
→ 最容易的办法就是再塞一个心理事实。

更严重的是，它只禁止了：

> “不要把珠子里的画面、比喻、声音写进线”

但**没有禁止把珠子里的隐含人物情节直接搬进线**。

所以 Op.60 出现：

> “对方轻快回应，他敢逗趣”

几乎就是 S08 珠子：

> “轻快的调情、回应”

的人物化。

又比如最终 S12：

> “觉得人生不只有个人得失”

跟珠子：

> “整个人被卷进一个比自己更大的世界，连‘我’都暂时退到了后面”

已经不是“情境相近”，而是在做意义翻译。

S14：

> “却不再追问；就此笃定”

也很容易理解为什么会长出来：珠子里有“铁锚落下”“站起来”“关门”“终于把话说完”，覆盖修补层很自然会把这种**结束感翻译成心理决断**。

于是它刚好重复了 S07/S12 已经做过的决定。

这不是某次模型发挥不好，而是提示词允许、甚至诱导它这么做。

---

### 4. Center 现在被当成了“生成发动机”，实际上更适合作为“最后的归纳”

这一点尤其值得大改。

N05a 一开始就给：

> “Thread 所围绕的那件事（Center）是：……”

而整个写作又只能发生在人的内心，不能靠外部事件。

那么模型自然会不断拿 Center 两端制造变化。

以当前 Op.60 的 Center：

> “亲密的幸福与留不住它的痛楚难以分开”

为例。

这个 Center 给人物留下的主要状态变量几乎就是：

- 幸福多少；
- 舍不得多少；
- 还要不要继续投入。

于是后半很自然变成：

幸福更深  
→ 更怕留不住  
→ 仍愿意爱  
→ 更幸福  
→ 更怕留不住  
→ 仍愿意爱。

评委说的重复，本质上已经写在状态空间里了。

而你认为不错的旧版 Op.60，真正好的地方不是 Center 文笔好，而是**活动问题不断变化**：

“能不能只顾眼下”  
→ “我是不是对他特别”  
→ “关心和期待回应为什么同时存在”  
→ “想被珍惜是不是等于逼他回应”  
→ “自己真正想要什么”  
→ “想一起过日子，对方呢？”

每一阶段改变的是**问题本身**。

这和“幸福越来越多 / 越来越舍不得”不是一个维度。

所以我会把正式 Center 后置。

这其实也和你们以前定过的“Center 在全曲写完后回头写出”更一致。

## A1：只写“人的经历骨架”，不看珠子，也不给 Center

这里不写散文。

直接写状态变化。

```text
你要为一首器乐作品设计 Thread 的“人的经历骨架”。

Thread 是同一个人在整首作品里经历的一件事。以后会把它写成逐段关系图，但这一层只负责把这件事本身想清楚。

【输入】
作品：{NAME}
段落顺序：{SECTIONS}

这一层：
- 完全不看任何听感记录或“珠子”。
- 不写音乐、声音、旋律、节奏、和声、小节里的事件。
- 不写正式 Center。Center 会在最终 Thread 写完后再归纳。
- 可以利用你对作品整体走向的理解安排各阶段的轻重，但输出里只写人的经历。

请独立提出 {K} 条完整候选路线。

每条路线必须从头到尾只是一件事。可以没有具体外部事件；不要新增聚会、书信、物件、对白、地点、职业等情节来推动变化。

最重要的规则：

1. 前面已经发生过、相信过、期待过、得到过、失望过的东西，才可以成为后面此刻这样想或这样感受的根据。

2. 不要默认采用“试一个办法 → 不管用 → 换一个办法”的发展。一个人可以只是经历、等待、沉浸、意识到后果、把以前的事看得更清楚，或者暂时不想这件事。

3. 一个认识、决定或问题一旦已经明确成立，后面不能再次把同一件事写成第一次成立。
如果后来回到类似的地方，必须明确写出这一次新增了什么；没有新增内容，就标成延续，不要制造第二次转折。

4. 不要求每段都有新认识。有些段落可以只是：
- 已经存在的感受继续存在；
- 某件已经知道的事真正落到自己身上；
- 暂时沉浸在别的感受里；
- 前面的某件事产生后果。
不要为了填满段落制造心理动作。

5. 特别区分“情绪变强”和“人物处境发生了新变化”。
情绪更强本身不算新的认识或决定。

6. 不要让人物不停总结自己。优先写他当时具体在意什么、盼什么、犹豫什么、已经知道什么、还不知道什么。

7. 结尾不必解决问题，也不要为了有终点而制造决心、原则或人生结论。

8. 同一路线中要保存一份“已经成立的事实账本”。后面的段落不得违背它，也不得把其中已经完成的变化重新完成一次。

每条候选输出：

- route_id
- situation：一句普通话，说清这个人正在经历的是哪一件事；不要写抽象论文标题。
- segments：
  - sec
  - state：本段此刻实际是什么情况，1–3 条
  - delta_type：从“新变化 / 后果 / 实行已有想法 / 延续 / 回到旧处但有新增 / 暂时没在想”中选择
  - delta：这一段相对以前真正新增了什么；没有就写空
  - depends_on：真正作为前因的更早 state 编号；没有就空
  - still_open：到这一段仍未解决或仍不知道的东西
- established：按首次成立顺序列出全文的重要事实、认识、愿望或选择，并标明第一次成立在哪一段

不要写最终文案，不要写 Center，不要评价候选。
只输出结构化结果。
```

这里最重要的是 `established`。

它相当于给 Thread 加了一个很简单的状态机。

Op.61 那种 S11 已经完成、S13 又“忽然看清”的错误，在这一层就应该被发现。

## A2：宏观选路，不看珠子

N05c 应该彻底换掉。

不要再问 doing / longing / about 能不能说清。那些最多说明“看懂了”。

真正该选的是**哪条路线有足够丰富的状态变化，又不是迷宫**。

```text
下面是同一首作品的几条 Thread 人物经历候选。你完全看不到珠子，也不要根据音乐细节评判。

你的任务不是挑最戏剧化、解释最完整、主题最鲜明的一篇，而是判断哪条路线最有可能写成一条独立成立、简洁、像真人经历的 Thread。

逐条检查：

1. 是否从头到尾确实是同一件事，而不是若干心理主题串在一起。

2. 每一次真正的变化，是否有前面已经发生的事实作为根据。
特别找：
- 没有来由突然出现的羞愧、委屈、害怕、自尊、价值判断；
- 没有铺垫却突然出现的新欲望；
- 作者直接宣布人物成长，但前面没有经历支持。

3. 是否存在“同一认识成立两次”的情况。
把语义相同或非常接近的认识、决定、结论归在一起，指出第一次已经成立在哪里，后面是否又被当作新变化。

4. 是否把“情绪变得更强”误写成“故事往前走了一步”。

5. 是否频繁出现：
想解决 → 暂时解决 → 又回去 → 再解决
这类没有新增认识的来回摆动。

6. 段落少有事情发生时，是否允许它只是延续或沉浸，而不是硬造转折。

7. 人物是否像一个人在经历事情，而不是作者不断替他分析心理结构、概括人生处境。

8. established 账本是否自洽：后面的段落有没有忘记前面已经知道、已经选择或已经解决的事。

先分别给每条路线：
- coherence：1–10
- forward_motion：1–10
- prerequisite_integrity：1–10
- non_repetition：1–10
- human_plausibility：1–10
- 主要问题

然后选出最多 3 条进入下一步，按优先顺序排列。

不要改写候选，只能选择和诊断。
输出结构化结果。
```

注意这里**不选最能覆盖珠子的路线**。

宏观选路仍然完全不知道珠子。

---

# 四、A3：把珠子变成“体验约束”，但不让它们直接进入写作模型

这是我认为很值得加的一层。

现在最大的问题之一，是最终 Writer 直接看到了珠子的情节化比喻。

我要在两者之间加一层“去词化”。

原始珠子依旧保留，完全不改；只是 Writer 不直接看。

```text
下面是某首器乐作品逐段的听感记录（珠子）。

你的任务不是写 Thread，也不是替珠子编人物故事。
你只负责把每一颗珠子转换成一个供后续匹配使用的“体验性质”。

对每颗珠子分别处理，不合并、不筛掉。

必须去掉：
- 音乐术语和具体声音事件；
- 画面、物件、天气、地点等比喻；
- 珠子为了说明感受而临时想象的人物动作、对白或关系情节；
- 从比喻中推断出的新人物事实。

留下的是：
“如果一个真实的人处在某种经历里，什么性质的处境或感受会与这颗珠子大体接近？”

只描述性质，不替 Thread 决定发生了什么。

特别注意：
- 珠子里的“某人说话、拥抱、回应、调情、离开、回家、回忆某件事”等都不能直接变成人物经历事实。
- 不要因为珠子有明确比喻，就假定 Thread 中真的发生了那个动作。
- 一颗珠子如果同时有几层可以并存的性质，可以保留几层。
- “另一种理解”与其他珠子不必强行统一。
- 不评价哪种体验更重要，不决定故事路线。

每颗珠子输出：
- bead_id
- qualities：1–3 条简短的体验性质
- temporal_shape：如果珠子明显包含本段内部的变化，只描述变化性质；没有则空
- forbidden_imports：这颗珠子中绝不能直接搬进 Thread 的人物事实、动作或情节
- confidence：高 / 中 / 低

最后每段输出：
- compatible_bundle：本段多颗珠子可以同时成立的体验性质
- tensions：本段珠子之间确实存在而不能强行合并的不同听法

只输出结构化结果。
```

这一步解决的是：

**珠子可以影响 Thread 的情境，但不能把自己的故事偷偷带进 Thread。**

例如“调情、回应”只应留下类似“轻快、相互有来有往、暂时没有负担”的体验性质，而 Writer 根本看不到“调情”两个字。

---

# 五、A4：第一次也是唯一一次写最终关系图

这一层直接写成品。

不再经过“文章 → 图 → 人话”。

```text
你要写一首器乐作品最终使用的 Thread。

Thread 是一个人在整首作品里经历的一件事。读者只看 Thread，也必须能从头到尾明白这个人为什么此刻会这样；之后它会和独立写成的听感记录放在一起，所以每段还要能接住若干体验性质。

你看到三类材料：

【段落】
{SECTIONS}

【已经通过宏观评审的人物经历候选】
{ROUTES}

【从珠子去掉音乐、比喻和临时人物情节后得到的体验性质】
{TARGETS}

你看不到原始珠子。不要猜原始珠子的画面或措辞。

第一步，先从候选路线中选择一条作为整篇的 base_route。
只能有一个 base_route。不要把几条互相不兼容的人物前提拼成一篇。
另一条候选里的局部想法，只有在不新增人物前提、也不改变 base_route 已成立事实时才能采用。

然后从头到尾一次写完整条线。

【最重要的规则】

一、线自己先成立

每段此刻为什么这样，只能来自：
- 更早已经发生在他身上的事情；
- 更早已经成立但现在产生后果的认识、愿望或选择；
- 上一状态自然延续到现在。

不能因为某个体验目标需要一种情绪，就临时给他新增一段前史、关系事实、对方行为、回忆、决定或人生观。

某个体验目标如果只有靠编新事实才能覆盖，宁可把它留下不覆盖。

二、人物状态只能真正变化一次

全文维护 established ledger。

某个认识、决定、愿望、问题一旦已经明确成立：
- 后面可以实行它；
- 可以承受它带来的后果；
- 可以发现它还有以前不知道的一面；
- 可以明确改变它；
但不能把同一件事重新写成第一次明白、第一次接受、第一次决定。

如果再次回到类似问题，必须有具体新增内容；否则只写延续。

三、不要把强度当推进

情绪变得更强、快乐更满、痛苦更深，可以是本段的重要体验，但不自动等于人物获得了新认识。

音乐般的高潮不要求人物在同一处得出人生结论。
已有事情在这一刻真正压到他身上，也可以构成充分变化。

四、覆盖珠子的方法

TARGETS 只是“体验性质”，不是待翻译的文本。

Thread 只需要提供一个人的经历，使其中一些性质自然成立。
不要逐项对应，不要写成对 TARGETS 的解释。

严禁因为 TARGETS 而新增：
- 对方做了什么；
- 两人发生了什么新事件；
- 过去曾具体发生什么；
- 新对白；
- 新场景；
- TARGETS 暗示出来、但人物路线原本没有的关系事实。

同一条人的经历可以自然覆盖多颗珠子。

五、每段内容

每段写 2–4 条。
一条是一句完整、自然的人话。
一件事一句能说清，就不要拆成几条。
每条必须有独立作用，不得重说本段或前文已经说完的认识。

不要为了凑 2–4 条把一个念头拆碎；事情少的段落就保持最短的合法长度。

语言像一个人平常讲自己的经历，不像心理分析、论文、总结或提纲。
少用抽象名词替代具体所求和顾虑。
不要写格言、人生原则或作者替人物作总结。

六、引用

某条之所以成立，确实依赖更早某一条具体经历时，在 cite 中写前文条目编号。

不强制每段一定有 cite。
只是主题相近、情绪相近，不算前因。

不要在正文里写“提供理由”“限制”“说明”等关系标签。

七、与整件事的关系

正文全部写完后，再根据这一段实际写出的内容，标：
- 没在想
- 还说不清
- 正在面对

标签必须从正文推出来，不能为了保持预设标签而改正文。

八、结尾

不要为了像结尾而制造最终决心、彻底想通、人生结论。
走到哪里就写到哪里。
如果还不知道，就保留不知道。

【输出】

{
  "base_route": "...",
  "segments": [
    {
      "sec": "S01",
      "relation": "没在想/还说不清/正在面对",
      "items": [
        {
          "id": "S01-1",
          "text": "...",
          "cite": [],
          "covers": ["..."]
        }
      ],
      "delta_type": "...",
      "delta": "..."
    }
  ],
  "uncovered_targets": [
    {
      "bead_id": "...",
      "reason": "为什么若强行覆盖会伤害人物逻辑"
    }
  ],
  "established": [
    {
      "claim": "...",
      "first_established": "Sxx-x"
    }
  ]
}

covers、delta、established 是内部校验信息；最终展示时删除。
```

这一步里有一句我认为非常重要：

> **某个体验目标如果只有靠编新事实才能覆盖，宁可留下不覆盖。**

你们现在的覆盖已经“差不多就够了”，真正危险的是为了把 93% 拉到 97%，把整条线弄坏。

# 六、A5：Center 最后再写，而且绝不反过来改线

```text
下面是一条已经完成的 Thread。

请从这条线本身归纳 Center。

Center 是读者回头看整篇时，这件事共同围绕的关系。
它不是写作提示词，不会再拿去要求每一段响应它。

要求：

1. 是最小完整关系句。
2. 主语是一个或多个名词短语；谓语说明它们怎样相关。
3. 不写“他想、他发现、他决定”等人物动作。
4. 不预告故事的发展路线、解决方式或结局。
5. 不使用“逐渐、反复、终于、越来越”等时间过程词。
6. 除非整条线确实建立了不对称关系，否则不要写成一个东西单方面“受另一个东西牵制、支配、阻碍”。
7. 尽量说清真正重要的东西和使它难以处理的条件，而不是只把两种情绪并列起来。
8. Center 要能包含整条线的重要侧面，但不要求每一段都显式谈到它。

先提出 3 个候选。
然后逐个检查：
- 是否把整篇缩成其中一个阶段；
- 是否只剩一种情绪；
- 是否把故事路线提前写进 Center；
- 是否暗示了线里没有建立的因果或高低关系。

最后选一个。

只输出：
{
  "candidates": [...],
  "selected": "...",
  "why": "...",
  "narrowing_risk": "..."
}
```

这会直接解决目前两种 Center 病：

- Op.60：过分被“幸福 / 留不住”两个情绪吸住；
- Op.61：“反复拉扯”“受……牵制”这种已经在 Center 里预写发展方式和高低关系。

# 七、A6：成品之后做两套完全分开的审计

这是另一个关键。

**单独成立评委绝不能看到珠子。**

**覆盖评委则必须看到原始珠子。**

不要让一个评委同时兼顾两件事，否则它会为了“接音乐”原谅故事问题。

---

## A6a：只读线审计

这基本可以吸收你们现在 N09 做得好的地方。

```text
下面是一条 Thread。你完全看不到音乐和珠子。

把它当成一个人经历的一件事，从头到尾连续读。

先不要逐句修改，先回答：只凭前文已经发生的事，每一段为什么此刻会这样，是否讲得通？

然后检查以下问题，但不要预设一定存在：

1. 前提缺失
某个羞愧、委屈、害怕、愿望、价值判断、决定或人物关系事实，是不是第一次出现时没有来由。

2. 重复完成
某个认识、决定或问题是否早已明确成立，后面却再次被写成新的发现、接受或决定。

3. 假推进
是否只是情绪更强、说法更重，却被当成故事又往前了一步。

4. 来回摆动
是否反复走到同一个地方，回来时又没有新增认识。

5. 状态标签冲突
“没在想 / 还说不清 / 正在面对”是否和正文实际内容不一致。

6. 啰嗦
哪些句子只是在重新说前文已经完整说过的东西。

7. 人话
连续读时，哪些地方像作者在分析人物、总结心理结构、下人生结论，而不像一个人在平常经历事情。

8. 句子本身及累积语言问题
先找真正不通顺的局部；再独立检查某种写法反复出现后是否让全文单调、抽象或像模板。

对每一个问题都要指出：
- 位置
- 原文
- 问题是什么
- 它损害的是 why-now / 前进 / 简洁 / 人话 / 标签中的哪一项
- 严重度

最后分别给：
standalone_coherence 1–10
forward_motion 1–10
efficiency 1–10
human_language 1–10

不要改写全文，只做诊断。
```

## A6b：覆盖 + “是否翻译珠子”审计

```text
下面有：
1. 一条 Thread；
2. 同一作品逐段的原始珠子。

你的任务只检查两件事：

A. 覆盖
对每颗珠子判断：
- covered
- partial
- uncovered

covered 的标准不是 Thread 重述珠子的画面。
只要 Thread 给出的人的处境、原因或当下状态，足以让读者觉得两者属于大体相近的情境，就算覆盖。

指出具体由哪些 Thread 条目接住，以及为什么。

B. 珠子翻译污染
反过来检查 Thread：
有没有某条人物事实，看起来并不是由 Thread 自己前面的经历长出来，而像是把珠子里的：
- 比喻情节
- 人物动作
- 对方反应
- 对话关系
- 结论
直接改写成人的故事。

特别注意：即使没有照抄珠子的字，只要 Thread 新增的事实主要来自珠子本身，也属于污染。

每个可疑位置说明：
- Thread 原文
- 对应珠子
- 为什么像翻译
- 如果去掉这一层具体事实，是否仍能保持大体覆盖

最后输出：
- 总覆盖情况
- 最重要的真实缺口
- translation_risk：1–10
- 哪些“缺口”不值得为了追求覆盖去修，因为修它很可能破坏 Thread 自己的逻辑

不要改写 Thread。
```

这最后一句很重要。

目前的评委只会说“这里没盖住”。

新的评委还要会说：

> 这颗珠子没盖住，但不值得修。

---

# 八、A7：最多只允许一次，而且是“全线修订”，绝不再局部补丁

如果审计确实发现问题，修订模型看到的是**完整线 + 完整历史 + 两份审计**。

它不直接看原始珠子，只看去词化 TARGETS。

```text
下面是一条完整 Thread，以及两份独立审计：

【当前 Thread】
{LINE}

【人物路线骨架】
{BASE_ROUTE}

【珠子的体验性质，不含原始珠子】
{TARGETS}

【只读 Thread 的独立审计】
{STANDALONE_AUDIT}

【覆盖与翻译污染审计】
{COVERAGE_AUDIT}

请对整条 Thread 做一次全局修订。

这不是逐段补丁任务。你必须从头到尾一起考虑，修掉真正的问题，同时保证前后状态账本仍然一致。

优先级：

1. 先修前提缺失、同一认识重复完成、来回摆动、标签错误。
2. 再修真正重要的覆盖缺口。
3. 再修啰嗦和不像人话。
4. 不为了提高某一颗珠子的覆盖，破坏前面三项。

重要规则：

- 可以合并、拆分、重写、调整同一阶段内部的表达。
- 不要求保留旧条目数量。
- 不要求保留旧 cite。
- 不要求保留旧 relation 标签。
- 修完后重新计算所有 cite 和 relation。
- 已经成立的认识不能再次成立。
- 如果删掉一个重复结论，后文确实依赖它时，直接 cite 它第一次成立的位置，不要重新说一遍。
- 不新增人物、外部事件、背景、对白、对方的新行为或新关系事实。
- TARGETS 只能提供体验性质，不能提供人物故事。
- 覆盖审计明确认为“不值得修”的缺口不要补。
- 不为了形成结尾而新增最终决心或人生结论。
- 原来独有而必要的意思不能无故丢失。
- 一段仍为 2–4 条；事情少就写短。
- 语言要像一个人平常讲自己的经历。

输出：
1. 完整修订版；
2. 新 established ledger；
3. change_log：每项修改解决哪个审计问题；
4. unresolved：你主动没有修的覆盖缺口及原因。

不要进行第二轮修订。
```

然后重新跑 A5、A6。

**如果新版本不是明确优于旧版本，就回退。**

这和当前“语言变好就接着跑、覆盖掉了再补回来”完全不同。

# 九、第二套方案：我甚至更想试——不修，直接 Best-of-N

如果额度真的不重要，我会把它作为很强的实验。

因为你们现在已经证明了一件事：

> 局部修改非常容易损坏另一维。

那最直接的办法就是：**不要修改成品。**

流程：

**A1 → A2 → A3 → A4 同一个成品生成提示词并行跑 8–16 次 → 每篇独立审计 → Pareto 筛选 → 盲比**

没有 A7。

也就是说，成品一旦写出来就不再动内容。

语言不好？淘汰这篇。

覆盖差？淘汰这篇。

重复？淘汰这篇。

不再尝试把一个 7 分稿修成 9 分，而是直接从 12 个完整稿里找那个本来就在四个维度上比较均衡的。

我认为它很值得试，因为四个维度之间不是简单的线性优化问题。局部梯度很容易往错方向走。

筛选提示词可以这样：

```text
下面是同一首作品独立生成的若干完整 Thread 候选，以及每篇分别得到的：

- 只读线审计
- 珠子覆盖审计
- 翻译污染审计
- 语言审计

不要修改任何候选。

先做 Pareto 筛选。

如果候选 X 在：
- standalone
- coverage
- efficiency
- human_language
四项中没有任何一项优于候选 Y，并且至少一项明显更差，则 X 被 Y 支配，淘汰 X。

“翻译珠子风险高”作为额外淘汰条件，不用高覆盖抵消。

对剩余候选再做全文比较：

1. 哪一篇只读时最像一件真的从前往后发生的事；
2. 哪一篇重复完成的认识最少；
3. 哪一篇覆盖缺口最少、但不是靠翻译珠子取得覆盖；
4. 哪一篇每句话承担的信息最多而不显得压缩；
5. 哪一篇最像平常人在经历事情，而不是作者解释人物。

如果两篇各有优劣，不要拼接，也不要改写。
直接保留两篇进入下一轮盲比。

输出排名、淘汰原因和进入盲比的候选 id。
```

如果让我押哪套更可能一步大幅提升，我会先跑 **Best-of-N 无修订版**。

因为你们目前最严重的退步几乎都发生在“修”的过程中。

# 十、还有几个我认为你们值得试、但目前流水线里没有真正做过的东西

### 1. “认识首次成立账本”

这是我最推荐加的内部数据结构。

不是关系标签，而是一张：

> proposition → first established at

例如模型内部会知道某个事实已经在 S07 成立。

S12 可以：

- 实行它；
- 因它受影响；
- 更具体地看见代价；
- 改变它；

但不能再次“决定”它。

它对解决 Op.60 和 Op.61 的后半重复非常直接。

---

### 2. 专门检查“假推进”

你现在的评委已经会指出重复，但可以把它做成一个非常便宜的 lint：

把每段 `delta` 抽出来，不看文风，问：

> 如果删掉程度副词和情绪强度，这一段相对前面到底新增了什么？

如果回答是：

> 没什么，只是更强。

那它不是一定错，但不要把它包装成“新领悟”。

这对音乐高潮尤其重要。

**音乐变得更强 ≠ 人必须获得更大的哲学认识。**

人在高潮里完全可以只是第一次真正承受一个早已知道的事实。

这反而往往更像人。

---

### 3. “珠子污染反推测试”

这是个很有用的 adversarial test。

给评委看成品线和珠子，然后问：

> 对每条 Thread，猜它最可能是由哪一颗珠子的哪个具体比喻改写来的。

如果评委很容易高置信度回答：

> S12-1 明显来自 B1 的“我退到后面”；  
> S14-3 明显来自最后落锚/说完；

这就是危险信号。

好的覆盖应该是：

> 我能说明为什么它们情境接近，

但不应该是：

> 我能反推出 Writer 当时在翻译哪一句珠子。

---

### 4. 做“删除珠子”反事实测试

对一颗可疑珠子：

- 去掉它；
- 保留其他输入；
- 再生成若干次。

如果某个人物事实只有在这颗珠子存在时才不断冒出来，而且它本身又没有前文根据，那么这个事实大概率是珠子污染，而不是 Thread 自己的内容。

这个方法特别适合查：

- 对方回应；
- 调情；
- 某种具体回忆；
- 最终决心；
- 突然出现的人生观。

---

### 5. 评估“当前问题有没有变化”，而不只是情绪有没有变化

你那版不错的旧 Op.60，有一个非常明显的优势：

每一阶段人物“现在到底卡在哪儿”都在变化。

我会给自动评审增加一个完全不同的输出：

> 每段如果有一个仍悬着的问题，用一句普通话写出来。

然后把所有段排在一起。

如果得到：

- 会不会失去？
- 会不会失去？

### 6. 不让“写作模型”同时做结构和文风优化

目前 N08 想同时：

- 保 Center；
- 保历史；
- 保关系；
- 压缩；
- 改人话；
- 制造方向感；
- 去重复；
- 保引用。

任务太混。

新方案里，宏观模型只负责人的状态。

最终 Writer 只负责：

> 在一个已经自洽的状态序列上，一次写成人话并适配体验目标。

这更稳定。

# 十一、为什么这套方案能同时守住“覆盖”和“单独成立”

关键不是给两边各加一个评分。

而是让它们在生成时承担不同角色。

**人的经历骨架拥有事实主权。**

它决定：

- 这个人经历过什么；
- 现在知道什么；
- 还不知道什么；
- 什么可以成为后面的前因。

珠子没有权力新增这些事实。

**珠子只拥有情境约束权。**

它可以说：

> 这一段如果有悬而未决、释放、沉浸、热切、突然变重等等性质，会更容易接。

Writer 的任务是在已有人的经历里找一个合法状态承载它。

这就和现在 N10c 完全反过来了。

现在是：

> 这颗珠子没接上 → 给人物加东西。

新方案是：

> 这个人物现在合法能经历什么 → 在合法范围里选最能接珠子的表达。

这才真正把“线是骨架、珠子是当下体验”落实到了 DAG 上。

# 十二、我最担心的新风险，以及怎么提前发现

| 风险 | 为什么会发生 | 提前检测 |
|---|---|---|
| 覆盖下降 | 去词化珠子是有损压缩 | A3 后单独让评委检查每颗原珠子是否被 target 忠实保留；这是 target fidelity，不评 Thread |
| 线太理性、太干净 | state ledger 容易让模型像工程师 | 最终 Writer 不展示 ledger 语言；A6a 单独做人话审计 |
| 太强调“不能重复”，导致该有的回响被删掉 | 重返旧问题本来可以有意义 | 审计区分“同一结论重新成立”和“旧事实产生新后果” |
| 高潮没有人物变化 | 不再强迫高潮产生洞见后，可能写得太平 | coverage evaluator 检查体验强度；允许“承受/实行已有东西”成为高潮，而非强制新认识 |
| 没有预先 Center 导致散 | 候选路线可能各段漂移 | A1 的 situation + established ledger + A2 coherence；正式 Center 后置，但“同一件事”不后置 |
| target 仍然偷偷带故事 | A3 可能把比喻转成隐含情节 | `forbidden_imports` + 最终 translation audit |
| 一次全局修订改坏好地方 | Writer 仍可能过度修 | 修前/修后盲比；新稿不明确赢就回退 |
| Best-of-N 过拟合自动评委 | 同类模型会共享偏好 | 用你已经定好的最终三类验收：逐珠覆盖、只读线、同底稿新旧盲比；自动分只是筛选，不是验收 |

这里我最想强调一个风险：

**不要把“禁止重复”做成机械去重。**

S03 的担心，在 S13 重新出现完全可以成立。

真正该禁止的是：

> S03 已经知道 X；S13 又写“他终于知道 X”。

而不是：

> S03 知道 X；S13 第一次真正承受 X 的后果。

这两者差很多。

# 十三、如果只允许我先改三件事

我会按这个顺序做：

1. **立刻删掉 N10c / N10g 这种“给局部原始珠子后重写人物”的流程。**这是当前珠子污染、前提新增和状态标签失真的最大来源。

3. **正式 Center 后置，并增加 established ledger。**这两件事组合起来，最可能直接解决两首现在共同出现的“后半段反复抵达同一结论”。

你给的材料让我觉得，目前离好的成品其实并不远；但继续沿着现有 DAG 修提示词，很可能收益越来越小。现在更像是应该把**五六次语义重写缩成两次：一次想清人的经历，一次写最终成品**。其余模型都做诊断和选择，不再碰正文。
