# Prompt 开发硬规则

以下来自项目既有开发准则与用户反复确认，违反即返工。

1. **只从当前 v0 / 冻结提示词派生。** 不凭讨论直接整篇重写 production prompt。
2. **每轮只改一个变量。** 一句 prompt、一个模型、一个 N、一个结构变量，不能混改。
3. **逐句归因。** 每个行为变化要回到具体 prompt 句子或模型差异。
4. **新增句必须能从宪法/V2A推导。** 写入 `DERIVATION.md`。
5. **不加作品专属 prompt 规则。** 不写人名、具体小节、某曲剧情/例子来教模型。
6. **例子/反例尽量不用。** 若用于 tooling/eval，要与 production prompt 分离。
7. **泛化必须三首都测。** 只对一首有效不算采用。
8. **前一层未冻结，不随手调后一层。** 当前尤其：timeline 未冻结，不宣布新的 Thread/WHY 为 production。
9. **提示词全文直接发子 agent。** 不让它自行去文件里“找某段 prompt”。
10. **有结论就停。** 不为了形式完整重复无信息实验。
11. **戏剧化、笃定、具体剧情不是默认缺点。** 评审不能沿用旧偏见。
12. **中间层不得把语言洗成心理标签。** 但 Humanizer 可重新组织、删减。
13. **不要把本交接包中的候选结构一次全写进 prompt。** 每个候选能力都要先作为 probe/condition 验证。
