# 给 Claude 主 Agent：只根据现有文献划分结构、从 A 生成珠子（替换版）

你在 `D:\musicclaude` 项目工作。本任务仅产出一个**能复用到其他曲目的“已有结构分析 → A-only Pool → Bead”方法**及其在当前作品上的实际示例。**禁止恢复旧 ZIP 的谱面、录音、模型竞赛路径。**

## 一、明确纠错

上一版 `01_独立外部结构分析.txt` 曾要求“有条件时直接核对谱面”，甚至安排独立乐谱/聆听复核，再让模型凭“完整自然换气”自行把文献段落合并成 5 段。这不是本轮任务。旧版结构结果可以作历史对照，但 **5 段不是已获用户批准的优选方案**。用户此前认为 run102 的九段尺度不错。本轮先**忠实取用已有研究者的段落**，不要替他们重新分析作品。

## 二、模型调用规则

Claude 负责文件查找、调用调度和结果整理，不得私自改变实验目标。所有**新增的模型调用**统一使用指定 GPT-6w（核实当前路由的实际 model ID 和 metadata；未找到或不可用就停下报告）。不要做 Luna / Terra / Sol / Opus 写手比赛，不安排 GPT 盲审/打分；质量由用户看实际珠子。已保存的 A 原文来自多模型，可全部复用，它们不是新增调用。

## 三、执行步骤

**STEP 1｜只读已有音乐结构文献。** 使用 `prompts/01_现成结构文献逐条提取.txt`。在线查找真实存在、能提供小节/时间范围的公开曲式分析、音乐学论文或权威曲目条目，引用实际结构表、段落起止、文献原有的层级。不要读谱、不要放录音、不要根据声音事件自己判断新边界。找不到可靠具体分段时如实中止，不允许凭记忆编造。

**STEP 2｜来源之间按层级并列。** 使用 `prompts/02_来源对齐与采用层级.txt`。尊重文献区分的一级乐段、次级主题/乐句等层级。它们若有五段、九段、十四段，优先说明是不是**层级不同**，而不是声称五段更自然；不允许凭“我觉得这里还没换气”把文献中清楚的起点消掉。用户喜欢历史九段的尺度，但不把九段写入通用生成提示词；只在文献整理完成后与历史九段做对照，提交清晰可审阅的建议。**未能确认采用哪一组边界前，不推进到下一步。** 用户已经指定边界或允许选择时，可按明示的来源层级执行；存疑则提交选择，不擅自定。

**STEP 3｜固定选定边界，按段映射 A 原文。** 使用 `prompts/03_A原文归段.txt`。直接复用已有 A-int/A-web 原文与可核实单元；保留模型来源和小节范围。跨段文字完整保留、多个 Pool 引用。任何无法定位、错误小节或后见之明单独标记；先完成并应用复核后的 Pool，再开始生成，不准“先写完后复核”。T 和 H1–H5 不参与。

**STEP 4｜仅用 A 生成 Bead。** 使用 `prompts/04_固定乐段Aonly珠子.txt`。固定分段，一段一颗主珠子，可含多种侧面和段内变化，不能再自由细切。GPT-6w 使用同一份冻结 A Pool，生成一份可供用户阅读的正文以及一份详细来源账本。不需要两种模型对照，不做盲评、不以字数或内容条目数量作为优胜标准。

**STEP 5｜用户审阅后 STOP。** 交付原始文献结构对照表、采用边界、A Pool 映射与错配处理、真实珠子全文、各段遗漏和风险。用户亲自决定是否认可。绝不向下游 Thread、E7 或渲染推进。不要擅自修改任何生产默认配置或覆盖历史 run。
