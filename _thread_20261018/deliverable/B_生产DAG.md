# B. 面向新作品的 Thread 生产 DAG（到 Thread / Inner / Outer 为止）

> 这里只写明天输入一首新作品时要重复执行的步骤。本轮为找方法而做的入口对照、去偏置消融、T 饱和检验、三模型评审组、基线对照，都**不在**这里。

## 1. 依次做什么

```
输入：冻结分段 ＋ 定稿 Bead / STRUCT ＋ 独立 T 研究（多模型 × int/web × 3）
                                                    （A 原稿不需要直接输入）
① 寻找   T 入口 3 路 ＋ Bead 入口 3 路（GPT-6，同一份寻找提示词）        并行
② 比较   2 个独立会话，各自读全部寻找结果（匿名、不同随机顺序）            并行
         → 取两边都选、或一边主选另一边列为重要发现的线（通常 2–3 条）
③ Inner  每条线：GPT-6 与 GPT-5.6 各写一份                                并行
④ 合并   每条线 1 位评审（GPT-6）指出两份各自更好的地方
         → 全新会话合并成定稿 Inner
⑤ Outer  每条线：GPT-6 8 路 ＋ GPT-5.6 4 路 ＋ Gemini Flash 4 路，按定稿 Inner 生成   并行
⑥ 精选   每条线 1 次（GPT-6），匿名混合候选池，只选最好的，不追求覆盖
⑦ 审查   每条线 GPT-6、GPT-5.6 两位 clean 审查                            并行
⑧ 修订   修订 Inner；再按修订后的 Inner 重选 Outer（只能从原候选池换）
⑨ 组装   代码按音乐时间拼接（Thread 说明 → 各时刻 Inner，少数时刻附 Outer → 曲终回看 → 保持独立的段落）
```

脚本负责：模型身份与 max / Temporary / Unpersonalized 校验、提交判定（按提示词找回 gpt3 证据目录；已提交或无法确认时一律不自动重发）、缓存与恢复、组装。

## 2. 每一步的职责与依据

| 步骤 | 做什么 | 为什么保留／这样做 |
|---|---|---|
| ① 寻找 | 找"一件持续发生、不断积累、让后面的音乐获得不同意义的人类事情或关系"，可多条；时刻判断守前缀；列出不应被吞掉的体验和最容易滑进的套路 | 两个入口各自给出对方给不了的线（本轮"承托"来自 Bead 入口，"各有其声"来自 T 入口）。TB 入口没有独有贡献，删去。每入口 3 路：本轮各入口 5 路高度收敛，加 6 份 T 研究也没有新线；按 9/22 的子集饱和测量，约 6 路就饱和 |
| ② 比较 | 判断哪些是真正不同的线、各自最强的时刻、是否落入套路；写出每条线的最好版本（取最具体的，不取公约数） | 两个独立会话主选基本一致，又各自有对方没选的线，单一会话会漏 |
| ③ Inner | 只在线真正发生的时刻写；每个时刻：听到什么、此前什么仍然活着、此刻是什么；独立段落列入 `not_touched`；另写曲终回看 | GPT‑6 鲜活、GPT‑5.6 结构和时间纪律更好，三线胜负互有；Gemini 的 Inner 9 次中 8 次垫底，不用 |
| ④ 合并 | 以一份为底稿，吸收另一份更好的句子与结构；全新会话 | 评审组一致建议互相吸收。生产中用 1 位评审代替 3 位：本轮三位评审对"该吸收什么"的意见高度一致 |
| ⑤ Outer | 一个携带此前历史的具体人类瞬间：动态、情绪质地对、历史藏在当下、说人话、停在情形本身；不配插图、不照搬表面题材、不连成同一故事；不给正例 | 三个模型都有候选入选（入选率 GPT‑6 3.0%，GPT‑5.6 2.4%，Gemini 1.6%）。宽度的价值在于命中少数好的长尾 |
| ⑥ 精选 | 先看单条生命力与情绪质地，再看整组是否同一姿态、同一感官通道、能否连成同一人物 | 9/22 的教训：精选是瓶颈；不能为覆盖各个时刻而选次一等的候选 |
| ⑦ 审查 | 时间纪律、是否改写 Bead、音乐依据、抽象化、套路、Outer 质量、真正新增的理解 | 两位审查发现的问题有重叠也有互补 |
| ⑧ 修订 | 审查的"缺席"意见只当线索；线只在它真正发生的地方说话 | 本轮最主要的失效模式就是线被稀释成逐段 Bead 复述 |
| ⑨ 组装 | 代码拼接模型原文 | 9/22 的教训：再用一个模型"总结"会压掉中间层的历史关系 |

## 3. 和以往 Thread 链路相比：保留、合并、删除

| 旧环节 | 处理 |
|---|---|
| 先找 Center，再找 stage | **删除**。核心关系句由寻找与比较顺带给出，并且要求谓语来自材料、不默认冲突。 |
| History 账本（thread_delta、active_history_delta 等字段） | **删除为字段，保留为提问方式**：每个时刻写"此前什么仍然活着"。 |
| 8–12 路 Finder | **减为 6 路**（两入口各 3）。 |
| 单模型生成 Inner / Outer | **改为多模型**：Inner 两个 GPT 模型合并；Outer 三模型混合。 |
| Consolidator + Renderer 重写 | **删除 Renderer**，由代码组装。 |
| 提示词里的正例、禁用题材、类别清单 | **删除**。只保留一句去偏置：不要把不同体验收进同一套情绪走向。消融显示删掉它会让"舍不得美好"的吸引子变成候选。 |
| 单次审查后直接定稿 | **改为两位独立审查**（GPT‑6、GPT‑5.6）再修订。 |

## 4. 成本与吞吐（按本轮实测）

- 以 3 条线计：寻找 6 + 比较 2 + Inner 6 + 评审 3 + 合并 3 + Outer 48 + 精选 3 + 审查 6 + 修订 6 ≈ 83 次调用。
- 单次耗时：寻找约 7–9 分钟；比较 12–14 分钟；Inner 4–7 分钟；Outer 8–15 分钟；精选 3–9 分钟；审查 6–10 分钟。Gemini 单次 1.5–2.5 分钟。
- 按依赖关系约 7 个波次，16 路左右并发下墙钟约 1.5–2 小时。
