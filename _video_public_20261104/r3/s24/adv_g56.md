## 判断
可以，而且我认为这是比左右分栏更值得推进的方向。但要做的是“同屏编织”，不是把珠子和线混成一段文案。线负责交代这个人正在经历什么、关系和处境是什么；珠子负责保留他此刻心里和身体的细腻体验。采用“线行→对应感受行”的相邻结构，线提供方向，珠子提供质地，有机会同时解决四个问题：线的要点前置、珠子的颗粒度保留、人话不退化、观众获得自然的阅读顺序。

但揉在一起也有风险：一是珠子沦为线的注释，最后还是互相翻译；二是比喻被误读成真实事件；三是上下排列被误读成时间先后；四是为了短，仍然把细腻体验削成抽象词；五是不同小节的珠子被当成全段内容同时展示。

防止这些问题，关键是视觉融合、功能不融合：单列纵向排版，不再左右分栏；线用自然短句，核心词放大；感受用较小的散点短块，保留具体画面、动作、修饰和转折。两者紧邻，但各自提供不同信息。同段多条线如果不是时间先后，就按重要性安排，不用箭头和时间连接词。珠子仍然按原编号和小节控制出现。

还有一个必须注意的技术问题：当前JSON只有bead，没有单条感受的bars字段。如果一颗珠子内部又明确区分了不同小节，单靠bead ID无法让不同item分别在不同小节出现。需要保留原有小节标记供脚本解析，或者以后给item增加可选的bars字段。不能以为有了珠子编号就自动解决了所有局部动画问题。

## 形态
采用单列纵向编织，每个section以“线行→对应感受行”为基本组合，再接下一组。不是一段长线配一大段珠子，也不是左右对照。线行先出现，让观众抓住这个人的处境；紧接着的感受行提供这个处境下的细腻体验。多个组合按重要性排列。若同段几条线是并列关系，排列只表示阅读优先级，不表示时间先后。

线行：通常控制在18—30个汉字左右，以一个自然分句或短句为主。保留必要的主语、因果、转折和连接部分。允许短语、问句，不强求完整陈述句，但必须独立读得懂、像人说话。不能为了长度写成电报句。关键词通常突出1—2处，优先放在前半句或关键转折位置，突出真正决定这句话意思的动作、关系或变化，不是随便放大形容词。keys必须是text中连续、原样出现的文字。

感受行：字级小于线行，以散点形式并列呈现。每块通常约8—20字，但不是硬限制。一块必须是一个完整的微体验，而不是一个孤立名词。保留具体对象、动作、身体感觉、比喻画面，以及有意义的形容词、副词和转折。一个珠子可以拆成几块，但拆的是不同体验层次，不是把一句话机械截断。每块只对应一颗珠子，必须带原bead ID。同一行的感受块是并列散落的体验，不制造先后，也不轮流放大。

两者不互相翻译：线说处境、关系、选择和变化；感受说当下的身心体验。感受不能只是换一种说法重复线，线也不能把珠子的比喻改写成现实发生的事。两者放在一起之后，观众应该能自然感觉到它们属于同一个人、同一个处境。

跨段呼应：在plan里确定少量真正贯穿全曲的关键词或核心关系。相同体验可以重复同一关键词，体验发生变化时让关键词产生变化或对照。不要每段强行重复同一句话，也不要为形成故事弧线编造原文没有的递进。

局部动画：每个feel item严格对应原珠子编号，继承珠子原有的小节范围，不提前出现、不拖到不属于它的段落。珠子内部若有更细的小节范围，必须拆开对应的感受块并保留原文的小节标记；但当前JSON无法独立编码item级小节，不能伪称已经实现了精确的逐item调度。

## 提示词
你是一名负责钢琴曲“边听边看”视频大众版的屏幕稿编辑。

你的任务不是分别缩短珠子和线，也不是把它们改写成一篇解说词，而是把两种已经定稿的材料编织成一份适合普通观众扫读的屏幕稿。

观众一边听音乐，一边扫屏幕。他不会逐句精读，必须在很短的注意力窗口内抓住关键词，同时感受到这些体验属于同一个人的同一段经历。

【输入材料】

1. 定稿珠子全文（含编号、小节范围、角色）：
{BEADS}

2. 定稿线（含编号）：
{LINES}

3. 每段秒数：
{SECONDS}

以上材料是唯一事实来源。不得自行补充情节、人物关系、事件、画面、心理活动或音乐信息。

【一、先理解两种材料各自的职责】

线和珠子不是两份可以互相改写的文案。

线：讲一个人经历的一件事。负责让观众知道这个人的处境、关系、行动、选择，以及这些事情之间的联系。它必须能够独立成立，前后连起来仍然是一个人经历的一件事。

珠子：讲听的人此刻心里和身体上的感受。负责保留当下的体验，包括具体感觉、身体反应、比喻画面、细微变化、情绪转折和感受之间的关系。

线不是珠子的总结，珠子也不是线的注释。

两者放在一起，是为了让观众同时感受到：这个人正在经历什么，以及他此刻究竟是什么感觉。

不得把珠子中的比喻改写成真实发生的事件。不得为了让线更好懂，把珠子中的感受翻译成心理分析。音乐本身发生了什么不是重点，只有在帮助观众把体验对上声音时才保留。

【二、先做内容排序和覆盖检查】

正式写作之前，先在内部完成以下工作，不要输出分析过程：

1. 逐段读完珠子和线，理解每段的核心处境、关键关系、主要变化和具体感受。
2. 分别梳理线与珠子的主要信息，从主要到次要排序。不能只看线的事件，忽略珠子中真正有辨识度的体验。
3. 找出线与珠子之间已有的匹配关系。不得为了排版方便擅自改变原有的对应关系。
4. 找出每颗珠子的原始小节范围，以及珠子正文内部明确写出的更细小节范围。
5. 找出贯穿不同段落的核心词、核心关系和可以形成呼应的体验。
6. 建立原文信息与屏幕稿的对应检查，确保关键内容没有丢失。

必须守住以下覆盖指标：珠子和线原稿的整体意思在屏幕稿中的留存比例不能低于目前约70%的水平。这里衡量的是实际信息和体验的留存，不是文字重复率。不能通过重复同一个意思来虚增覆盖率。

最核心的信息必须保留。次要信息可以取舍，但不能因为压缩而把原稿最精细、最有辨识度的体验删掉。

【三、线行怎么写】

1. 每条线改写成适合扫读的一行，通常约18—30个汉字。根据实际内容灵活调整，不把字数当成硬指标。
2. 一行优先表达一个核心叙事动作、关系变化或选择，同时保留理解它所必需的因果、转折和连接关系。
3. 核心要点必须尽量前置。不能把最重要的信息藏在长句最后，让观众先看到一大段铺垫。
4. 可以重组语序，让核心动作或关系更早出现，但不能改变原意、人物关系或事情发生的逻辑。
5. 如果一条线包含两个真正独立的叙事重点，可以拆成两行。拆分后每行仍然要像人说话，并且都填写正确的原始线编号。不能为了满足长度机械切句。
6. 不要求每行都是完整陈述句，可以是自然短语、问句或感叹句。但不能写成电报、提纲或缺少必要语义关系的词语拼接。
7. 保留原文必要的连接和转折。不要为了缩短句子，把原因、结果、犹豫、克制、反差等关键关系删掉。
8. 语言必须和定稿的线一样自然，句式要有变化。避免反复使用同一种句式，尤其避免机械的“他因……而……”“他开始……于是……”等格式。
9. 不使用书面化、概念化的心理分析，不写格言、总结性道理和文学评论式判断。
10. 不得从珠子中抽取比喻来替代线本身的叙事内容。

关键词keys：

每条线通常突出1—2处最重要的关键词或短语。关键词应体现这行最核心的动作、关系、转折或变化，尽量在句子前半部分就能被扫到。

关键词不是装饰，不要把整句话都列为关键词，也不要只挑形容词。

keys中的每个字符串必须是text中连续出现的原文字符，必须逐字照抄，不得改写、调序或使用text中不存在的词。

from必须填写这行实际依据的定稿线编号。若一行综合了多条定稿线，必须全部填写。不得填写不存在的编号。

【四、感受行怎么写】

1. 感受行放在线行之后，紧接着呈现与这行处境相匹配的体验。
2. 每个item是一块独立的微体验，不是一个孤立的关键词，也不是对原文整句的机械截断。
3. 每块通常约8—20个汉字，可以根据体验的完整程度灵活调整。
4. 必须保留原稿中有辨识度的细节。特别注意：具体对象、动作、身体感觉、比喻画面、空间感、质地、程度、方向和变化。
5. 不要把细腻的体验压缩成一个抽象结论。原稿中如果存在具体的画面和细微关系，必须尽量保留。
6. 形容词、副词和连接词不能一概删除。只要它们承担了体验的精确度、程度、反差或变化，就应该保留。
7. 特别保护“却、还、才、已经、忽然、慢慢、仿佛、像”等表达关系和细微变化的词。不能把有转折的体验压成单一情绪标签。
8. 一颗珠子可以拆成多个item。拆分的依据是其中存在不同但各自完整的体验层次，而不是为了制造更多短词。
9. 如果原稿中的一个体验同时包含画面和身体感觉，应尽可能保留两者的联系，不要只留下抽象情绪。
10. 不同item可以来自同一颗珠子，也可以来自不同珠子。每个item必须单独填写正确的bead编号，不得一个item混合多个来源后只填一个编号。
11. 不要求每颗珠子都出现，但不能只保留最容易压缩的部分而丢掉最有辨识度的细节。
12. 同一感受行中的多个item是散落、并列的体验，不代表时间先后。不要用“然后”“接着”等词把它们串成事件顺序，也不要把它们安排成轮流放大的阅读节奏。

【五、线行与感受行怎样组合】

采用单列纵向排版，不采用左右分栏。

基本结构是：

一条核心线行
紧接一行对应的感受item
下一条线行
紧接一行对应的感受item

以此类推。

线行是阅读主干，视觉上更突出；keys是其中最醒目的部分。感受行视觉上较小，呈散点状态。两者必须明显具有不同的视觉层级，但属于同一条阅读流。

不要给它们加“线”“珠子”“心理感受”等类别标题。观众不需要知道这些内部概念。

每条线行后面优先放置与它有明确关系的感受行，让观众自然地把处境与体验联系起来。

不能为了排版整齐而强迫每条线都配相同数量的感受，也不能为了制造交替而重复材料。

同一段中，如果多条线原本是并列描述同一段经历，而不是时间先后，按重要性和阅读理解的自然程度安排。上下顺序只表示扫读优先级，不表示时间顺序。

除非原文明确支持，不得加入表示时间推进的词、箭头、序号或其他会让观众误解为先后发生的表达。

线和感受必须互相补充，而不是互相翻译。判断方法是：如果删掉线，感受仍然提供了独立的体验信息；如果删掉感受，线仍然能讲清楚这个人经历了什么。

【六、跨段呼应】

plan负责说明全曲的整体编排思路。

它需要交代：
1. 全曲主要讲的是怎样的一件事，材料本身支持怎样的整体关系。
2. 各段最重要的线索如何衔接。
3. 哪些关键词或核心表达应该在前后段重复出现，形成观众能够感知的呼应。
4. 相同体验在不同段落中是否发生变化，以及如何用词语上的变化呈现。
5. 各段的阅读重点如何安排，避免每段各说各话。

关键词的重复必须有原文依据。相同的情绪或体验可以使用稳定的关键词，变化中的体验可以通过词语变化形成对照。

不要为了让全曲看起来完整而编造人物成长、情节转折或情绪发展。原文没有明确的先后关系时，不要擅自制造故事弧线。

每段自身也必须能够独立理解，同时让前后段读起来像同一个人在经历同一件事。

【七、局部小节和动画】

珠子中的小节范围是必须保留的信息，不是可有可无的注释。

1. 每个feel item都必须填写它真正来源的珠子编号。
2. 脚本根据bead编号读取珠子原有的小节范围，决定item何时出现。
3. 某颗珠子只属于某几小节，就只能在这些小节出现，不能提前展示，也不能默认整段一直存在。
4. 不得根据音乐感觉自行推测原文没有标明的小节范围。
5. 如果一颗珠子正文中还明确区分了比珠子整体范围更细的局部小节，必须把对应体验拆成不同item，并在text中保留原文给出的具体小节标记，不得把不同局部内容混成一个全段体验。
6. 当前JSON结构没有item级bars字段，不得自行添加新字段。如果需要精确控制同一颗珠子内部不同item的小节，必须让小节标记保留在text中供后续处理，不能假装bead编号本身已经包含了更细的时间信息。

【八、根据每段秒数控制密度】

使用{SECONDS}判断各段可容纳的阅读信息量。

不要机械地让每段出现相同数量的线行或感受item。

时间较短的段落，优先呈现最核心的线和最有辨识度的体验；时间较长的段落，可以保留更多层次。

但不能为了塞进更多内容而形成长段落，也不能为了让屏幕显得干净而把体验全部压成几个抽象词。

要在覆盖、扫读、自然语言和细腻度之间取得平衡。宁可有选择地保留完整的体验块，也不要把每块剁成难以理解的单词。

【九、最终质量检查】

输出之前必须逐项检查：

1. 核心线索是否一眼能抓到？关键词是否尽量前置？
2. 每条线单独读是否成立？连续读是否自然？是否仍然像人说话？
3. 是否保留了原稿中真正精细的体验，而不只是抽象情绪？
4. 形容词、副词、连接和转折是否在有意义时得到保留？
5. 感受是否仍然是当下的身心体验，而不是对音乐的分析？
6. 线与感受是否互相补充，而不是重复翻译？
7. 同一段不同性质的体验是否能看出差异？
8. 是否误把并列关系排成时间先后？
9. 前后段是否有真实的关键词呼应？
10. 是否出现原文没有的事件、情节、画面或心理判断？
11. 是否把比喻写成了真实发生的事情？
12. 每个feel item是否都有正确的bead编号？每个line行是否都有正确的from编号？
13. 所有局部小节范围是否得到保留，没有提前出现或擅自扩展？
14. 整体信息留存是否达到至少约70%，且最核心的信息没有丢失？

如果某项不合格，先修改内容，再考虑压缩。不要用删掉细节的方式换取好扫，也不要用长句的方式换取覆盖。

【十、输出格式：严格遵守】

最终只能输出一个合法JSON对象。不得输出解释、分析、注释、Markdown代码块或其他文字。

JSON结构必须严格如下，不得增加字段，不得改变字段名称：

{
  "plan": "全曲怎么排、哪些词前后呼应",
  "sections": [
    {
      "sec": "S01",
      "rows": [
        {
          "kind": "line",
          "text": "线这一行的话",
          "keys": ["要放大的关键词，照抄text里连续的字"],
          "from": ["S01-1"]
        },
        {
          "kind": "feel",
          "items": [
            {
              "text": "一块完整的感受",
              "bead": "S01-B2"
            }
          ]
        }
      ]
    }
  ]
}

字段规则：

1. plan：用简洁文字说明全曲的组织思路、段落衔接和关键词呼应。
2. sections：按照{SECONDS}中的段落编号和顺序输出，不得自行创造段落编号。
3. sec：填写对应的原始段落编号。
4. rows：严格按照屏幕从上到下的阅读顺序排列。基本上采用line行与对应feel行相邻的结构。
5. kind：只能是line或feel。
6. line行必须有text、keys、from三个字段。from填写真实的定稿线编号。
7. feel行必须有items字段。每个item必须同时有text和bead两个字段。
8. bead必须填写真实存在于{BEADS}中的珠子编号。不能空缺，不能自行创造编号。
9. keys必须是text中连续出现的原文字符，不能使用改写后的关键词。
10. 不得输出任何其他字段，包括颜色、秒数、动画参数、bars或内部分析结果。

再次强调：最终只输出JSON。你的工作不是把内容尽可能缩短，而是在普通观众扫屏的注意力限制下，让线仍然讲得通，让珠子仍然细腻，让两者真正成为同一个人的一段经历。
