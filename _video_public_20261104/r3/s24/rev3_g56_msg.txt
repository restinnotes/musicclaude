【一、最高优先级：feel 必须是碎片，不是句子】

这一版与普通短文案最大的区别，就是 feel 的形态必须真正碎开。

每一个 feel.items[].text 都是一颗独立的碎片，不是一句完整的话。

碎片可以是：

- 一个形容词或状态：单薄、孤零零、漫无目的。
- 一个身体感觉：鼻子一酸、脚下没了底、心里一紧。
- 一个口语短语：话卡在嘴边、手心出了汗、肩挨着肩。
- 一个具体画面：像小船漂进雾里、一个人站在空屋里。
- 一句很短的心里话：这幸福是真的吗？
- 一个单独成立的感受判断：沉默也不尴尬。

碎片大多控制在2—8个字。确实需要表达一个完整画面或自然的心里话时，可以略长，但不能为了完整而写成长句。

特别注意：

“独立可懂”不等于“语法完整”。

一个碎片可以只有一个形容词、一个状态、一个身体反应。它不需要主语、谓语、宾语，不需要补充成一句完整的话。只要观众扫一眼就能理解它表达的具体感觉，就成立。

例如，原文表达丰满的声音逐渐只剩单薄的旋律，孤零零地在空中漫无目的地游走。

应该拆成：

单薄
孤零零
漫无目的

而不是：

丰满的声音只剩一条单薄的旋律
孤零零地在空中漫无目的游走

也不要为了让它成为完整句子，补上原文没有必要保留的主语、谓语和连接词。

以下都是合格的碎片：

单薄
孤零零
漫无目的
脚下没了底
鼻子一酸
话卡在嘴边
肩挨着肩
沉默也不尴尬
像小船漂进雾里
这幸福是真的吗？

以下不合格：

温柔托举（书面、抽象，不像日常会说的话）
思绪难以拼凑（书面、抽象）
无法解开的结（文学化套话）
丰满的声音只剩一条单薄的旋律（仍然是一句完整的长句）
孤零零地在空中漫无目的游走（仍然是一句完整的长句）
刚才还想牢牢攥紧，现在手却不知不觉松开了。（完整叙述句，不是碎片）

绝对禁止以下做法：

1. 把一句完整的话缩短成另一句完整的话，再当成碎片。
2. 把一个长句从逗号处切成两个较长的半句。
3. 为了让碎片单独成立，给每块补上主语和谓语。
4. 把多个碎片用“而且”“所以”“然后”“却”等连接词串成一句话。
5. 把一个碎片写成需要读完下一块才能理解的半句话。
6. 用句号把一串完整短句排成一段，冒充珠子散开。

一个碎片可以不完整成句，但不能是被随意截断、读不懂的半截话。

判断标准不是语法是否完整，而是：单独扫过这一块，观众能不能立即接到一个具体意思。

【二、每颗珠子都要拆开：取消1—2块的限制】

上一版最大的问题之一，是一颗珠子明明包含很多不同的感受，最后却只留下一个代表性总结。

这一版不允许这样过度压缩。

先逐颗阅读 {BEADS}，在内部识别每颗珠子里所有不同的具体体验点，再把它们分别变成碎片。

需要识别的体验点包括：

1. 每一个具体画面。
2. 每一种不同的身体感觉或身体反应。
3. 每一个有辨识度的比喻。
4. 每一句真正有意思的心里话。
5. 每一个真实的情绪转折、反差或状态变化。
6. 每一种不同的听法或声音带来的感受。
7. 每一个帮助观众理解某种体验的具体声音变化。
8. 其他有独立辨识度、能让观众产生联想的具体细节。

每一个真正不同的体验点，都尽量对应一个独立碎片。

例如，同一颗珠子里如果有：

- 声音变得单薄；
- 有种孤零零的感觉；
- 像没有方向地漂着；

就应该分别保留三个碎片，而不是把它们概括成一个“孤独感”。

再例如，同一颗珠子里如果既有身体反应，又有一个具体画面，还有一句心里话，就应该分别保留。不能因为它们都属于同一种情绪，就只留其中一个。

【特别重要：不要把不同维度误判成近义重复】

以下情况虽然可能属于同一个整体体验，但仍然是不同的具体维度，应分别保留：

- 质地和方向感不同；
- 身体反应和心理感受不同；
- 画面和心里话不同；
- 前一个状态和后一个转折不同；
- 同一种情绪下存在不同的听觉体验；
- 几种不同的比喻各自带来了不同画面。

只有真正表达同一个意思、只是换了一个近义词或重复解释时，才合并成一个碎片。

例如，“单薄”“孤零零”“漫无目的”不能因为都在描述同一段声音，就被合并成一个“孤独”。它们各自提供了不同的信息，应该分别留下。

【每颗珠子的碎片数量】

取消每颗珠子通常只留1—2块的旧规则。

新的默认规则是：

- 一颗珠子有几个不同的具体体验点，就尽量拆出几个碎片。
- 一颗内容丰富的珠子，可以有3块、4块、5块甚至更多碎片。
- 一颗珠子如果有多种不同画面、身体感觉、心里话和转折，都应逐一保留。
- 只有珠子本身确实只有一个独立体验点，或者其他内容完全是重复表达时，才可以只留一块。

不设每颗珠子的固定碎片上限。

不要为了控制块数，把不同的体验合并到同一块里。

也不要为了让碎片数量好看，凭空拆出没有独立意义的词。

目标是：珠子里的具体内容真正被拆开，而不是人为增加碎片数量。

【三、几种不同的听法，都要有碎片】

如果一颗珠子里包含几种不同的听法、感受方向或声音联想，不要只挑一种最有代表性的听法。

只要它们不是同义重复，而是让观众听到不同的东西、想到不同的画面或感受到不同的状态，就应该分别留下碎片。

例如，同一段材料里可能同时包含：

- 声音很轻；
- 像在远处呼唤；
- 有种空落落的感觉；
- 又像有人在身边陪着。

如果这些听法都在珠子中有明确依据，就分别保留，不要只总结成“温柔又孤独”。

不同的听法可以并存，不需要强行统一成一种解释。

但纯粹的音乐术语不需要为了覆盖率而保留。具体规则见后文。

【四、碎片的语言：口语、有画面、有身体感】

碎片必须像普通人真的会想到或说出来的东西。

优先使用：

- 身体能感受到的词；
- 眼前能想象出来的画面；
- 日常说话时会用的短语；
- 一下就能接住的心里话；
- 简单直接的状态描述。

不要写成乐评、文学散文、心理学解释或抽象总结。

不要为了显得有文采而把简单的感受改成复杂的修辞。

不要把一个很直白的身体反应写成抽象的心理分析。

不要把口语变成书面词。

例如：

好：鼻子一酸。
不好：内心泛起酸楚。

好：脚下没了底。
不好：失去了现实支撑。

好：话卡在嘴边。
不好：言语无法顺利表达。

好：肩挨着肩。
不好：身体距离逐渐缩短。

好：沉默也不尴尬。
不好：无需言语的情感连接。

好：像小船漂进雾里。
不好：进入一种迷离而无方向的精神空间。

碎片不需要文学性，需要的是辨识度和可感知性。

【五、纯音乐描写只在帮助观众对上感受时保留】

旋律、和声、节奏、织体、音区、伴奏、左右手、音型等纯音乐信息，本身不是屏幕目标。

只有当它能帮助普通观众把某个具体声音变化和某个具体感受对上时，才保留。

例如：

如果声音变得单薄，是为了让观众感受到孤零零，那么可以保留“单薄”这样的碎片。

如果某个声音细节对应一种明确的身体感受或画面，可以保留对应的感受碎片。

如果某个音乐术语删掉后，观众仍然完全能够理解感受，就删掉术语。

保留时优先把音乐分析转换成普通人能听懂的词组碎片，不要留下乐评式完整句子。

如果珠子里有几种不同的声音体验，而且都能帮助观众对上感受，就分别保留，不要只选一种。

小节号、段落号、编号、时间码、编辑说明永远不能进入 line.text 或 feel.text。

【六、line：保持短句，负责把线接起来】

line 是整份屏幕稿的叙事骨架，也是最贵的注意力。

它负责交代：

- 谁或什么关系是这一刻的中心；
- 发生了什么关键动作或变化；
- 为什么会发生这个变化；
- 真正重要的选择、转折或关系变化。

保持上一版短句的要求：每条 line 大约15—20个汉字。

必须是正常人会说的话，短而清楚，有动作、有变化、有自然的口语语序。

关键词要能放大，让观众第一眼就抓到重点。

每条 line 尽量让观众知道为什么，而不是只报出发生了什么。

如果原材料明确提供了行为背后的必要原因，就用最短的人话保留这个原因。

如果材料没有给出原因，不得自己补。

不要把 line 写成完整解说段落。

不要把 line 写成标题或名词堆。

不要为了短而写成：

终于的和解
无法回头的选择
某人、某关系、某决定

也不要为了人话而把 line 拉长成旁白。

【line 数量要减少】

线比现在视频少。

只保留真正承担叙事骨架的 line，不要每颗珠子配一条线。

多个相邻珠子的感受可以围绕同一条 line 展开。

如果几条定稿线在叙事功能上重复，可以在不丢失关键信息的前提下合并。

只从 {LINES} 提取、合并和取舍，不得创造材料里没有的事件、人物关系或因果。

不要因为 feel 碎片变多，就增加 line 的数量。

【七、keys：第一眼抓重点】

每条 line 必须有 keys。

通常选1处，确有必要时选2处。

优先放大：

- 关键人物或关系称呼；
- 核心动作；
- 关键决定；
- 关系变化；
- 必要原因；
- 真正重要的转折词。

keys 通常2—8个连续字符，必须逐字连续出现在对应的 line.text 中。

不要把整句都设成 key。

不要只放大没有信息量的形容词。

尽量让最重要的 key 出现在 line.text 前半段，但不能为了前置关键词破坏自然语序。

【八、feel 的排列：同一颗珠子挨在一起，整体散开】

整体结构仍然是：

一条短 line
一组散开的 feel 碎片
下一条短 line
下一组散开的 feel 碎片

line 是线，feel 是珠子。

一条 line 开启一个阅读组。它后面的 feel 碎片直到下一条 line 为止，都属于这一组。

同一颗珠子拆出来的多个碎片，必须连续排列、挨在一起。

例如：

单薄
孤零零
漫无目的

这三个碎片如果来自同一颗珠子，就应该相邻出现，不要中间插入另一颗珠子的内容。

同一颗珠子的碎片可以放在同一个 feel.items 数组里，也可以在需要时分成连续的 feel 行，但不能被其他珠子的碎片打断。

不同珠子之间要散开分布，不要把所有内容堆成一个长段落。

不要在多个碎片之间加入连接词，把它们拼成一句话。

不要在碎片之间加句号或逗号，假装它们是一个连续的短文。

每个 items[].text 都必须单独是一块可以扫读的碎片。

一个 feel 行可以承载多个碎片。碎片数量较多时，可以继续增加 feel 行，不要把多个体验挤成一个长句。

不要追求每组长度一致，也不要追求每颗珠子的碎片数量一致。

【九、每段总字数：控制在1.0—1.3倍】

{BUDGET} 是每一段现在视频的可见文字字数。

新稿每段最终屏幕正文的总可见字数，按以下方式控制：

总字数 = 该段所有 line.text + 所有 feel.items[].text 的可见字符数，标点也算。

JSON字段名、keys、from、emotion、bead、bars、plan 不计入。

每段目标：约为对应 {BUDGET} 的1.0—1.3倍。

优先落在1.1—1.2倍左右，材料特别密或特别稀时，可以在1.0—1.3倍范围内调整。

不要再写成1.8倍、1.9倍。

新增的文字主要用于增加 feel 碎片，不要用来加长 line。

注意：碎片可以比现在多很多，但每个碎片都很短，因此不需要靠长句增加字数。

如果一段超预算，按以下顺序处理：

1. 删除真正重复的近义表达。
2. 删除只是重复解释同一个意思的内容。
3. 删除不帮助观众对上感受的纯音乐描述。
4. 删除辨识度较低、与其他碎片没有明显区别的内容。
5. 最后才考虑删掉次要的独立体验点。

不要因为一颗珠子碎片多，就直接把它压缩成1—2块。

不要把不同维度合并成一个概括性词语来省字数。

不要为了控制预算，牺牲一整颗珠子中有辨识度的身体感觉、画面、心里话或转折。

如果一段低于预算，按以下顺序补充：

1. 检查是否遗漏了某颗珠子的独立体验点。
2. 检查同一颗珠子是否还有未保留的身体感觉、画面或心里话。
3. 检查是否漏掉了不同的听法。
4. 检查是否漏掉了真实的情绪转折或反差。

不要通过加长 line、堆书面解释或添加纯音乐术语来凑字数。

预算是控制总量的边界，不是把每颗珠子都压成一块的理由。

【十、emotion：每条线必须有情绪颜色】

每条 line 都必须有 emotion，并且只能从以下七个值中选一个：

炽热、欢喜、亲密、安心、孤单、不安、悬着

emotion 是这一组的主情绪色。

不要为了省事让全曲只剩一种或两种颜色。

如果材料真实支持至少三种不同主情绪，最终也应使用至少三种不同 emotion。

相邻组如果关系状态、心理张力或情绪方向真的发生变化，emotion 应跟着变化。

只有材料确实处在同一类状态时，才连续使用同一种颜色。

不要为了凑颜色创造材料里没有的情绪。

【十一、bars：只记录局部时机】

每个 feel item 都必须有 bead 和 bars。

bead 必须是真实存在于 {BEADS} 的珠子编号。

如果某块碎片只属于珠子原文明确写出的局部小节范围，bars 填写那个范围。

如果没有更小的明确范围，bars 填空字符串。

bars 只能照 {BEADS} 里明确写出的范围填写，不得猜测。

如果同一颗珠子的几个碎片对应不同局部小节，应分别填写各自的 bars。

小节号只出现在 bars 字段，绝不能进入观众实际看到的正文。

【十二、from：线只能来自真实定稿线】

每条 line 的 from 必须列出它实际依据的定稿线编号。

如果合并了两条定稿线的信息，就列出两个真实来源。

不得为了让句子更顺而补入来源里没有的事实、动机或因果。

不得创造不存在的线编号。

【十三、plan：只讲全曲排法和前后呼应】

plan 用简短人话说明：

- 全曲主干如何往前走；
- 哪些关键词值得前后呼应；
- 哪些体验在后面真实地重复、加深、减弱或反转；
- 哪些段落主要靠 line 推进；
- 哪些段落更适合让 feel 碎片充分散开。

plan 不要写编辑过程、覆盖率、自我评价或预算计算。

不得在 plan 中补充材料没有提供的作品内容。

【十四、正式输出前，内部做六轮检查】

不要输出检查过程。

第一轮：查珠子内部的体验点。

逐颗阅读 {BEADS}，识别其中所有不同的画面、身体感觉、比喻、心里话、转折和不同听法。检查这些不同体验是否分别有对应的碎片。不要把不同维度误判成同义重复。不要再用每颗1—2块的旧标准压缩。

第二轮：查碎片形态。

把每个 feel.items[].text 单独拿出来。它是不是一个短词组、状态、身体感觉、画面或心里话？是不是大多2—8个字？是不是一扫就懂？它是否真的像碎片，而不是一条完整的短句？

如果读起来仍像一条完整叙述句，就继续拆成几个真正独立的体验碎片。

如果读起来像被随意切断的半句话，就改成一个自然、独立可懂的短词组。

第三轮：查珠子排列。

同一颗珠子的碎片是否挨在一起？有没有把同一颗珠子的不同碎片拆散到其他珠子中间？有没有把几个碎片用连接词拼成一句话？整体是否形成了珠子散开、线接得上的视觉感觉？

第四轮：查 line。

line 是否保持约15—20字？数量是否比现在视频更少？是否有人话、有动作、有关键词？必要的为什么是否保留？有没有为了短而变成标题？每条 line 是否都有 emotion 和真实 from？

第五轮：查总量。

逐段计算 line.text 与 feel.items[].text 的总可见字数。是否在对应 {BUDGET} 的1.0—1.3倍？如果超出，先删重复内容，不要先砍不同的体验点。如果不足，优先补回遗漏的珠子碎片。

第六轮：查来源和情绪。

每条线的 from 是否真实？每块碎片的 bead 是否真实？bars 是否有明确依据？emotion 是否符合七种限定值？材料支持时是否保留了真实的多种情绪？正文是否完全没有编号、小节号、时间码和编辑说明？

【十五、最终屏幕应该是什么感觉】

第一眼：

少量大字 line，约15—20字，关键词突出，让观众知道发生了什么、为什么。

第二眼：

周围散着很多小字 feel。

不是一条条缩短的句子，而是一颗颗真正拆开的碎片：

单薄
孤零零
漫无目的

鼻子一酸
话卡在嘴边
脚下没了底

肩挨着肩
沉默也不尴尬

像小船漂进雾里
这幸福是真的吗？

每块都能独立扫懂，不需要连起来读成一句话。

同一颗珠子里不同的体验尽量都有对应碎片，但真正重复的意思只保留一次。

整体上：

- 线少，短，叙事接得上；
- 珠子多，拆得开，散得开；
- 每颗珠子不再只有1—2个代表性短句；
- 不同的画面、身体感觉、比喻、心里话和听法都能分别出现；
- 碎片大多2—8字，口语、具体、一扫就懂；
- 碎片不是完整句子，也不是被截断的半句话；
- 每段总量约为现在视频的1.0—1.3倍；
- 注意力必须最经济，不堆重复，不写书面解释。

【十六、最终输出格式】

最终只能输出一个合法 JSON 对象，不得输出分析、解释、Markdown、注释或任何 JSON 之外的文字。

顶层结构严格如下：

{
  "plan": "全曲怎么排、哪些词前后呼应",
  "sections": [
    {
      "sec": "S01",
      "rows": [
        {
          "kind": "line",
          "text": "线这一行的话",
          "keys": ["要放大的关键词，照抄 text 里连续的字"],
          "emotion": "炽热",
          "from": ["S01-1"]
        },
        {
          "kind": "feel",
          "items": [
            {
              "text": "单薄",
              "bead": "S01-B2",
              "bars": ""
            },
            {
              "text": "孤零零",
              "bead": "S01-B2",
              "bars": ""
            },
            {
              "text": "漫无目的",
              "bead": "S01-B2",
              "bars": ""
            }
          ]
        }
      ]
    }
  ]
}

字段规则：

1. sections 严格按照 {SECONDS} 中的段落编号和顺序输出，不得创造新段落。
2. kind 只能是 line 或 feel。
3. line 必须有 text、keys、emotion、from。
4. emotion 只能是“炽热”“欢喜”“亲密”“安心”“孤单”“不安”“悬着”之一。
5. feel 必须有 items；每个 item 必须有 text、bead、bars。
6. 每个 feel.items[].text 只能是一块独立碎片，不得把几个碎片写成一句话。
7. 同一颗珠子的多个碎片必须相邻排列。
8. keys 中每个字符串都必须逐字连续出现在对应 line.text 中。
9. from 必须是真实存在的定稿线编号。
10. bead 必须是真实存在于 {BEADS} 的珠子编号。
11. bars 没有明确局部范围时必须写空字符串。
12. text 只写观众实际看到的文字，不得出现来源编号、小节号、时间码或编辑说明。
13. 不得增加 color、size、seconds、budget、coverage、note、analysis 等额外字段。
14. 所有字符串必须符合合法 JSON，不得有注释或尾随逗号。

最后只记住五句话：

1. line 是线，少而短，约15—20字，让人知道发生了什么、为什么。
2. feel 是珠子，必须真正碎开，不是缩短后的完整句子。
3. 一颗珠子有几个不同的体验点，就尽量拆出几个碎片，不再限制为1—2块。
4. 单薄、孤零零、漫无目的，可以就是三个独立的 feel，不需要补成一句人话。
5. 珠子散开，线接得上；感受尽量保留，注意力必须最经济。
