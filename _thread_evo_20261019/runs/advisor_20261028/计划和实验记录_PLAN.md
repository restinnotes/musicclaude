## 为什么改

- 包3：最终选中的解释几乎全是综合时看着珠子现写的（Op.60 25 个里 1 个来自池子，Op.61 0 个），补缺成了主要生产方式。
- D13：写稿只给本线前史和谱面事实，模型拿不到音乐的感受，只能把强弱变化解释成"管理表达"，核心体验没有来由。
- 人话：D12 原稿本来很像人话（"他再也不能原样待在那一刻里"），是池子字段（前提/桥/结果）和综合重写把它变成"延续需要未获满足"这类说法；
  最后的人话化只能修短，找不回原句，还丢限定、添东西（包3 Op.60 人话化后主审改回 9 处、修补 3 处）。
  原料抽象而有内容，翻译会丢东西；原料是空的抽象，人话化补不出内容。所以人话必须从写稿开始一路保住。

## 模型与链路

- 只用 mimicgate 网页版：Web6 High、Web5.6 High（yi-mimicgate-20261002，最多 5 路并行）。写稿和评审都用这两个。
- 不加 Sol 6.1、Argon、Luna 等其他模型（单独写都不如旧 Web，也没有证据能补强）。
- 每次调用记耗时；长任务明显快于历史就做水杯题，答 8 保留，不是 8 就停。账号保护信号立即停并告诉用户。

## 步骤

1. **写稿 D14**：一次写整首，每段先写感受、再写为什么，大白话。在 D12 P1 上加：
   - 不许拿"更在乎了 / 更有分量了 / 不是从前那个人了 / 经历过所以不一样"当原因，要说出前面具体发生了什么、它为什么让此刻这样；
   - 新增历史只写心里真实发生过的具体事；
   - "可以 / 允许 / 不等于"只排除一种理解，不是此刻感受出现的原因；
   - 音乐回来不等于对方回应了、关系恢复了。
   不给谱面事实，不给珠子。6 和 5.6 各写 3 篇（自由 / 时间 / 自己 三种视角各一），两首共 12 篇。
2. **覆盖关**：D10–D14 合起来逐颗判（covjudge，两位评委都说"解释了"才算严格）。重点看老缺口：
   Op.60 93–110（回忆、时间过去、"我"退到后面），Op.61 24–65（凄婉、越撑越焦灼）。不够就改提示词重写，不往下走。
3. **建池**：每段收所有稿子的解释，**保留原稿原句**（feel / thread / new 原文）。前提 / 桥 / 结果只作合并和接线判断用，
   三者都相同才合并，不限条数。
4. **只从池里接线**：逐段往下挑，后面用到的前史必须是这条线前面真的写过的；接不上就回退。成品**直接用原句**，只做补指代、删重复这类小改；
   改写后比原句更抽象要扣分。挑完统计这条自洽线上解释了多少颗珠子，缺口如实留空。
5. **补缺最后做并计数**：只补第 4 步的空；补得多说明写稿不够，回第 1 步。
6. **对照**：与包3 成品、N8、B0、60d、60f 比，原来解释清楚的地方不能退步。合格后做关系图（一个解释一个节点）和轻度润色（只管句式、衔接），再交给用户。

## 规矩

写稿不看珠子；评委每个判断写一句理由；中间产物不给用户读；伪因果负例进评委校准。
