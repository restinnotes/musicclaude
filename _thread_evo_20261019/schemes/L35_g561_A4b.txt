你要为一首钢琴曲写最终使用的 Thread（线）。

Thread 是同一个人在整首作品里经历的一件事。最终成品应当是一条方向明确、因果自然、像普通人讲述真实经历的线。

【段落】
{SECTIONS}

【Center（已经给定，不得修改）】
{CENTER}

【已经通过 A2 的人物经历候选】
{ROUTES}

【从珠子提炼出的体验性质（TARGETS）】
{TARGETS}

你看不到原始珠子，也不得猜测珠子的具体画面或措辞。

【第一步：选定唯一经历弧】
从 ROUTES 中选一条最自然、因果最完整、人物经历方向最明确的路线。

不要选择心理活动最多的路线。优先选择真正的心理变化少而清楚、其余时间可以自然呈现体验和后果的路线。

选定后，在内部把这条经历整理为：
- 起点：人物最初的实际处境。
- 节点：真正改变人物认识、选择或承担方式的事实。
- 后果：节点成立以后，人物实际怎样继续经历这件事。
- 落点：全曲结束时人物处在什么位置。

这份整理只供写作使用，不增加输出字段。

【第二步：给段落分配不同权限】
每段只能承担以下一种或两种功能：
1. 节点：一个真正的新认识、新选择或新的实际后果首次成立。
2. 后果：已经成立的节点在此刻对人物造成的实际影响。
3. 体验：人物仍处于已有处境中，此刻的身体感受、注意力、情绪质地或沉浸状态。
4. 延续：人物带着前面的事实继续经历这件事，没有新认识。

先确定哪些段落是真正的节点段。节点不需要很多，不能为了音乐段落数量增加节点。

节点一旦成立，后续所有段落都必须承受它。不能重新把人物放回节点成立以前的状态。

非节点段没有创造新认识、新决定、新问题、新判断的权限。它们只能呈现已经成立的经历在此刻的体验、后果和延续。

这不是要求非节点段落都写成暂时不想。可以写他正在享受什么、身体怎样、注意力在哪里、某个已经存在的念头怎样影响此刻。只要不重新讨论已经成立的两难，就是有效内容。

【第三步：Center 的使用】
Center 是整条经历的恒定核心，不是逐段重复的题目。

两极可以同时存在，也可以始终无法完全分开。人物不需要通过不断重新选择其中一极来证明 Center 贯穿全曲。

同一个两难只在真正需要人物面对它时呈现。后续如果仍然受到它影响，写具体后果，不重新问一遍，不重新宣布一遍，不把相同问题拆成几个不同问句。

人物最后可以没有解决问题，但必须处在已经经历过这一切之后的位置，不能回到最初的心理状态。

【第四步：TARGETS】
TARGETS 只决定这一段体验的情感底色和质地，不产生新的心理事实。

如果某个 TARGET 的体验性质与人物当前的经历相符，可以自然呈现。
如果它只是一种情绪强弱变化，就让它留在体验层，不要据此增加新的认识或决定。
如果它与人物的经历不相容，不要编造事实去迎合；可以放入 uncovered_targets。珠子本身仍然可以在屏幕稿中承担这项体验。

【第五步：人物经历必须自己成立】
不新增外部事件、前史、对白、物件、第三人、地点或场景。
不新增对方的动作，不推断对方未经检验的隐秘心事。
允许一个从头到尾不变的轻处境和小动作。
所有变化都必须来自已有经历、已经成立的事实和人物实际承受的东西。

必须像普通人平常想事、说话。写具体念头、所求、顾虑、实际感受。不要写心理分析报告、人生道理或抽象总结。不要用不同说法反复解释同一个认识。

【第六步：条目数量】
每段必须有条目，不得空段。
每段以一条为基础，需要两个彼此独立的内容时才写第二条。真正的节点段可以有更多条，但不能为了达到固定数量而拆分同一个念头。
体验条目不是新的心理变化。一个段落可以只有一条体验或延续。

每条是一句完整、自然的话，只表达一个主要意思。相邻段落之间的承接必须自然，整条线连续读下来必须像一个人讲述同一件经历。

前面已经成立的事实，后面直接承受其后果，不重新解释因果。

【第七步：最终检查】
只读正文，检查：
1. 能否清楚指出整条经历的起点、真正的节点和结尾？
2. 每个节点是否只首次成立一次？
3. 有没有在节点成立以后重新回到节点以前的犹豫？
4. 有没有同一个决定、认识或问题换一种说法重新出现？
5. 非节点段是否在写体验、后果和延续，而不是伪造心理变化？
6. 有没有为了对应音乐情绪而增加人物没有经历过的心理事实？
7. 有没有外部加戏？
8. 全文是否仍然具体、有人话、有真实所求，而不是为了不重复变成空泛的短句？

发现重复，优先检查节点安排和段落功能，不要只替换词语。

【输出格式】
只输出 JSON，保持以下结构，不增加字段：
{
  "status": "complete",
  "base_route": "route_id",
  "segments": [
    {
      "sec": "S01",
      "relation": "没在想/还说不清/正在面对",
      "items": [
        {
          "id": "S01-1",
          "text": "...",
          "cite": [],
          "covers": ["bead_id"]
        }
      ]
    }
  ],
  "uncovered_targets": [],
  "blocked_sections": []
}

每段严格按照 {SECTIONS} 顺序出现，必须有条目。relation 只作元数据。cite 只在直接依赖前面某条内容时填写编号。covers 只填写实际覆盖的 bead_id。

不得输出 blocked，不得空段。blocked_sections 固定为空数组。status 固定为 complete。

【每段都要写】
每一段都必须有条目，不得输出 blocked、不得空段。音乐很短的过渡段、或者实在没有新东西的段，可以只写一条短的承接：人物带着前面已经有的东西继续往下（接着做、接着在意、暂时没在想），如实写，不硬造新认识，也不重复前面的辩论。
