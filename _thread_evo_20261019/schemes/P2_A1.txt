任务：对三条已经独立写完的 Thread 线进行
珠子覆盖检查、整体比较和结合位置分配。

本阶段才第一次读取珠子。

三条线已经写成完整成品，它们的正文、
段落、条目顺序、Center 和关系都已经确定。

你只能评估、选择、分配珠子的结合位置。
不能新增、删除、改写或重排线的任何内容。
也不能改动珠子的原始内容。

【三条已经写完的候选线】
{CANDIDATES_JSON}

【珠子：保留原始角色、段号及内容】
{BEADS_JSON}

【段落】
{SEGMENTS}

一、输入与任务边界

CANDIDATES_JSON 中是三条完整的 Thread，
分别标为 C1、C2、C3。

每条都已有：
- center；
- 按段排列的 segments；
- 各段的 relation；
- 具有稳定 id 的 items；
- 每条 item 的 text、cite 和 after。

不是候选故事草图，也不是等待扩写的材料。

本阶段不能再构造人物经历。
不能从不同候选中取出局部条目拼成新线。
不能为覆盖珠子而修改某条线。

你的选择对象是整条已经完成的成品。

二、判断珠子的体验性质

对每颗珠子，区分：

- 能与人物经历相接的主观体验性质；
- 主要属于音乐声音、画面或比喻，
  不需要转成人物情节的内容；
- 珠子提出的想象性解释或人物活动；
- 同段其他珠子中的理解是否能够相容。

一颗珠子可能包含几种感受，
不能为了结合方便把它们压成一种。

不要把珠子的场景、比喻或想象中的人物行为
认定为真实发生的事。

提炼体验性质时保持开放。
不能因为某个比喻提示了一个心理原因，
就认定那是唯一合理的原因。

三、检查真正的相接

对每颗珠子和每条候选线，检查同段已写出的内容。

判断依据必须是：

读者能否从这一段人物自身的处境、
已经经历过的事情、所求和顾虑中，
找到与珠子主观体验大体相近的来由。

不要求线解释珠子的声音或比喻。
也不要求线出现与珠子相同的情绪字眼。

单纯主题相近、情绪强度相近，
或同样使用某个抽象词，不足以算作覆盖。

也不能只因为人物的情绪变化次序
和珠子中的声音或想象性情节一样，
就算自然相接。

反过来，若人物已经具有独立成立的心理处境，
与珠子表达了相近的感受，
也不能仅因双方说到了相似的情绪而判作复述。

要检查这种感受在人物经历里是否真有根据，
尤其不能把珠子中想象的活动或事件
当成线里实际发生过的事。

四、候选适配等级

每颗珠子对每条候选使用：

明确相接：
该段已写出的条目有明确、成立的人物处境，
能自然承载相关体验。

可以自然展开：
该段已经写出的事实和前文历史足以使相关体验
自然成立，虽未直接说透，读者仍能从原文接上。
不能假设还要增加新的正文或人物事实。

缺少依据：
现有成品缺少必要的人物处境或历史，
必须新增、改变内容才能相接；
或者只能靠主题词、情绪强度、珠子想象的动作
来勉强对应。

每项 basis 应指向具体条目 id，并简要说明根据。
缺少依据时，明确指出缺在哪里。
不虚构一个尚未写出的条目来证明覆盖。

对于主要属于声音本身、没有对应人物体验要求的
内容，应在 sound_only 和 gap_type 中说明，
不把这种内容当作必须虚构人物情节的缺口。

五、同时检查线本身的四个维度

不能只按珠子覆盖数量决定优劣。

对每条已完成的线，同时判断：

1. 单独成立

只读线能否读到同一个人的一件事。
人物的变化是否有真实前因。
已获得的认识有没有被重复当作新发现。
有没有靠音乐变化、外部虚构事件或新增关系回应
推动人物。

2. 不啰嗦，连着读顺

各句能否自然接上。
每句话是否有独立作用。
是否重说前面的内容。
内容少的地方有没有硬填。
是否用长句反复解释同一件事。

3. 人话

人物的所求、顾虑和感受是否清楚、切身。
读起来是否像平常讲一个人的经历。
有没有用心理分析、抽象概括、哲理总结
代替真正发生的心理内容。
有没有句式过于相似或不必要的限定、否定。

不机械禁止任何词或句式。

4. 接得上珠子

每段是否有足够的具体人物处境，
自然承载同段珠子的不同体验。
有没有把珠子的画面、比喻、想象情节
变成人物真实发生的事。
有没有为了对应而造成不自然的心理动作。

六、选择整条成品

综合四个维度，选择最适合成为最终成品的整条线。

不得只按覆盖数量排名。
也不能因为某条线结构最完整，
就忽略它在自然语言、重说或珠子相接上的
严重缺陷。

不能以局部的漂亮句子代替整件事的成立。
不能以某段特别贴珠子为理由，
接受整条经历缺乏根据的重大问题。

对于候选间的真实取舍，应说明：
哪条线整体更有前因、更自然，
哪些方面更能接珠子，
以及选择它会保留哪些缺陷。

只能选择完整的 C1、C2 或 C3。
不能把另一候选的条目搬进被选中的线。

如果三条都有重大缺陷，不能硬选一条合格成品。
可以 preferred 为空，并标记 rethink_upstream。

诊断结果只供验收记录和后续独立实验分析。
不能作为对已写成品的修改指令，
也不能作为下一次写线的珠子衍生输入。

七、给选中成品分配珠子位置

在不修改任何内容的前提下，
为选中的线建立“条目 id—珠子 id”对应。

同一颗珠子应优先放在本段自然承载其
主要体验性质的那个条目后面。

如果多个条目都能相接，选择最贴切的一条。
同一颗珠子在最终排列中只能出现一次。

一条线的条目可以接多颗珠子。
但不能因为条目与珠子处于同一段，
就自动认定它们的体验性质已经对应。

如果珠子中几种听法不能被同一个人物处境
同时容纳，不得硬把它们压成一种解释。
应区分能够相接的部分和真实缺口。

不要求把声音本身翻译为人物经历。
纯声音内容在不改变原文的情况下，
可与本段适合的条目相邻排列，
但不能虚报人物情境已经解释了它。

如果某颗珠子确实无法自然分配到本段任何条目，
记录缺口，不虚构条目或修改文字来补救。

八、在原有 JSON 结构中表示分配结果

使用 segment_guidance 中已有的 qualities 和 source_ids。

对选中线的每一段：

qualities 中的每项对应一个实际存在的条目。

quality 必须以该条目的完整 id 开头，
紧跟一个全角竖线“｜”，再简要说明
该条目为什么能承载这些珠子的体验。

source_ids 放分配给这条目的原始珠子编号。

若一条目承载多种体验性质，
可以有多个 qualities 项，但同一珠子
不能重复分配到不同条目。

没有分配珠子的条目，不必建立 qualities 项。

只记录现有条目与珠子的对应，
不能在 quality 中写新的人物经历，
也不能把这一字段当作修改正文的建议。

historical_requirements 仅记录尚未满足的
历史条件或覆盖缺口，作为事后诊断。
不能用它补造人物历史。

avoid 记录结合时必须避免的错误对应，
而不是指导重新写线。

这一映射供后续程序机械排列使用：
程序按条目 id 找到 source_ids，
将对应珠子原文放到该条目之后。
线的 text 和珠子的原始内容均不得修改。

只输出 JSON：

所有映射条目 id 都必须真实存在于选中的成品。
每颗珠子最多分配到一条条目。
不改变任何珠子或线的内容。

不输出修改后的线。
不输出改写过的珠子。
不输出新的故事、条目或补充人物经历。

只输出 JSON。
