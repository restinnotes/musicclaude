下面是同一首作品的几条 Thread 人物经历候选。你完全看不到珠子，也不要根据音乐细节评判。

你的任务不是挑最戏剧化、转折最多、主题最鲜明的一条，而是判断哪条路线最有可能写成一条独立成立、简洁、像真人经历的 Thread。

这一步尤其要判断：路线有没有真正保住一个人的具体处境、所求和顾虑，而不是只剩一串自洽的心理状态。

逐条检查：

1. 起点是否真的让人知道“他正在经历什么”。
starting_condition 和 stakes 应当足以让读者明白他具体在意什么、想要什么、顾虑什么；如果只能看出高兴、害怕、留恋、没有把握之类的泛化情绪，路线太薄。

2. 起点有没有为了后半转折而偷塞事实。
某个起始事实如果不是理解整件事从一开始就必需的，只是为了让后面的某个认识、决定或关系判断显得有依据，应视为提前补剧情，不因它被写在第一阶段就变合法。

3. 后面的 phase 是否真的由前面的经历长出来。
检查每次换 phase 时，新增的后果、看法或选择是否能从 starting_condition、stakes 和前面 phase 已经写出的经历自然得到。
不得依赖突然出现的他人行为、隐秘心思、外部事件、未写出的前史或模糊的“后来发生了什么”。

4. 是否把一个持续存在的具体所求或顾虑，逐渐换成了更泛的心理问题。
如果开头还看得出人物具体在意的东西，到了中后段只剩“能不能安心”“有没有把握”“要不要想开”“还能不能接受”之类的自我管理，说明路线已经把真实处境抽空。

5. phase 是否真的有不同任务。
允许多个音乐段落留在同一 phase，也允许同一所求或顾虑一直存在；但如果几个 phase 只是反复把同一个问题重新想一遍，或者只是情绪强度不同，却没有新的后果、处境或立场，那么这些 phase 应当合并，路线不够好。

6. 是否把共存的东西过早处理掉。
一个具体愿望和一个真实顾虑只要都还成立，就可以长期并存。不要因为路线没有快速解决它们就扣分；相反，如果某一边没有充分原因便突然消失，或人物过早得到一个过分整齐的答案，要视为风险。

7. 是否主要靠人物管理自己的心理来推进。
如果多数 phase 的差别只是人物压住、放开、劝自己、暂时不想、重新面对、再次坚定，说明路线把一件事缩成了一种心理操作。

8. 是否有足够的实现空间。
路线应当锁住事实、具体所求、顾虑和真正的阶段变化，但不应规定每个音乐段落唯一的心理动作。后续综合者应当还能根据体验性质，让同一处境的不同侧面在不同段落显出来，而不用改动路线事实。

9. 结尾是否只是把开头的矛盾再说一遍、把情绪放大，或者突然给出一个此前没有挣来的成熟答案。
结尾可以开放，也可以有明确变化；关键是它必须是前面这件事走到这里留下的位置。

对每条路线输出：
- route_id
- verdict：保留 / 淘汰
- strengths：最多3条，写真正的结构优势
- risks：最多4条，指出具体结构风险
- phase_distinctness：高 / 中 / 低
- stake_persistence：高 / 中 / 低
- unsupported_fact_risk：高 / 中 / 低
- implementation_space：高 / 中 / 低

然后选出最多 3 条进入下一步，按优先顺序排列。

不要改写候选，不要替它补事实，也不要因为某条路线转折多就奖励它。
只输出 JSON：
{
  "routes": [...],
  "selected": ["route_id"]
}

候选路线会追加在本提示词末尾。
