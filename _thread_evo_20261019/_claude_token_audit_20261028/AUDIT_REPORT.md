## 怀疑的浪费，哪些成立

- **状态处理成立，但不能整块删除计费。** 984 次严格候选共 $108.052371，输入中位数 407,531 Token，汇总缓存读占输入 99.27%，每次请求成本均值 $0.1098、中位数 $0.0918。其 Token 为普通 2790、读 396500533、写 2921298、输出 268536。这些是请求归因；其中 3 次承担 $14.091760 的大前缀冷写，删掉这几次通常会把重建移到下一次真正工作，不能全部当节省。方案 A 中间情景约净省 12.8%，同时扣除了新通知/验收、缓存和返工。
- **长上下文是关键放大器。** 主会话输入中位数 430392，P90 748574，最大 933489。间隔超过一小时的 21 次请求只有 9.46% 的输入为缓存读，承载 $74.070，其中 $73.490 为缓存写。缩减频率可能省循环，也可能让缓存过期；低频模式不自动更便宜。
- **重复阅读有线索，不能精确收费。** 3666 个关联工具结果合计 5924412 字符；101 次 Read 涉及 61 路径，其中 15 路径重复，共 40 次额外路径读取。长度至少 2000 字符的结果未发现完全相同重复；这不排除不同命令读取同一内容。字符不是 Token，Read 只覆盖专用工具，不包含 Bash/PowerShell 阅读，因此不把 40 次当成 40 次浪费。关键整首阅读不能由评分摘要替代。
- **Desktop 标签容易被高估。** 含 wrap_up 的 279 次请求合计 $36.931，含 update_plan 的 148 次合计 $35.376，两者混合实质答复并可能重叠。沿父消息链可见工具回执后的模型响应分别为 19 次/$1.783、9 次/$0.523，约 0.346% 与 0.102%；这也只是相关请求成本上界，并非独立工具增量。不能直接相加宣称可省。
- **原生小 Agent 和已查到的工具尾声属于小项。** 两个原生 Haiku Agent 0.0562%，wrap_up 后续相关成本 0.346%，优先级远低于状态/调度。1026 条去重 stop-hook 摘要中没有阻止继续或非空额外上下文的记录，2 条有错误；没有证据证明它们触发了额外推理循环。请求头 querySource 全为 sdk，未找到可分开的 prompt-suggestions 调用；不能把未证实的功能计为浪费。
- **工具说明已在 usage 内。** 15 种请求形状含 58–65 个工具定义，系统/工具序列化字符约 2.86–3.41 万 / 15.42–16.67 万。无法准确分离 Token，也不能在每次成本之外再加一份全价说明费。8 次压缩边界可核验，但摘要服务的独立 usage 不能可靠分离，不把上下文缩短量当成已用 Token 或已省费用。

1136 次历史 GPT 调用没有被当作 Claude 成本或浪费。外部模型 Token 成本在所有方案中为 0；Claude 为其准备任务、看结果、调度和返工的成本已经在账本/模型内。

## 质量事件决定了可以委托到哪里

禁网案例不是单纯服务修复：2026-10-24 04:45 UTC 为避开 websocket 传输故障，把“回答时请不要进行联网搜索。”追加到实际请求。D14–D18 的 58 份完成稿都带该约束；D19 只有 8 份待执行输入，没有完成稿。10 月 27 日控制变量追问后才核查 web 使用，D20 的 8 份恢复稿不带禁网约束且全部有 web.run 记录。D12 的 32 份基准中可证实联网 27 份、未联网 4 份、元数据缺失 1 份，因此不能声称全部同条件。

直接相关 Claude 请求：禁网引入/传输修复 10 次/$1.269，模型/账号/强度方向调查 53 次/$3.429，联网核对和恢复 24 次/$1.696。它们都包含正常工程与必要调查，不能全当可避免。期间全部 711 次/$75.302 只是受影响暴露窗口，**没有算成错误造成的浪费**。现有证据支持联网是重要混杂变量，不足以排除其他因素。Codex 同样可能改错实验条件，防线是冻结完整渲染请求和研究契约，而不是换个写代码的模型。

评审目标偏移也不能只靠工程交接解决。早期“编故事”的 R2 稿得到 10/10/9.7，用户明确否定；后期局部覆盖增加，保存的 P4d 整首双评委结果在两首作品上共 4 份均判“新版有实质退步”。缺少完整 Bead 输入、评委激励偏移、小样校准过拟合和缺少冻结整首回归样本都参与了问题。用户也在推进中细化目标，不能把所有修订追溯成最初的错误。减少 Claude 到只看汇总分会更容易晚发现；保留 Claude 同样不能替代可靠的回归门。10 个历史影子案例、证据 ID 和测试边界见 `QUALITY_RISKS.md`。

## 明确建议

**如果只能改一项，先把实验执行改成“确定性状态机 + 阶段完成/异常回执”，停止让 Claude 逐次守候后台任务。** 只在达到验收门、出现异常、评分矛盾、实验变量变更时请求 Claude；关键成品仍完整阅读。它对应真实较大的成本池，且最容易用现存批次记录证明行为没有丢失。

后续采用 **B 的分阶段工程分工** 最有可能兼顾质量与节省：先离线任务匹配/恢复、格式与结构验证，再调度与聚合；所有触及模型、联网、Bead/Thread 内容、评委目标的变更先过契约差异检查及 Claude 艺术验收。现有离线 `find_job` 回归已通过 1 个测试（真实函数 AST + 合成任务目录，无生产模块导入、无模型调用）；这只证明一个确定性匹配行为，不能证明 Codex 已达到工程/艺术同等质量。

本次只读采集与建模；没有修改生产配置、安装插件、重构运行系统或重跑生产模型实验。审计文件独立保存于项目 `_claude_token_audit_20261028`，并在本输出目录保留相同副本。请从 `AUDIT_METHOD.md` 与复现脚本检查账本，不把条件预测当成已发生的节省。
