# 交给 Claude 主 Agent：仅恢复「结构分段 → A/T/H Pool → Bead」的可复用机制

你在 `D:\musicclaude` 中执行任务。当前任务已明确收窄：**只做到独立音乐结构分段、A/T/H 研究贡献检查、Pool 映射、Bead 生成和用户验收**。不得扩展到 History、Thread、WHY、Inner/Outer、E7、视频渲染、V3 宪法修订。

## 一、不要再误读 DAG

不是让 run151 重新跑，run151 是读取冻结 23 站珠子和 GPT-5.6 History 的后期呈现实验。也不应把 run126/127 的 run ID 当作将来每首曲子固定要读取的依赖。它们是既有方法、数据和对照基线。

**新机制的真正 DAG：**

```text
作品 + 可核查乐谱/录音/外部音乐结构资料
                   ↓
       独立结构研究与边界裁决（S）
                   ↓
         确认宏观自然音乐段落
                   ↓
  A-int/A-web、T-int/T-web、H1–H5 的原始研究
                   ↓
  按 S 的段落做时间/语义关联，形成带来源的逐段 Pool
                   ↓
           A-only 珠子基线（固定段落）
                   ↓
   T 增量检查 / H1–H5 分别增量检查 / 来源模型检查
                   ↓
            仅保留真实改善的部分
                   ↓
            候选珠子 + 独立盲审
                   ↓
              用户阅读、作判断
       [停止：不执行任何后续语义或渲染环节]
```

注意：A/T/H 首轮研究可以在独立结构研究之前或平行运行；**但它们进入某个段落的 Pool 必须依据结构研究已经确认的时间范围**。不允许在此阶段把“旧 run126 的 9 个计算窗口”与“任意作品必然九段”等同；也不允许 Bead Generator 自己再次切出 23 站。

## 二、立即执行的具体步骤

### STEP 0 — 查实实际研究数据和现有代码（只读）

找到现有仓库中的研究产物与提示词、`run102_struct_timeline/timeline_v2.json`、run126 的 `manifest.json`/`units.json`/`canon.json`/`resid.json`、run127 的 `go.py` 与 BEAD 模板，以及实际研究材料的原文件。确认哪些材料真的存在，列明 `source_id / branch / model / int-or-web / work / mm_range / path / hash`。

必须区分旧样本模型与当前可调用模型；未知可用性不能自行编造。不要因为看见摘要就宣称读过原始材料。

### STEP 1 — 独立结构分析（这是必须真正可复用的新能力）

使用 `prompts/01_STRUCTURAL_RESEARCH_WEB.txt`，输入当前作品和已有资料；必要时独立运行 `02_STRUCTURAL_LISTEN_OR_SCORE.txt`，再由 `03_STRUCTURAL_ADJUDICATION.txt` 产生完整宏观乐段。**这三个 Agent 都不能读取 A/T/H 的情感或历史正文，也不能从 run102 切点倒推答案。**

结构提示词完全通用：不包含 Op.60/52/61 专属分段、小节数字、人物、故事或“分九段”的固定要求。明确允许无谱/无录音/无可靠来源时报告不足，不准假装验证。

结构研究重点是读者能明显感到的呼吸、较完整乐句群、主题/织体/结构段转换，而不是把每个装饰音、细微力度、换声部作为新宏观段。音乐资料可留下次级边界，但不自动升级为段。各结构判断附来源、定位、置信度、歧义；不能把任何单一外部分析当无误的绝对真理。

Op.60 的历史 run102 **九个宏观窗口只用于结构分析完成之后的盲后比较**；允许结构分析结果不同，但差异必须有音乐依据。如果结构可信但与九段不一致，应当呈现原文对照并解释，不要为了复现历史数字而修改结构提示词。Op.52、Op.61 只能凭各自资料决定大小。

### STEP 2 — 按结构段落建立真正的 Pool

用 `prompts/04_POOL_ALIGNMENT.txt` 处理原始文档及已提取的单元。旧 Canon 是校验与加速素材，**不能只从规范代表句重新构建 Pool 并声称没有丢失细节**。应当能够回到原始 A/T/H 完整文字。归入哪段和是否有产品价值是两次判断；不可因为边界不精确而删除原文。宽范围内容保留完整原文和跨段共享链接，不能被硬切成两句；来源不确定的放 `UNRESOLVED`。

### STEP 3 — A-only Bead 基线

使用 `prompts/05_BEAD_A_BASELINE.txt`，**先只给 A-int / A-web**，不在生成时混入 T/H。固定一个结构段就是一个候选珠子的时间容器，不允许模型再切成两个或六个新珠子。内部可以包含清楚的先后、异质读法、同时存在的侧面；必须保住音乐的鲜活性。独立记录「内容完整版本」和「自然中文供人直接阅读的版本」，但暂时不定上屏字数。

### STEP 4 — 不预设 T/H 的价值：消融而非统统塞进去

读 `02_ABLATION_AND_MODEL_MATRIX.md` 并运行 `06_T_BEAD_ABLATION.txt` / `07_H_BEAD_ABLATION.txt`。

**T 的任务不是自动给【此刻】增加心理解释。** T 中可能有真实的本段历史意义、音乐关系或者 A 没看到的局部事实；逐条判断是否对 Bead 的当前体验有独立且前缀有效的新增。没用的 T 要留给未来 Thread，不强行塞进 Bead。

**H1–H5 要分别看，不是一个大 H 包。** H1 可提供更清楚的听觉锚点；H2 可能帮助保住跨乐段持续的体验尺度；H3 多为全曲竞争理解；H4 主要是由此前引出的期待；H5 多为回听时才成立的回顾。哪条真能提升本段当前体验，用 A-only 对照和原文证据证明；否则排除在 Bead 内容之外但保留研究资产。不能把研究分支的数量当作质量。

**每个原始来源模型都必须被检查，不得只比较最终合成写手。** 区分两个变量：① 各模型在 A/T/H 研究层贡献了什么；② 哪个模型更擅长把相同 Pool 统合成 Bead。来源模型通过增量/留一法比较；合成模型用相同固定 Pool 和相同提示词比较，不得同时换模型、输入和切法。

### STEP 5 — 受控实验与审阅

初期选择 3 个对比力强、长度不同的乐段（Op.60 优先；原历史 mm.4–16 只是待比较位置之一），做 A-only、A+T、按 H1–H5 单独检验，以及原料模型贡献审计。先复用旧 A/T/H 原文，不再生成全套研究。

对合成写手，至少以经核实、现有可调用的 GPT-5.6 为基线，并比较有证据/可用的 Gemini、Muse 或其他候选。历史上 Opus 的覆盖偏高但重复严重（run129）；如果想再测，必须控制输出长度与输入。不因为历史模型盲评胜者身份直接锁定新机制。所有模型不可用则记录原因，不得伪称完成。

先做少量可比调用、独立盲审和完整源追溯；明确改善才扩大到 Op.60 整首完整结构段落。若没有质量增益，停止，不进入下游。让用户看到**实际整颗珠子的原文及其鲜活内容**，不要只交分数或摘要。

## 三、验收必须具体而且停止在 Bead

每段产物至少包含：固定音乐区间、Affect 核心、真正不同的侧面与替代读法、必要的段内变化、只起定位作用的音乐事实、原文来源列表、完整内容版、读者自然语言版。两版都允许较丰富，不强制 30 字；读者版不能堆满分析术语和来源编号。

必须答出：① 独立结构分析是否可信；② 旧研究原文装进段落后是否被完整保留；③ A-only 珠子是否已经很好；④ T 对珠子究竟新增了什么，还是只对未来 Thread 有用；⑤ H1–H5 各自的价值和损害；⑥ 原始研究中每个模型的独有贡献与错误；⑦ 合成模型在同样输入下的质量区别；⑧ 是否有可以让用户亲自批准的珠子。

**严格停止：** 不跑 History/Thread、Center、WHY/MECH、Inner/Outer、E7、humanizer 或任何渲染模块。那些都是用户看过 Bead 并认可后才继续的事。不要替用户宣布通过验收。

## 四、交付与开发纪律

在项目的隔离实验路径下新增，不覆盖已有 run，做成作品可配置、模型可替换、缓存可验证的通用机制。调用记录含模型、提示词 sha256、输入 sha256、来源、失败和重试；没有任何调用成功的产物不得标为已运行。

交付文件：
1. `CURRENT_SOURCE_AND_MODEL_INVENTORY.md`：当前仓库有哪些 A/T/H/F 材料、每家模型对应原文在哪。
2. `STRUCTURE_EVIDENCE.md` 和 `structure.json`：通用结构提示词运行结果、来源和切点冲突。
3. `SEGMENT_POOL_AUDIT.md` / `pool_mapping.json`：所有来源材料在固定段落中的去向。
4. `BRANCH_MODEL_ABLATION.md`：逐 A/T/H 分支、逐原始模型、逐写手的增量证据和质量损失。
5. `BEAD_READER_COMPARISON.md`：每个实验位置旧版与新生成珠子的**实际文字**，匿名盲审以及失败处。
6. `BEAD_APPROVAL_CANDIDATES.md`：用户能直接阅读并勾选“可用/有问题”的完整珠子样例，不掺 Thread 文案。
7. `README_FIRST.md`：两页以内的结论、仍未证实部分、下一步（但不执行）。

任何一步若发现缺少关键原始文件，先列搜索路径与缺口；做能做的实验并标记限制，不用总结推测冒充结果。
