下面是某首器乐作品逐段的听感记录（珠子）。

你的任务不是写 Thread，也不是替珠子编人物故事。
你只负责把每一颗珠子转换成供后续匹配使用的体验性质。

对每颗珠子分别处理，不合并、不筛掉。核心方法是“分面保真”：保留同一颗珠子里彼此不同的体验性质，不把它们压成一个笼统情绪。

一、把每颗珠子拆成清楚的性质
每颗珠子输出 1–3 条 qualities。每条只说一种体验性质，使用普通、简短、可供后续匹配的描述。
在每条 quality 前加一个性质类型标记，只能从以下类型中选最贴切的一项：
- 【感受】情绪、身体感受或整体体验的温度；
- 【关系姿态】靠近、疏离、接纳、抗拒、依赖、保留等关系取向，但不把它们写成真实关系事实；
- 【注意力】沉浸、分心、回味、放空、被某种感受占据等注意力状态；
- 【期待顾虑】盼望、担心、预感、舍不得等面向未来或可能性的体验；
- 【行动倾向】想靠近、想退开、想坚持、想停下等人物自身可控的倾向，不得写成已经发生的外部动作；
- 【时间变化】仅当这条性质本身主要描述体验随时间的变化时使用。
类型标记只帮助后续匹配，不是人物台词，也不是故事内容。

二、只复制原记录明确给出的来源角色，不自行判主次
如果原珠子明确标注“主体验”“主感受”“主导听法”等，在对应 qualities 前加【原记录主体验】。
如果原珠子明确标注“另一种理解”“替代听法”“另一种听法”等，在对应 qualities 前加【原记录另一种理解】。
如果原珠子明确标注“补充侧面”或同义来源标记，在对应 qualities 前加【原记录补充侧面】。
原文没有明确标注来源角色，就不加角色标记。绝不能根据 bead_id 顺序、篇幅、强弱、自己的判断推断主体验或次要体验；这一步不是排序，也不是评判哪种听法更重要。

三、保留时间关系，不替它制造先后
temporal_shape 只描述原珠子明确包含的段内时间变化，按实际先后写清；没有明确先后就留空。
同一颗珠子中可以同时存在几种性质。并存不等于先后，不要为了写 temporal_shape 把并存性质排成过程。
如果原珠子本身给出互相替代的理解，不要把它们合成同一个时间过程。

四、去掉不能进入人物经历的内容
必须去掉：
- 音乐术语和具体声音事件；
- 画面、物件、天气、地点等比喻；
- 珠子为了说明感受而临时想象的人物动作、对白或关系情节；
- 从比喻中推断出的新人物事实。
留下的是：如果一个真实的人处在某种经历里，什么性质的处境或感受会与这颗珠子大体接近？
只描述性质，不替 Thread 决定发生了什么。

forbidden_imports 只列原珠子中明确出现、但绝不能直接搬进 Thread 的人物事实、动作或情节；不要为了显得全面而扩写新的禁入事实。珠子里的想象动作不能变成人物已经做过的事，也不能变成他人的真实反应或隐秘事实。

五、按段整理，但不压平不同珠子
每段输出 compatible_bundle，列出本段多颗珠子之间可以同时成立的体验性质。它应是若干条并列性质，不是把整段压成一句总情绪；保留不同性质类型与原记录明确的来源角色。
每段输出 tensions，指出本段珠子之间确实存在、不能强行合并的不同听法。说明涉及哪些 bead_id，以及差异在哪里；不替它们选出唯一正确解释。
compatible_bundle 不必收录每颗珠子的全部 qualities，只收录彼此确实兼容的部分；不兼容的部分留在 tensions 中。

六、信心
confidence 按原文表达是否清楚判断：高 / 中 / 低。不要把“有多种理解”误判成低信心；多种理解应在 qualities 与 tensions 中分别保留。

【输出格式】
只输出 JSON，顶层按段落编号组织：
{
  "S01": {
    "beads": [
      {
        "bead_id": "S01-B1",
        "qualities": [
          "【感受】【原记录主体验】..."
        ],
        "temporal_shape": "",
        "forbidden_imports": [],
        "confidence": "高/中/低"
      }
    ],
    "compatible_bundle": [
      "【感受】【原记录主体验】..."
    ],
    "tensions": [
      "涉及 S01-B1 与 S01-B2：两种体验性质的差异..."
    ]
  }
}

只输出 JSON（字段名照上面写的）。
