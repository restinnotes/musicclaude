## 3. 去重与 usage 处理

1. 只收录非 `<synthetic>` 的 assistant 模型消息，以供应商 `message.id` 作为实际响应单位；全来源再按相同 ID 去重。requestId/requestRef、UUID、源行号作为交叉证据，不以 assistant 序列化行或 tool_use 数当请求数。
2. 同 message.id 的 usage 在分块/复写中通常相同，选择四个主字段合计最大的完整非零版本，一次计入。发现一个同 ID 冲突：`msg_011CgKSaN5FzDaXwQ5Ti4rW9` 后续复写顶层为零，但原版和嵌套 iterations 保留非零。保留完整版本；不把零覆盖实数。
3. usage.iterations 是同请求的重复/分解视图，不在顶层之外再累加；thinking 是 output 的子集，也不再累加。工具使用合并重复块后用于分类，不将每个工具块再计同一份usage。
4. 不做去重会得到 $1381.247520，约为正确已见基线的 2.68 倍。fork 的历史副本同样按 ID 排除，原生 Agent 和真正新子会话的新响应则保留。

## 4. API 等价成本公式与官方价格

`cost = (ordinary_input × p_input + cache_read × p_read + write_5m × p_5m + write_1h × p_1h + output × p_output) / 1,000,000`。

| 模型与输入长度 | 普通输入 | 缓存读 | 5m 写 | 1h 写 | 输出 |
| --- | --- | --- | --- | --- | --- |
| Opus 5.5 | 4 | 0.20 | 5 | 8 | 20 |
| Haiku 5.5 总输入≤100000 | 0.10 | 0.01 | 0.125 | 0.20 | 0.50 |
| Haiku 5.5 总输入>100000 | 0.50 | 0.05 | 0.625 | 1.00 | 2.50 |

单位均为美元/百万 Token；总输入是普通+读+写。Haiku 跨过100k后整次请求适用高档，不只对超出部分收费。所有已见请求为 standard/global，缓存TTL均有分拆；本账本不存在需要任意补默认TTL的写入。Opus 5.5 缓存读按该模型特定价 $0.20，不能套用所有模型0.1倍输入的泛用近似。未见 Sonnet，因此不虚构 Sonnet 历史费用；如将来换模型需重新定价并做能力验证。[官方定价](https://platform.claude.com/docs/en/about-claude/pricing)、[Haiku 5.5 文档](https://platform.claude.com/docs/en/models/haiku-5-5/overview)、[缓存机制](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

价格是审计日标准API价代理；不声称准确复刻每个历史瞬间的商业价格或订阅扣额。API价即使与部分日志 cost-state 一致，也不能反推出五小时订阅权重。没有成对历史Usage面板轨迹，无法给订阅百分比/剩余时间的置信区间。[Claude Code 模型与用量说明](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)

## 5. 分类是推断，Token 是日志实测

逐请求使用真实 tool_use 名称、命令/路径、写入行为、触发根消息、回复内容分类；优先识别委托、原生Agent、Desktop独立工具、监控、写代码/修改规范、技术探测、交付、作品阅读、统计、状态处理。规则在 `scripts/CLASSIFICATION_RULES_REFERENCE.py`；参考规则读取内部 features.json，不作为可直接执行的独立入口。交付的 `CLASSIFICATION_MAP.csv` 用真实 message.id 固定本次解释，供复算使用。

6个固定关键消息人工改类，加1个主Haiku识别，共7个manual；它们不是全面人工逐条标注。高/中/低置信分别占成本18.47%/76.13%/2.81%，manual2.60%。低置信比例不是统计误差界；中置信混合艺术/工程也可能受规则优先级影响。I为环境及无法细分请求而非独立系统提示账单。根任务按最近可见 human 触发分组；跨后台阶段/跨任务并发可能归到同根，故 TASK_ATTRIBUTION 是便于审查的任务簇，不声称恢复完美项目任务图。标签为受控概括，不复制原用户长文或秘密。

严格轮询标记需类别E、短答/无实质因果或艺术判断、监控工具或简单状态命令/短后台通知；规则仍可能包含有用的监控判断，所以只作为替代候选，反事实保留一定比例。5小时quota没有逐条标记，任何类权重仅为API代理。

## 6. 请求归因与边际归因

请求归因：把一整次实际请求包括已缓存历史的费用归给触发工作；九类成本恰好加总基线。这样能描述“Claude 当时在做什么”，不能说明这些历史内容都由当前任务产生。

边际归因：对可移出的请求份额减费，再回补可能转移到下一保留请求的大前缀冷写、新交接、回执、新验收、过期与失败返工。大冷写启发式为写入>100k且读<写，共18次，写成本$74.860672；不是每次cache miss的完整定义。删除长历史带来的后续减费与压缩减费都记0，避免无证据兑现收益。反事实细节、假设范围与失效条件见 COUNTERFACTUAL。

任务数是 message响应数，toolcounts是合并后的工具块，tool_result_chars是字符，仅供负载线索；不可把字符当真实Token。Read重复路径并不表示重复内容，更不表示阅读无价值。

## 7. 压缩与附加开销的测量边界

主日志有8个唯一compact_boundary，7次manual、1次auto：10-21 00:47/21:24、10-22 14:28、10-23 15:57、10-27 02:28/16:29(auto)/20:57、10-28 15:17（UTC）。前后上下文长度变化能证明压缩事件，不能把差值当摘要服务Token费用。隐藏Haiku残差不能未经证据归为压缩或suggestions。对工具回执后响应的计数只用可见parentUuid链，可能漏链且混有其他工作，不代表工具的精确边际成本。Hook日志无额外循环证据，不为每条hook凭空增一请求。

## 8. 只读复现

Python 3.10+ 标准库，无依赖安装。运行：

```powershell
python .\scripts\READ_ONLY_REPRODUCE.py --output-dir .
eproduced
```

脚本默认从 manifest 原路径读取四个JSONL的固定字节前缀并验证hash，重新解析去重usage、独立重算模型价格、加载审计分类映射、重算九类和9个反事实情景，输出新的复算文件。原始日志没有打进交付包；若搬到别处，请提供 `--source-map paths.json`，JSON为 owner→本地原始或快照路径。分类本身不能从数值唯一推出，复算使用明确披露的固定映射；规则参考文件与证据行号允许人工改标、另做敏感性分析。

`CASE_SELECTION_RULES_REFERENCE.py` 给出历史案例的UTC窗口与关键词筛选；案例成本是这些确定请求集合的实测总和，不等于完整任务费用或可避免损失。CASE_EVIDENCE可按ID与账本联接；多个集合会重叠，禁止直接相加。

交付包只含统计、必要路径/消息ID/行号、文件hash与方法，不包含原始JSONL、凭证文件、完整工具参数、账号认证信息或GPT大段原稿。文件完整性见 FILE_HASHES.json。所有写入在独立审计目录和工作目录内。
