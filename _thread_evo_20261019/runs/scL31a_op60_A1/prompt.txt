你要为这首钢琴曲设计 Thread 的人的经历骨架。

Thread 是同一个人在整首作品里经历的一件事。这一层只负责确定这件事本身及其完整的内在发展路线，不写最终文案。

S13：第 103–110 小节
S14：第 111–116 小节
Center：亲密的幸福与留不住它的痛楚难以分开

请独立提出 3 条完整候选路线。

【本层边界】
1. 完全不看任何听感记录或珠子。
2. 不写音乐、声音、旋律、节奏、和声、小节里的事件。
3. Center 已经给定，不得修改。它是读者回头看整首时把各段组织起来的那件事，不是人物一开始就清楚知道的事，也不是每一段都要回应的题目。
4. 可以利用对这首钢琴曲整体走向的理解安排各阶段的轻重，但输出里只写人的经历。
5. 从头到尾必须是同一个人经历同一件事。
6. 不得新增聚会、书信、物件、对白、地点、职业、第三人、对方的新动作或其他外部事件来推动故事。允许一个从头到尾不变的轻处境和小动作。不得凭空推断其他人的隐秘心事。

【核心要求：建立真正向前发展的经历】

一条路线不能只是让人物在几种情绪之间反复摆动，而必须形成有先后关系的内在发展。

每个段落都必须为这件事增加一个真正不同的内容。允许的推进贡献包括：

1. 新认识：人物第一次知道某件事，或者对已经知道的事实形成了实质不同的理解。新的措辞、新的角度或更强烈的情绪不算新认识。
2. 新所求：人物开始想要一件此前没有明确想要的东西，或者原有愿望的对象、优先级发生实质变化。原有愿望变得更强不算。
3. 新代价：人物第一次真正认识到某个愿望、选择或处境需要付出的具体代价。原有担忧变得更强不算。
4. 新选择：人物形成一个此前没有成立过的选择，或者在已有选择上发生有根据的实质调整。重复宣布同一个选择不算。
5. 实行已有选择或承受其新后果：此前已经形成的选择在后续真正产生了新的影响、限制、得失或心理后果。仅仅再次说自己仍然坚持，不算。

每段指定一个主要推进贡献。可以同时出现其他状态，但不得用多个近义句替代一个推进贡献。

【推进的硬规则】

1. 为整条路线建立明确的起点、核心矛盾和终点状态。终点可以仍有问题没有解决，但人物对这件事必须已经有了与起点不同的认识、所求、代价或选择。
2. 在写各段之前，先确定每一段的独立叙事功能。相邻段落不能只是同一个问题的不同情绪版本。
3. 每个段落都必须有一个独立、可辨认的推进贡献。该贡献必须与之前所有段落在语义上不同。
4. 同一个问题可以始终存在，但不能在每一段重新提出。问题可以作为背景继续存在；只有当人物获得新的事实、认识到新的代价、改变了所求或形成了不同选择时，才允许重新面对它。
5. 如果后来回到类似的心理处境，必须明确写出这次多出来的认识、所求、代价、选择或后果。不能仅仅更换提问方式、情绪词或比喻。
6. 一个认识、愿望或选择一旦明确成立，后文必须把它作为已知事实。后文可以承受它的后果、执行它、发现它的局限，或者在有新依据时调整它；不能重新把它写成第一次发现。
7. 不要默认采用试一个办法、不管用、换一个办法的循环，也不要默认采用希望、害怕、安心、再次害怕的循环。
8. 情绪更强、感受更复杂、想得更多、反问得更深，都不自动算作故事推进。
9. 允许人物不总结、不解决问题，也允许某段主要呈现已经形成的情绪。但这种延续或沉浸不能成为空白的叙事贡献；该段仍必须呈现一个不同于前文的新后果、新代价、新所求或新选择的实际影响。
10. 不要求每段都有新的重大领悟，但要求每段都给这件事增加不可替代的内容。
11. 不要让人物不停分析自己。优先写当时实际在意什么、想要什么、丢掉了什么、承担了什么、已经知道什么。
12. 不得为了填满段落制造心理动作，也不得为了让结尾有终点而制造决心、原则或人生结论。

【路线容量检查】

在完成一条路线后，逐段检查：如果去掉这一段，是否会失去一个独立的新认识、新所求、新代价、新选择或后果？

如果某段只是重复其他段落的两难、情绪或选择，必须重新设计该路线。

如果在不新增外部事件、不违背前因后果的情况下，仍无法为所有段落找到独立的新贡献，则将该路线标记为 `insufficient_arc_capacity`，列明无法成立的段落。不得通过换词、加强情绪、增加反问或重复选择来伪造推进。

宁可判定一条路线无法支撑现有段落数量，也不要交付一条看似完整、实际打转的路线。

【事实与问题账本】

每条路线都必须保存两份账本：

1. established：已经成立的事实、认识、愿望、代价和选择，按首次成立顺序登记。后文不得重新完成同一个变化。
2. question_ledger：人物面对的核心问题及其首次出现的位置。后文如果再次面对同一个问题，必须明确说明出现了什么新的前提、代价或选择；没有新内容，就只能作为背景，不得作为新转折。

【输出格式】

只输出 JSON。每条候选包含：

- route_id
- route_status：`viable` 或 `insufficient_arc_capacity` 或 `causal_break`
- situation：一句普通话，说清这个人正在经历的是哪一件事，不写抽象论文标题。
- opening_condition：故事开始时人物实际处于什么情况，已经知道什么、想要什么、尚不知道什么。
- central_question：这件事真正悬而未决的问题。只写一次，不要将它变成每段重复回答的题目。
- ending_condition：故事结束时人物与起点相比发生了什么变化；可以没有解决问题。
- segments：严格按照 S01：第 1–3 小节
S02：第 4–16 小节
S03：第 17–23 小节
S04：第 24–34 小节
S05：第 35–39 小节

S08：第 62–71 小节
S09：第 72–77 小节
S10：第 78–83 小节
S11：第 84–92 小节
S12：第 93–102 小节
S13：第 103–110 小节
S14：第 111–116 小节 的顺序，每段包含：
  - sec
  - narrative_function：本段独有的叙事功能。
  - state：本段此刻实际是什么情况，1–3 条。
  - payload_type：从 `新认识 / 新所求 / 新代价 / 新选择 / 实行已有选择 / 已有选择的新后果` 中选择。
  - delta_type：从 `新变化 / 后果 / 实行已有想法 / 回到旧处但有新增` 中选择。
  - delta：本段相对以前真正新增的内容，必须具体且不能与其他段落同义。
  - question_id：本段实际面对的问题编号；没有则留空。
  - depends_on：真正作为前因的更早 state 编号；没有则留空。
  - carry_forward：本段必须承接的、此前已经成立的事实或选择。
  - still_open：到这一段仍未解决或仍不知道的东西。不得把同一个问题伪装成新的问题。
- established：按首次成立顺序列出，包含 id、kind、claim、first_established。
- question_ledger：列出各个问题的 id、首次出现段落、后续是否再次出现，以及再次出现时新增的依据。
- repetition_audit：列出语义相同或近似的认识、愿望、代价、问题和选择，检查它们是否被重复当作新变化。
- capacity_audit：列出段落总数、独立推进贡献数、缺少独立贡献的段落，以及路线是否具备支撑全部段落的能力。

不得写最终文案，不得评价其他候选，不得编造外部情节。
