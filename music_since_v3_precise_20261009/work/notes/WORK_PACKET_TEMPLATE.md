# Muse 工作包模板：少占 Claude 上下文、执行可以充分放大

每个 `delegate_task` 子智能体任务可从下面模板复制裁剪。任务可以大，也可以并行很多；**不是要求每次只有一个小任务**。特别要明确写入边界、独立运行环境和成果落盘位置。

## 交给 Muse 的任务消息模板

```text
你是 Muse 执行代理，负责独立完成以下工作，不代表 Claude 做最终审美/生产裁决。

目标 / 本轮唯一需要交付的结果：<一句话>
已冻结输入与上游前提：<git commit、文件路径、运行 ID、prompt 版本与 hash；不用整段聊天历史>
可读取：<路径或目录>
允许修改：<文件/分支/独占目录>
禁止修改：<production prompt、原始历史 runs、产品宪法、他人并行写入文件，或按需明确>
步骤与验证：<具体检查、命令、比较条件、回归命令>
独立性：<不得看到的其他候选或评审结论；若本任务非盲审写“不适用”>
如何处理失败：<重试次数是否开放、错误处理与停止条件。费用由主 Claude 按真实模型权限掌握>

必须将原始输出、数据、测试日志、diff、错误、哈希、模型及路由元数据保存至：<runs/或notes/的专属路径>
先自己诊断和修复可处理的机械问题；确实失败要给出可复现实验与错误出处，不准隐藏。
回复 Claude 主会话：最多 8 行中文，提供（1）完成/未完成（2）关键改变及测试（3）最重要正/反证（4）证据路径（5）值得主 Claude 决策的一个问题。请勿粘贴完整文本或大量日志。
```

## 典型的并行工作包

- `muse-router`: 只负责 `gpt2 --help`/网页模型适配/缓存/回归测试，写自己隔离的代码分支。
- `muse-baselines`: 定位 V2A+Gemini 02/05 和旧 production 的真正原文、时间范围、来源，建立可对照索引（只读）。
- `muse-eval`: 准备冻结样本及匿名盲评工具，绝不更改候选内容。
- `muse-errors`: 独立从旧 run 找 E5/R6/Thread 假增量与有意义增量的案例，包含反例、真实原文路径。
- `muse-challenger`: 独立寻找反对“GPT-6 一定更好”“四层必需”“NONE 越多越好”等假设的证据。
- `muse-surface`: 依冻结语义输出做 E7 **诊断样稿**，不触碰生产默认值。
- `muse-ops`: 整理 run manifest、hash、差异摘要、每轮 Downloads ZIP、跨会话状态。

## 独立 review 重要约束

每一轮要开一个**新** `delegate_task`、给新的 `clientRequestId`，按 `notes/CLAUDE_MUSE_ORCHESTRATION.md` 的 target 调度。禁止在旧的 `childThreadId` 上续聊 review；如需上次证据，传文件路径而非长消息。

## 给 Claude 的决策包格式

```text
要决定什么：A 或 B，或二者都不采用？
冻结条件：inputs + prompt/model/架构变化点
可核查结果：<≤5 个实际数字 + 出处>
强样例：<1–2 对短引文 + 原始路径>
反证/不确定点：<1–2 对 + 原始路径>
已有评审：<匿名、评审来自什么模型、分歧何在>
后续决策选项：<维持/扩大/回退/另找假设>
```

Claude 只有在这个 packet 仍无法判断时才打开更多原文；不要让免费的 Muse 把几十页中间资料原样回传主会话。
