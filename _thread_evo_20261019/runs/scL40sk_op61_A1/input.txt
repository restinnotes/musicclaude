你要为一首器乐作品设计 Thread 的“人的经历骨架”。

Thread 是同一个人在整首作品里经历的一件事。这一层只负责把这件事本身想清楚，不写最终文案。

【输入】
作品：作曲家：肖邦（Chopin）

段落顺序：S01：第 1–23 小节
S02：第 24–65 小节
S03：第 66–91 小节
S04：第 92–115 小节
S05：第 116–147 小节
S06：第 148–180 小节
S07：第 181–205 小节

S09：第 214–215 小节
S10：第 216–225 小节
S11：第 226–241 小节
S12：第 242–253 小节
S13：第 254–288 小节
Center：维持尊严的行动与对旧日生活及归属的怀念反复拉扯

【基本约束】
- 你看不到原始的听感记录（珠子），也不得猜测它们的画面、比喻或措辞。你只拿到每一段的“体验性质”（TARGETS，附在最后）：听这一段时大致是哪种性质的感受、怎样变化。它不是事实，不是情节，也不是要写进去的话；其中 forbidden_imports 列的东西一律不得写成人物的经历。
- 不写音乐、声音、旋律、节奏、和声或小节里的事件。
- Center 已经给定，不得修改。它是读者回头看整首时把各段组织起来的那件事，不是人物每段都要重新思考的问题。
- 不新增外部事件、人物、对白、物件、地点、场景或前史。
- 可以利用你对这首钢琴曲整体走向的理解安排经历轻重，但输出只写人的经历。

请独立提出 3 条完整候选路线。

【本次最重要的任务：找到经历铰链】

每条路线都必须先判断：这件事中有没有一个已经被现有处境支持的真实变化，可以把经历分成变化之前和变化之后。

这个变化可以是一个已经作出的选择、一个已经成立的事实、一个已经发生的认识变化，或一个原先只存在于心里的东西现在已经成为现实。它必须来自路线本身和 Center，不得为了制造故事而新增事件。

先在内部建立一条单向事实链：
1. 铰链之前，人物已经知道什么、在意什么、期待什么、害怕什么。
2. 铰链究竟改变了什么，第一次在哪一段成立。
3. 铰链之后，人物实际承受了什么后果，原先的事实怎样影响他的行为、感受和日常处境。
4. 到结尾，哪些事情仍然没有答案，哪些事情已经不能再当成未知。

如果没有自然的经历铰链，不要制造一个。允许整件事是一段持续经历，但必须如实说明路线如何在已有事实中展开。

【每一段都要回答：为什么此刻是这种滋味】

各段的体验性质彼此不同，即使情绪相近，质地、轻重、方向也不一样。骨架的任务就是给这些不同找到人的理由：

- 逐段读 TARGETS，先看清这一段的滋味和上一段、和前面相似的段相比，多了什么、少了什么、变了什么。
- 然后回答：这个人此前经历过、明白过、做过什么，才让他此刻是这种滋味，而不是上一段那种。理由只能来自他自己在前面段落已经成立的经历和这件事本身，不得新增外部事件、人物、对白、物件、场景或前史。
- 理由要具体到只属于这一段：把这一段的 state 原样挪到别的段，应该明显不合适。一句放在哪一段都说得通的话（重申他珍惜什么、担心什么、决定什么）不算回答。
- 不要复述体验性质的词，不要把它翻译成人物“感到……”。写的是处境和缘由：他此刻面对什么、手里已经有什么、哪件已经成立的事在这时显出了它的分量。
- 同一段的体验性质有好几个侧面时，尽量让处境同时说明其中最主要的几个；说明不了的，如实列在 unexplained 里，不要硬凑。
- Center 仍是把各段组织起来的那件事，各段的理由合起来必须是同一个人的同一件事，前后因果连得上。

【规则】
1. 一项事实、认识、愿望或选择只允许第一次成立一次。后面不能换一种说法重新宣布它。
2. 一个问题可以长期没有答案，但不能在每一段重新成为第一次提出的问题。
3. 铰链成立之后，不能假装人物还没有经历过它。后面的犹豫必须发生在已经知道、已经选择或已经承受的基础上。
4. 后面回到类似的感受时，必须区分：是旧事实带来的新后果、人物应对方式的变化，还是单纯的感受延续。不能把情绪增强包装成新的认识。
5. 不要求每段都有新的认识、决定或问题。允许延续、沉浸、后果、注意力转移和暂时不想这件事。
6. 不要用不同说法把同一个两难拆成多个问题。
7. 不要让人物不停总结自己。优先写当时具体在意什么、想做什么、害怕什么、已经承受什么。
8. 不要为了让后半段显得更深而重新解释前半段的事实。
9. 结尾不必解决问题，也不必制造新的决定。

每条候选路线包含：
- route_id
- situation：一句普通话，说清这个人正在经历哪一件事。
- segments：严格按照 S01：第 1–23 小节

S13：第 254–288 小节 顺序。
  - sec
  - state：本段此刻实际是什么情况，1–3 条。
  - delta_type：从“新变化 / 后果 / 实行已有想法 / 延续 / 回到旧处但有新增 / 暂时没在想”中选择。
  - delta：本段相对以前真正新增的内容；没有就写空。
  - depends_on：真正作为前因的更早 state 编号；没有就空。
  - flavor_diff：这一段的滋味和前面相比有什么不同（一句，用你自己的话，不抄 TARGETS）。
  - why_now：他为什么此刻是这种滋味（一句，只用前面已经成立的经历）。
  - unexplained：这一段里处境说明不了的体验侧面；没有就空。
  - still_open：本段仍然没有解决的问题；同一个问题如果没有发生实际变化，不要每段重新写一遍，没新增就留空。
- established：按首次成立顺序列出全文的重要事实、认识、愿望或选择，并标明第一次成立在哪一段。

输出必须是完整 JSON。字段名照上面写。不要写最终文案，不要评价候选。
