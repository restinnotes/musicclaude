# 珠子 × 线：对接问题讨论包（2026-10-22）

这个包是给你（另一位 agent）用的，用来和用户一起讨论一个还没解决的问题：**珠子和线怎样合在一起，才有整体性。**请先读完本文，再看各个文件夹。

## 一、项目是什么

我们在为肖邦的两首作品做随音乐播放的讲解视频：《船歌》Op.60 和《幻想波兰舞曲》Op.61。时长就是音乐本身的时长。观众可以来回看；如果需要，也可以分成基础版和详细版两个视频。

内容由两条链组成：

- **珠子（Affect）**：每一刻听到什么、像什么、身体和心里是什么感觉，都带小节号。珠子来自 24 份独立来源稿（4 个模型 × 查资料/不查资料 × 3 次），经过提炼和合并。Op.60 有 51 颗，Op.61 有 55 颗。每颗珠子有一个角色：主体验 / 段内变化 / 另一侧面 / 另一种理解。珠子之间也标了关系。
- **线（Thread）**：一个人在这首曲子里经历的一件事。每一段都说明他此刻为什么会这样，理由来自他前面真实经历过的东西，而不是“音乐忽然怎样了”。线有一个贯穿全曲的 Center（一句关系句），每段还标出他和这件事的关系：还说不清 / 正在面对 / 没在想。

产品宪法里的比喻：珠子一颗颗各自成立，线把它们串起来，让听者知道每颗珠子为什么出现在此刻。

## 三、要讨论的问题（用户的原话和意思）

用户认为对接最重要的评审标准之一是**整体性**。现在珠子和线是割裂的，读者得在两边之间反复横跳，阅读负担很大，也感受不到整体。

用户已经明确的几点：

1. **线不能被扭曲。**线就是“我们认为最有解释力的那个故事”，不能为了配珠子去改它的逻辑。
2. **不能拿珠子当底稿去写线。**以前试过（DAG.md 里的 E2/E3、fuse.py），结果“沦为纯粹拿连接词串起来珠子”，没有自己的逻辑。
3. **线没写具体小节，就不该被安排到某几个小节上。**呈现时给线单独留一块区域就行，这不是重点。
4. **只把两条并列摆出来不算“串”**，那样就成了两块各自独立的内容。

所以核心问题是：**在线不扭曲、珠子不改写的前提下，怎样让观众感受到这是一件事？**现在的线到底能不能把珠子串起来？我们的思路本身有没有问题？

### 我（上一位 agent）对割裂原因的观察，供参考，不是结论

- **两种说话方式**：线是“他……”，讲心理机制；珠子讲声音、画面、身体，人称在“你”、无人称、“像一个人”之间变。读者要不停换频道。
- **数量不匹配**：一段里线有 5–6 条，珠子有 10–15 句。
- **既重复又不一致**：
  - 重复的例子：线说“不必时时确认对方有没有接住”，珠子说“话到了嘴边，又轻轻咽回去”。
  - 不一致的例子：Op.60 1–3 段，线写“柔软起来”，主体验珠子写“开头那两下响亮的和弦，有一点突然”。
- **珠子本来就是多声部的**：它们来自多份来源，有几种听法，天然不像同一件事。
- **一个结构性矛盾**：宪法 A3 说“线从珠子的真实内容中生长”；10-21 定下的 A 路线则规定写线时完全不看珠子，以免线去复述珠子。结果是线能不能接住珠子，要看运气。

### 上一位 agent 想到的三条路，都还没有做实验

- **甲：只在真正交汇的地方并置。**每一刻只放一句线和一两句真正属于同一刻的珠子，其余珠子放进“也可以听成”或详细版。这和“不按线的理解筛珠子”的规则冲突（见“用户决定记录/assembly-keep-bead-multiplicity.md”）。
- **乙：线的逻辑不变，换一种说法。**线是我们自己的文字，可以改措辞，不改因果。可以借用 P0 里的 Outer（一个从头到尾不变的轻处境，比如船上、身边那个在意的人），让线和珠子站在同一个场景里。风险是变成编情节。
- **丙：把珠子压成一两行。**旧组装里“珠子压成要点”那版明显更连贯，但要改写珠子。用户对“珠子能不能改写”还没有决定。

## 六、其他约束（来自用户）

- 不编外加情节；不改写珠子去修正音乐事实小错；语气戏剧化、笃定不算缺点。
- 阅读量不能成为删内容的理由：靠排布和分版本解决，不能牺牲内容质量和音乐哲学。
- 给用户看的样本要标明来源，不匿名。
- 和用户交流用中文，说人话，先把问题答清楚，不要只抛问题。
