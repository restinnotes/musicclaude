补做结果先给结论：**目前我没有找到任何一家具备公开可核验能力，能在“中国商品尚未采购/尚未入仓”时，仅凭商品 URL/确定 SKU + 美国地址，就返回包含商品价、国内运费、仓储/操作费、包装后的计费重、国际运费、关税/清关费、末端费在内且具有约束力的 all-in quote。** BuckyDrop 最接近可系统集成；Superbuy、Sugargoo 的公开标准流程仍明显是“先买到中国仓，再形成更可靠的国际运费”。这不等于能力不存在，而是**本轮没有公开证据证明已可用**。

同时，国内平台 API 并非完全封闭：淘宝全球开放平台、海外淘宝客、1688 跨境方案、京东联盟都存在正式官方接入路径。但它们是**供销/导购/联盟/商家生态中的授权数据能力**，不是“任意美国 comparison engine 可匿名拿中国全货架实时价”的通用数据许可证。Amazon 的约束反而更明确：当前 Creators API/Associates 条款与一个“中立、必要时推荐非 Amazon 路线”的产品存在实质冲突，尤其是 browser extension、价格提醒、聚合分析和用 Amazon 内容推广其他零售渠道。

旧 54 SKU 样本我不作任何重新解释：**CN transaction verified=0/54、完整 landed=0/54 仍然只表示未测出，不是 54 个反例。** 本次是基础设施独立探索，没有加入 SKU 分母。

# 三、Taobao / Tmall：真正有用的是两条不同轨道

## A. Taobao Global Open Platform：采购/供销轨道

**Observation.** 官方开发手册更新时间为 **2023-09-11**，目前仍在线，访问 2026-10-06。它明确要求申请“全球供销平台”应用类型、审核 API 权限；卖家业务数据按具体接口还可能需要 seller OAuth。网关为 `https://api.taobao.global/rest`。 [Alibaba Developer](https://developer.alibaba.com/docs/doc.htm?articleId=120906\&docType=1\&treeId=735)  
[Taobao Global Open Platform manual](https://developer.alibaba.com/docs/doc.htm?articleId=120906&docType=1&treeId=735&utm_source=chatgpt.com)

已能从官方手册核验的相关 API 包括：

| 能力 | 官方证明 | 对本项目的支持范围 | 剩余缺口 |
|---|---|---|---|
| 按淘宝 item ID 取商品 | `/product/get` | SKU/价格/库存/邮费等结构化采购数据 | 非跨境供货商品可能被裁剪素材 |
| 批量撞库 | `/batch/src/products/check` | 从已知 item ID 建 identity graph | 不是全网 consumer search |
| 同款/相似 | `/product/similar/get`、`/product/recommend` | 图片/商品关联、低价候选 | 文档不同章节对商品池范围描述不完全一致，需真账号测试 |
| 下单预检查 | `/purchase/order/render` | 可返回库存/下架、优惠、应付价 | 文档标注过“灰度中”；当前生产权限需重新确认 |
| 创建订单 | `/purchase/order/create` | 可做代购/导购业务流 | 需要获准应用/商品身份 |
| 订单/退款 | 有正式订单及退款接口 | 可构成采购 lifecycle | 国际售后/美国退货不是这些接口本身解决的 |

API 请求示例甚至直接展示 `/product/get`、价格、`promotion_price`、SKU 数量和 `postFee` 等字段。 [Alibaba Developer](https://developer.alibaba.com/docs/doc.htm?articleId=120906\&docType=1\&treeId=735)

一个很关键的限制：Taobao Global 文档历史升级说明称 `/product/get` 曾扩展到淘宝/天猫全量商品，但**非跨境供货商品可能返回 `WITHOUT_MATERIAL`，不提供图片、描述及部分素材字段**。所以“可采购某 item ID”不等于“被授权拿完整全站商品内容做美国 comparison catalog”。

另一个关键点是 `/purchase/order/create` 的地址数据包含 distributor 的**中国境内收货仓地址**。因此这套采购 API 本身不提供“中国 SKU → 美国消费者 landed quote”；国际运输层仍需要 BuckyDrop/Superbuy/其他 forwarder 衔接。

- `site` 官方枚举包括 TW/HK/MY/SG/AU/CA/MO/GLOBAL，我没有看到专门 `US` 枚举，因此**不能写成“已证明美国站支持”**；
- 搜不到联盟商品时还可请求“similar recommendation”，这不能被当成“同款已验证”。访问：2026-10-06。 [Alibaba Developer](https://developer.alibaba.com/docs/api.htm?apiId=72807)

**不证明：**

# 六、Amazon：当前接口本身不是最大问题，许可证才是

这是本轮最需要改变产品路线的部分。

### 1. PA-API 5 已经 deprecated

Amazon 当前官方文档明确说 Product Advertising API 5.0 已 deprecated，Creators API 是 successor；继续调用 PA-API 5 可返回 403 `AccessDeniedException`。访问 2026-10-06。 [Amazon Associates](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/paapiv5-deprecation)  
[Amazon PA-API 5 Deprecation Notice](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/paapiv5-deprecation?utm_source=chatgpt.com)

Creators API 当前 endpoint 形态为：

`https://creatorsapi.amazon/catalog/v1/*`

并采用 OAuth 2.0。 [Amazon Associates](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/migrating-to-creatorsapi-from-paapi)  
[Amazon Creators API migration guide](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/migrating-to-creatorsapi-from-paapi?utm_source=chatgpt.com)

当前 onboarding 文档还要求目标 marketplace 的 Associates 身份，并写有过去 30 天至少 10 个 qualifying sales 才能访问相应 API。 [Amazon Associates](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/introduction)  
[Creators API Introduction](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/introduction?utm_source=chatgpt.com)

### 2. Comparison 本身不是绝对禁止，但条件非常苛刻

Amazon Program Policies 当前标注 **Updated: April 14, 2026**。它明确承认 comparison format：若把 Amazon 商品价格与非 Amazon 渠道同款/相似商品价格一起展示，必须显示 Amazon 的 lowest new price，并在 Amazon 提供时显示 lowest used price。 [Amazon Associates](https://affiliate-program.amazon.com/help/operating/policies)  
[Amazon Associates Program Policies](https://affiliate-program.amazon.com/help/operating/policies?utm_source=chatgpt.com)

但新的 `OffersV2` 又明确说：

- 只提供 retail detail page 的 **featured listings**；
- 旧 `Offers.Summaries` 被取消；
- `HighestPrice`、`LowestPrice`、`OfferCount` 均标为 **Not Available**；
- shipping charges、Prime eligibility 等若干旧字段也不再提供。 [Amazon Associates](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/api-reference/resources/offersV2)  
[Amazon Creators API OffersV2](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/api-reference/resources/offersV2?utm_source=chatgpt.com)

所以有一个需要 Amazon 澄清的实际接口/条款缺口：**政策要求 comparison 中展示 lowest new，但当前公开 OffersV2 已没有旧的 LowestPrice summary。** 我不会推断出一个并不存在的替代 endpoint。

### 3. 更致命的是 usage restrictions

当前 Amazon 条款还明确规定：

- Creators/PA Program Content 的应用**主要目的必须是 advertising/marketing Amazon 并驱动 Amazon 销售**；
- Product Advertising Content 的每次使用原则上只能链接到 Amazon；
- 未经 Amazon **express prior written approval**，不得为 aggregating / analyzing / extracting / repurposing Product Advertising Content 使用 Creators API；
- 不得用 Amazon Program Content 去 advertise/promote 非 Amazon 站点的产品；
- 网站默认不能有 price tracking / price alerting，除非 Amazon 另行同意。 [Amazon Associates](https://affiliate-program.amazon.com/help/operating/policies)

更直接的是 browser extension：条款明确禁止把 Program Content / Special Links 用在 browser plug-in、helper、toolbar、extension 等 client-side software 中，Approved Mobile Application 是另一个例外类别。 [Amazon Associates](https://affiliate-program.amazon.com/help/operating/policies)

缓存也很严格：图片本身不得 cache，image link 最多 24h；其他 Product Advertising Content 最多 24h，之后必须刷新；若价格/库存刷新不足每小时一次，还要显示 timestamp 和指定免责声明。 [Amazon Associates](https://affiliate-program.amazon.com/help/operating/policies)

### Inference I4

**用标准 Amazon Associates/Creators 许可证直接实现“Google Flights for all retailers”风险很高，尤其不能把当前 memo 里的 browser extension 当成默认首发载体。**

这不是说“Amazon comparison 永远不能做”，而是说标准许可更像 **Amazon affiliate publisher license**，不是中立 retail-pricing data license。真正可走的路径是：

1. 向 Amazon 取得明确的书面特殊许可；或
2. Amazon 一栏改用另一家有权授权跨零售比较的独立数据提供商；或
3. v0 让用户自行提供 Amazon URL/价格，只把不受 Amazon Program Content 许可证约束的最小识别信息用于 match——这里仍需单独做法律/ToS 设计。

# 八、美国 landed cost 已不能继续用“<$800 基本零关税”的旧假设

这一点会直接影响最小架构。

2026-02-20 白宫行政命令继续暂停所有国家的 duty-free de minimis treatment；此前的全局暂停已使美国低价值进口不能简单按旧 `$800 = duty free` 模型处理。对非邮政件，适用的 duties/taxes/fees 仍需按商品、原产地、入境方式等计算。 [The White House](https://www.whitehouse.gov/presidential-actions/2026/02/continuing-the-suspension-of-duty-free-de-minimis-treatment-for-all-countries/?trk=article-ssr-frontend-pulse_little-text-block)  
[White House — Continuing the Suspension of Duty-Free De Minimis Treatment for All Countries](https://www.whitehouse.gov/presidential-actions/2026/02/continuing-the-suspension-of-duty-free-de-minimis-treatment-for-all-countries/?utm_source=chatgpt.com)

因此真正的 `landed()` 至少要知道：

`SKU identity + country of origin + HTS/classification + customs value + entry mode + carrier/line + DDP/DAP + broker/clearance rule + actual/volumetric parcel weight`

**Inference I5：** 在 2026 年监管环境下，“采购前 all-in quote”的难度已经不只是体积重，而是**体积重 + 线路资格 + HS/关税 + importer/DDP 角色**共同决定。只做 freight calculator 不够。

# 九、不自营进口情况下，我认为可行的最小架构

可以做到**不持库存、不先买货、不建美国仓、不自己成为传统零售 importer**，但第一版最好是 **web app，而不是 Amazon browser extension**。

建议的数据流是：

`用户提交美国商品 URL / 搜索意图`
→ `Identity service`
→ `US channel quote adapters`
→ `China catalog adapters`
→ `Agent procurement quote`
→ `Pre-landed estimator`
→ `risk/confidence gate`
→ `只有 savings 足够大才展示 China route`
→ `handoff 到 agent/其 checkout`
→ `agent 采购/入仓/发货`

其中几个模块必须严格分开：

**Identity graph** 只输出 `EXACT / VERSION-CONFLICT / SUBSTITUTE`，相似品永远不能自动升级成“同款”。像中国 ROM、频段、电压、插头、容量、套装、保修区域、大陆版/国际版都进入 identity key。

**China discovery** 第一阶段可以用海外淘宝客作为合法候选池，用 Taobao Global/BuckyDrop 作为采购验证层；1688 用于 supply discovery，但默认标 substitute/source，而不是 exact retail equivalent。

**Quote engine** 初期不要输出一个假装精确的单数字。应该输出类似：

`Estimated landed: $18.40–$21.20`
`confidence: medium`
`freight locked: no`
`duty locked: no`
`packed dimensions verified: no`
`quote timestamp: …`

只有供应商给到真正有约束力的 API 后，才升级为：

`Guaranteed landed through YYYY-MM-DD HH:MM`

**Checkout/进口角色** 则交给有合同的 buying agent / logistics partner。你的软件可以收 routing/service fee 或 referral，而不碰 title to goods；但谁是 Importer of Record、谁承担 duties、拒收/退运和消费者退款义务，必须在供应商合同和美国法律审阅中明确，不能仅凭“我们只是软件”推定免责。

# 十、真正的阻塞，按优先级排序

**1. 最大阻塞：采购前 binding landed quote。**  
不是“有没有运费计算器”。三家都有。真正缺的是：

`exact SKU + US ZIP → product + domestic + service + packed billable weight + eligible line + duty/clearance + last mile → binding total / validity / variance cap`

目前公开证据是 **0 家证明完成这个闭环**。

**2. 中国 catalog 的“合法、稳定、可在美国 comparison UI 中展示”的权利。**  
API 技术上比预想乐观，但授权语境都是联盟、供销、商家、跨境分销；这和“中立美国购物比较器”不是同一个许可问题。

**3. Amazon 数据权利。**  
标准 Creators/Associates 许可与产品最核心的 neutral routing logic 存在结构性冲突；如果不先解决，extension + cross-retailer comparison + price alerts 三件事会同时撞条款。

**4. 入仓前 packaging prediction。**  
轻小件差别可能小，大盒子、鞋盒、玩具、家电、显示器、机器人、帐篷等可能被 volume weight 彻底改变 economics。目前没有看到三家公开承诺“按 SKU 历史数据在采购前给保证尺寸”。

**5. 美国 duty/IOR/DDP。**  
de minimis 已不能当兜底。必须把 customs computation 变成正式 quote dependency。

**6. Returns。**  
“中国商家退款”“中国仓拒收/退货”“已出口后的美国消费者退货”是三个不同流程。目前公开标准 agent 页面不足以证明后两者可以低摩擦 API 化。

换句话说，**matching AI 反而不是当前最硬的 blocker；quote truth 和 data/license truth 才是。**

# 十一、建议下一步的判定标准

我会把 Phase 0 的 infra gate 改成一句非常硬的测试：

> 给供应商 20 个确定规格 SKU + 20 个美国 ZIP，要求在**不先购买商品**的情况下，通过 API 返回可审计的 landed-cost breakdown；随后实际跑少量允许的测试订单，比较 quoted vs invoiced。

成功门槛可以预先规定，例如“90% 包裹最终总履约费用落在 pre-buy quote 的 +10% / -5% 内”，但这个数目前只是**产品假设**，不是供应商现有 SLA。

如果三家都只能给 ±30–50% estimate，那么 v0 可以做“price anomaly discovery”，却还不能诚信地做 memo 里 `$16.80 all-in · 9–13天` 那种确定性 UI。

## 最终判断

这个创业假设目前**没有被基础设施层证伪**，但基础设施并没有像 memo 中一句“利用现成 Superbuy/Sugargoo/BuckyDrop”那么即插即用。

最值得继续验证的组合是：

**BuckyDrop API/商务合作 + Taobao Global/海外淘宝客合法商品源 + 独立 customs/landed engine + Web app。**

而不是：

**直接抓淘宝/JD + Amazon Creators API + browser extension + 把运费 calculator 数字写成 all-in。**

后一个组合同时踩中了四个尚未解决的问题：Amazon 许可、国内数据授权、入仓前体积重、美国关税。

如果只选一个接下来最能杀死或强化 thesis 的实验，我会选 **20 SKU × 20 ZIP 的 pre-buy quote → actual invoice reconciliation**。只要供应商连结构化 pre-buy quote 都给不了，产品第一阶段就应该明确叫 **“estimated China route”**，而不是“真实到手价”；如果 BuckyDrop 或定制合作能把最终偏差压到可控范围，才真正出现可以产品化的 routing primitive。
