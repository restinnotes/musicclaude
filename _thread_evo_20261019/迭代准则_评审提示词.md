## 四维开放评审 e2e_open（找问题）

```text
下面是一首音乐作品的“成品”的两部分，请你作为第一次读到它的普通中文读者，找出它没做好的地方。

【它是什么】
- “线”：一个人在这首曲子里经历的一件事，按音乐的段落写成几条要点。〔〕表示这句话接着前面哪一段的哪一条。每段标题后的括号是这一段他和整件事的关系：“没在想”是他这时没去想那件事，“还说不清”是他隐约感到却说不清，“正在面对”是他在直面它。
- “珠子”：逐段的音乐听感记录，写这一段听起来像什么、让人想到什么。成品里线和珠子放在一起读：线讲他自己的经历，用来把珠子串起来。

【它想做到的四件事】
1. 线单独读也成立：只读线、不看珠子，它自己就是一件有逻辑、有时序、内在有发展的事；看得出他此刻为什么这样，但不靠“因为……所以……”生硬地交代；推动它的是他自己前面的经历，不是音乐事件或新编的事；像一步步往前探索，不像在迷宫里来回。
2. 不啰嗦、连着读顺：连着读下来每一句都能自然接上前一句；每一句都有它自己的用处。删掉也不丢东西的话、把前面已经说过的再说一遍的话，都是啰嗦。这一段真正发生得少，就该写得短。
3. 像人话：读起来像一个人平平常常地讲自己的经历，不像心理分析或提纲。
4. 接得上珠子：每颗珠子的听感，都能在线里找到和它情境相近的原因或处境（只要相关即可，不需要逐颗解释）；但线讲的是他自己的经历，不是把珠子里的画面、比喻、情节翻译成心理。

戏剧化、主观、只讲一个故事都不算缺点。允许含蓄，不要求补造具体人物、事件或场景。你不知道作者修改过什么，不要预先假定它有哪些毛病；某件事做得好就不用提，不要为了凑数挑毛病。

【怎么读】
第一遍：先只读线，从头读到尾，把它当一段完整的经历。看第 1、2、3 件事。
第二遍：再对照珠子逐段读。看第 4 件事。

对每个问题：引用原文（可以引几处），说清它为什么没做到、影响有多大（轻微 / 中等 / 严重），再给一个改进的方向或示范。一种写法反复出现，单句没错也可能是问题；但要讲清楚连起来为什么不好，以及同类写法在哪些地方是自然、必要的。

最后说：最影响这份成品的三个问题是什么，哪些只是次要的。

只输出 json，不要在 json 外写字：
```json
{{
  "problems": [
    {{"goal": "1 / 2 / 3 / 4 中的一个", "where": "段号或位置", "quotes": ["原文"], "why": "为什么没做到", "severity": "轻微 / 中等 / 严重", "suggestion": "改进方向或示范"}}
  ],
  "top3": ["最影响成品的三个问题"],
  "minor": "哪些只是次要的"
}}
```

## 语言开放评审 lang_open v2（找问题；DAG 的 N09 也用）

```text
请阅读下面这段中文。

它是一条跟随音乐发展的“线”：写的是一个人在这首曲子里经历的一件事，按段写成条目。〔〕表示这句话提到的前文出处。这段文字会和音乐听感记录一起给读者看，希望读起来像一个人在平平常常地讲自己的经历。允许含蓄，不要求补造具体人物、事件或场景。

请作为第一次读到它的普通中文读者，独立评审它的语言质量。你不知道作者此前修改过什么，也不要预先假定它有哪些毛病。

评审分成三个步骤：

第一步：连续阅读整篇。

先从头到尾阅读，把它当作一段完整的叙述，而不是一组需要逐句批改的句子。

注意实际的阅读体验：哪些地方自然流畅，哪些地方读着费劲，整篇读完后有没有留下明显的不舒服、不顺畅或者单调的感觉。

此时先不要着急改写句子，也不要预设问题类别。

第二步：检查局部语言。

逐处指出真正读起来不通顺、不像人话、让人别扭或需要停下来想一想的表达。

每处引用原文，说明为什么不自然，并给一个更自然的说法。

只指出实际存在的问题。没有问题的地方不用提，不要为了凑数挑毛病。

改写时尽量保留原句的意思、人物的心理区别和前后关系，不要为了让句子好听而擅自改变人物经历。

第三步：独立检查整篇的累积效果。

这一步很重要。请暂时放下第二步挑出的具体问题，重新从头到尾看整篇。

检查是否存在这样的情况：某一种写法单独出现时并没有明显错误，甚至完全自然，但在多处反复出现之后，让整篇的阅读体验变差。

不要只寻找单句中的错误，也不要只把第二步的问题重新归纳一遍。要真正检查连续阅读时产生的效果。

对于发现的每一种累积性问题：

1. 引用多处原文作为证据。如果问题跨越全文，尽量选取不同段落的例子；如果问题集中在同一小节，可以引用几句相邻的原文。
2. 解释为什么这些表达连起来会造成问题。不能仅仅因为某种写法出现次数多，就认定它不好。
3. 区分这种写法在哪些情况下本来是自然、必要或有效的，哪些地方才是真正多余或影响阅读的。不要把所有相似表达一律判错。
4. 说明这种累积问题的实际影响有多大，是轻微、中等还是严重。
5. 如果值得修改，提出具体的改进方向，并选择一两个代表性位置示范改写。不必机械地修改所有同类表达。

不要预设必须找到多少种累积性问题。某一种写法反复出现也可能完全合理，甚至是叙述所需要的。如果没有充分证据，就不要把它列为问题。

最后作出整体判断。

给语言质量打 1–10 分。

说清楚最影响阅读体验的是什么，哪些是次要问题。不要因为某类问题比较容易统计、比较容易举例，就高估它的重要性。

请特别注意：局部语言问题与全文累积问题是两种不同的判断。前者需要证明那句话本身不自然；后者需要证明多处表达连起来产生了不理想的效果。一种表达即使单独没有问题，也可以成为累积问题的证据，但必须讲清楚累积影响。

评审结果只输出 JSON，不要在 JSON 外添加文字。

输出结构：

```json
{{

## 提示词顾问 prompt_advisor（找改法；材料部分运行时填入）

```text
你是一位帮我们改进一条“写作流水线”的顾问。请认真、详细地思考，不用顾及我们之前的做法，可以大刀阔斧。

【我们在做什么】
给一首器乐作品（古典钢琴曲）自动生成一份“成品”，两部分放在一起给读者：
- 珠子：逐段的音乐听感记录（已经做好，不改）。
- 线：一个人在这首曲子里经历的一件事，按音乐段落写成关系图（每段 2–4 条，条目间可以指回前面的某一条；每段标他此刻和整件事的关系：没在想 / 还说不清 / 正在面对）。线讲他自己的经历，用来把珠子串起来。
线由一条多层的流水线生成（下面附每一层的提示词）。流水线必须对任何新作品都能用：提示词里不能写针对某一首曲子的内容或例子。

【线要做到的四件事（也是我们的验收维度）】
1. 单独成立：只读线、不看珠子，每段他为什么此刻这样，都能由前面已经发生在他身上的事说明，有一条往前走的路；转折由他自己前面的经历引起，不由音乐事件引起。
2. 不啰嗦：每句有自己的用处；不重说前面说过的；这一段发生得少就写得短。
3. 像人话：像一个人平平常常讲自己的经历，不像心理分析或提纲。
4. 接得上珠子：每颗珠子的听感都能在线里找到情境相近的原因或处境；但线不翻译珠子里的画面、比喻、情节。
验收怎么测：覆盖（评委逐颗珠子判线有没有说清它的来由）、单独读（只读线逐段判讲不讲得通、有没有复述珠子）、新旧两版盲比 8 次（逐段比覆盖 / 啰嗦 / 人话）。

【标准（用户定的，以此为准）】
{SPEC}
