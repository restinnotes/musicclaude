下面会追加同一首作品的 Thread 人物经历候选。候选 JSON 中包含原样复制的 center_input。

你完全看不到珠子，也不要根据音乐细节评判。

你的任务不是挑最戏剧化、最现实、转折最多或最“像故事”的一条，而是先检查事实边界，再判断哪条路线最有可能写成一条独立成立、简洁、像真人经历的 Thread。

事实边界是硬门槛，优先于其他所有优点。

一、先做事实合规检查
把 center_input 当作这一步唯一的内容事实来源；作品名、作曲家和段落顺序不提供人物故事事实。

逐条检查 situation、starting_condition、stakes、phases 中的每个断言：

- 如果读懂一句话必须额外相信某个未在 center_input 中给出的现实条件已经存在，这就是新增事实。
- 关于人物身份、关系状态或历史、外部安排、他人态度或行为、能力资源义务、已经发生或必将发生的外部事件、已经兑现的现实结果，只要 center_input 没有明确给出，就不能因为“很合理”“很常见”“让路线更具体”“放在起点里”或“对后文很必要”而放行。
- 不要只抓显眼事件。名词预设、完成体、含糊的“如今已经……”“原来一直……”等，只要暗中要求一个外部事实成立，也算越界。
- 人物自己的所求、顾虑、取舍、承受、选择和自我可控的行动方向，可以作为路线构造的一部分，只要它们处在 Center 的语义范围内，并且不依赖新增外部前提。
- 如果 Center 本身明确含有行动性，可以允许人物采取自己能控制的做法；但未输入的对象、场景、障碍、他人反应和行动后的现实效果仍不能补造。

任何路线只要存在会承担后续因果作用的未输入现实事实，grounding_verdict 就必须判为“越界”，verdict 必须为“淘汰”。不要替它改写或补救。

二、合规路线再看是否足够具体
具体性应来自人物究竟在意什么、哪几样东西同时拉扯、他准备怎样取舍或行动，而不是来自现实设定的多少。

如果去掉所有外部背景后，只剩高兴、难受、留恋、害怕、安心、不安之类的泛化情绪，路线太薄。

反过来，也不要因为一条路线没有具体场景、人物身份或现实安排就扣分；这些不是本任务的具体性来源。

三、检查 stakes 是否真的能贯穿
一个 stake 可以长期存在，不需要每个 phase 都变化。

看后面的 phase 是否仍然在处理开头已经建立的具体所求、顾虑或行动方向，而不是逐渐换成更泛的心理问题。也检查某个 stake 是否没有依据便突然消失或被解决。

四、检查 phase 是否真的稀疏而有任务差异
允许多个 section 留在同一个 phase，也允许某个 phase 的 development 为空。

换 phase 时，应当能看出人物在同一件事里的位置、选择或利害关系发生了实质变化；不能只是情绪强度不同，也不能靠新增现实事实制造差异。

可做两个检验：
- 如果删掉中间某个 phase，后面的经历完全不受影响，这个 phase 可能只是重复。
- 如果交换相邻两个 phase 的顺序仍几乎一样，路线的时序积累可能不足。

这两个检验只用于发现空转，不要求为了通过检验而强造新后果。

五、检查是否把“行动”误写成结果
人物可以作选择、坚持某种做法、改变自己的处理方式；但“做了以后外部局面已经改变”“因此获得了某种现实位置或效果”等，若输入没有给出，仍是新增事实。

不要把行动能力全部收缩成纯内省，但也不要把行动后的预期效果写成已发生结果。

六、检查是否主要靠心理办法循环推进
如果几个 phase 的区别主要是人物反复压住、放开、劝自己、暂时不想、再重新面对同一个问题，说明路线仍然是心理状态机，只是 phase 变少了。

真正的稀疏 phase 应该让前面形成的所求、顾虑、选择和承受改变后面还能怎样对待同一件事。

七、检查实现空间
路线应锁住人物的核心利害和少量真正的阶段变化，但不规定每个音乐段落唯一的心理动作。后续综合者应当还能结合体验性质，让同一 phase 的不同侧面在不同段落显出来，而不用改动路线的事实边界。

八、结尾检查
结尾可以开放，也可以有明确变化；不要求解决 Center。

淘汰以下结尾：
- 只是把开头的矛盾再说一遍或把情绪放大；
- 突然给出此前没有挣来的成熟答案；
- 为了显得有结果而补入未输入的现实效果。

对每条路线输出：
- route_id
- grounding_verdict：合格 / 越界
- verdict：保留 / 淘汰
- strengths：最多3条，只写结构优势
- risks：最多4条，指出具体风险
- unsupported_claims：列出所有导致越界的关键断言；没有则空数组
- phase_distinctness：高 / 中 / 低
- stake_persistence：高 / 中 / 低
- abstraction_risk：高 / 中 / 低
- implementation_space：高 / 中 / 低

然后选出最多 3 条进入下一步，按优先顺序排列。

如果没有任何路线同时通过事实边界和基本结构要求，selected 必须为空；不要为了让流水线继续而勉强选一条。

不要改写候选，不要替它补事实，也不要因为某条路线更像现实故事就奖励它。

只输出 JSON：
{
  "routes": [...],
  "selected": ["route_id"]
}

候选路线会追加在本提示词末尾。
