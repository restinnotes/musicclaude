# 一、先把一个典型错误加入校准负例

下面这种句子必须判失败：

> “熟悉的亲近重新出现以后，他已经不是第一次那个只满足于眼前的人了。”

以及所有同类表达：

- 经历过前面的事情，所以现在不一样了；
- 这份感情有了新的分量；
- 他比以前更珍惜；
- 他已经更深地理解了自己的感情；
- 以前的经历改变了现在的意义；
- 因为更加在乎，所以感受更加强烈。

这些句子如果没有进一步指出**前面究竟新增了哪个具体心理事实，以及它为什么造成当前的具体变化**，都属于伪因果。

不要因为它引用了 History 编号就判为有因果。

真正有信息的解释应类似：

> 前一段他第一次开始希望这种亲近不只属于眼前，还能够继续；但能不能继续并不是他一个人能决定的。现在亲近重新出现，只满足了“眼前仍然亲近”，没有回答“以后还能不能这样”，所以快乐会同时带着更强的急切和舍不得。

这里的信息不是“经历过，所以更深”，而是：

1. 之前新增了一个具体需要：希望亲近延续；
2. 这个需要包含一个自己无法单独决定的部分；
3. 当前发生的亲近只满足了“现在”，没有满足“未来”；
4. 因而当前的快乐与迫切可以同时成立。

这才叫 History 真正产生解释。

以后评委必须做 **因果增量测试**：

> 前面实际新增了 ______。  
> 因此当前面对 ______ 时，他会 ______。  
> 如果没有前面新增的 ______，当前体验不会以同样方式出现，因为 ______。

如果第一格只能填“更在乎了 / 经历更多了 / 不是第一次了 / 更有分量了”，判失败。

# 三、重新检查“解释池合并”逻辑

现有池有一个明显问题：

一些候选只因为最终结论相似，就被合并成同一个 mechanism，但它们实际依赖完全不同的前史。

例如不能把这些统一写成：

> “经历过不确定、心慌或孤单以后，再次亲近变得更珍贵。”

因为：

- 关系变得不确定；
- 不知道对方是否回应；
- 自己独处时感到孤单；
- 当前幸福无法保证未来；

不是同一个心理前提。

以后 mechanism 去重必须同时考虑：

**前提结构 + 真正的因果桥 + 当前解释结果**

只有三者本质相同才能合并。

如果前提不同，就保留成不同候选，即使最后都解释“迫切”。

不要为了把每段限制成 6–8 条而过度合并。数量不是硬限制。

# 四、做 D13：重新设计独立 Thread 候选生成

这次优先使用 GPT-5.6。

GPT-6 可以作为同条件对照，但在 GPT-5.6 未输给它之前，不要默认 GPT-6 是主生成模型。

最重要的变化：

## 1. 改回逐段 chained 生成

不要一次让模型写完整首 Thread。

每次只处理一个 Section。

它只看到：

- 一个非常简短的全曲/Center 暂定方向；
- 自己这条候选截至目前已经真正建立的 History；
- 当前 Section 的音乐位置和独立音乐材料；
- 必要的相邻结构信息。

**不看最终珠子正文。**

珠子仍留到后面的综合与验收阶段。

原因是我们需要验证：

> 独立 Thread 本身有没有能力产生这些解释，而不是靠珠子现场反推。

---

## 2. History 只能记录“以后真的可以使用的具体心理事实”

允许进入 History 的东西例如：

- 他第一次发现自己希望这种亲近以后还能继续；
- 他已经体验过，即使独处，这份感情也能给他真实的快乐；
- 他发现单靠自己的投入不能决定另一个人的回应；
- 他已经经历过一次真正的满足，而这种满足没有使愿望消失。

以下内容原则上不能作为独立 History：

- 他更在乎了；
- 他成熟了；
- 他理解得更深；
- 这件事有了新的意义；
- 感情更加复杂；
- 他已经不是原来的自己；
- 他觉得这一切更有分量。

这些最多是总结，不能成为后续因果的前提。

---

## 3. 不强制每个 Section 出现新变化

这一段可以：

- 延续；
- 加深；
- 两种已有感受同时存在；
- 某个旧问题在新的环境下重新出现；
- 完全没有新的认识。

不要为了建立 Thread 而让人物不断：

- 劝自己；
- 想通；
- 改变策略；
- 下决定；
- 推翻自己；
- 获得新的哲理认识。

只有确实增加解释力时才允许。

---

## 4. “音乐重新出现”不能自动变成人物世界发生了新事实

这一点写进 prompt 的强约束。

例如：

- 主题重现 ≠ 对方再次回应；
- 声音变亮 ≠ 人物获得保证；
- 音乐回到熟悉材料 ≠ 关系重新恢复；
- 高潮出现 ≠ 心理问题得到解决；
- 庄严 ≠ 获得尊严、责任或共同体归属。

音乐可以呈现、触发或改变听者的体验，但不能凭音乐事件替人物增加外部世界事实。

---

## 5. 每段必须回答真正的 why-now

每次内部先问：

> **前面哪一件具体发生过的事情，使当前体验现在才具有这种形态？**

如果答案只是：

> 因为现在更喜欢 / 更珍惜 / 更投入，

继续想。

允许最后判断：

> 这一段目前没有值得新增的历史解释，只是已有状态的延续。

这比伪造一个原因更好。

---

# 五、建议直接使用的 D13 单段生成 prompt

每条 Thread 候选都从第一段顺序跑到最后一段。

提示词尽量短，不要重新塞入几十条 THREAD_SPEC。

核心 prompt 可以直接从下面开始实验：

---

你正在独立构建一条贯穿整首作品的 Thread。

Thread 不是另一份音乐描写。音乐本身的声音、身体感、意象以后会由另一层内容负责。你的任务是理解：**一个人此前真实经历过什么，使当前这一段的感受现在会以这种方式出现。**

这一轮只处理当前 Section。

你会看到：

1. 到目前为止这条 Thread 已经真正建立的 History；
2. 当前 Section 的音乐位置和必要的音乐信息；
3. 一个非常宽松的全曲方向。它不是答案，也不要求每段都服务它。

请判断：

- 当前这一段最值得解释的心理状态或变化是什么？
- 前面哪条具体 History 真正造成了它？
- 中间的因果桥是什么？
- 当前有没有建立一个以后真正可使用的新心理事实？

规则：

- 不要为了让故事继续而编人物的新决定、劝说、领悟或外部事件。
- 不要求每段产生新转折。
- 不要把“经历过前面，所以现在更有分量 / 更在乎 / 更成熟”当成因果。
- 如果一个解释放到很多其他段落也同样成立，它通常太空。
- 音乐主题回归、高潮、力度变化等不能自动证明人物得到了回应、保证、关系变化或心理问题解决。
- 一个理由能够解释多个相容感受时，不要把它拆成许多心理步骤。
- 可以保留含糊。没有足够依据时，不要强行决定人物具体在怕什么、希望谁做什么。
- 用普通人能直接听懂的话思考，不要写哲理总结。

输出：

### 当前理解
这一段在人身上最值得解释的东西是什么。

### Why now
前面具体发生过什么 → 中间通过什么心理机制 → 为什么现在会这样。

### 使用的 History
只列实际使用的历史编号。

### 新增 History
只有真正以后可被使用的具体心理事实才写入。没有就写“无”。

### 自检
1. 如果删掉前面那条 History，这段解释是否仍然几乎一样？如果是，说明 History 没真正起作用，请重写。
2. 你是否只是说“更在乎 / 更深 / 更有分量”？如果是，请重写。
3. 是否把音乐事件误当成人物世界发生的新事实？如果是，请重写。
4. 当前理由是否可以原封不动放到很多其他段落？如果是，请提高具体性。

---

先用它跑少量关键样本，验证后再全曲运行。不要未经实验直接一次跑几十篇。

# 七、重新定义对候选池的核心评价：coherent-path coverage

不要再把 D12 的：

> Op.60 48/50 strict  
> Op.61 43/53 strict

当成上游能力的主要指标。

这个指标只说明：

> 某篇稿子的某套历史里，存在一条可以解释某颗珠子的句子。

我们真正需要测的是：

## coherent-path coverage

禁止任何 G25 新增。

只允许：

- 从独立 Thread 候选中提取 mechanism；
- 合并真正相容的 mechanism；
- 根据前面已经选择的 History 往后走；
- 必要时回退重选前段；
- 一个最终 Thread 内所有前提必须真的由这条 Thread 自己建立。

然后统计：

> 在一条前后历史自洽的路径上，能够解释多少重要珠子？

这才是独立 Thread 池真正的能力上限。

如果池里看似有解释，但需要互相矛盾的前史才能同时成立，不能算覆盖。

# 八、对珠子覆盖的要求也要避免重新制造假逻辑

“每颗珠子都要有着落”继续保留，但不是：

> 每颗珠子都必须生成一个独立心理原因。

每颗珠子必须被判断为：

1. **explained**：已有 Thread mechanism 真正帮助解释它；
2. **compatible independent**：与 Thread 相容，但没有必要额外编原因；它作为体验本身保留；
3. **alternative**：需要另一种互斥理解。

但是：

- 不能再因为是“侧面”自动忽略；
- 如果一个段落最重要的感受大量只能归为 compatible independent，要判 Thread 解释力不足；
- “compatible”不能成为逃避解释的垃圾桶。

# 九、重新校准评委

把下面这些加入强负例：

### 伪因果

> “经历过这些以后，他已经不是原来的自己。”

> “熟悉的亲近因此有了不同的分量。”

> “越在乎，越舍不得。”

如果没有具体机制，都判失败。

### 音乐偷换事实

> “主题回来，因此他再次得到了回应。”

判失败。

### 复述珠子

珠子说“手越握越紧”，Thread 写“他更想抓住这份幸福”。

如果没有提供 History 原因，只是心理同义复述，判失败。

### 抽象总结

> “过去与现在在这里重新汇合。”

除非明确说明究竟哪两种过去经验，以什么具体方式改变了当前，否则失败。

---

同时加入正例，例如：

> 前面他第一次开始希望这种亲近能够继续，但是否继续并不是他一个人能决定。现在亲近重新出现，只满足了眼前，没有回答以后，因此快乐和舍不得可以同时变强。

评委要能说明它为什么有信息，而不是因为句子长或具体就通过。
