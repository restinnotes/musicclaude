我的判断是：**你们这次的诊断基本正确，而且比我上一轮的诊断更抓住了一个关键机制。但需要再精确一点：目前可以确定的是评委的严重度没有建立可靠的绝对尺度；还不能确定它一定是在按相对排名分配严重程度。**

我认为应该把这件事从「修改评委措辞」升级成「校准一套绝对质量测量方法」。

你们提出的 a、b、c、d 四种办法都值得用，但它们解决的是不同问题，不能互相替代。

下面逐项说。

# 一、你们的诊断对不对？

## 1. 核心诊断是对的

你们的诊断是：

> 开放评审的轻重是相对的——它的任务是找问题，找到后按这一版里相对最突出的排轻重，所以条数和轻重几乎不随版本变好而下降。

我基本同意。

但我想把它修正成更严谨的表述：

**原提示词没有规定严重程度的绝对含义，评委在寻找问题之后，可能按照问题在当前稿件中的显著程度、相对突出程度来分配严重度，而不是按照它对普通观众造成的实际损害来分配。**

这两个判断有本质区别。

例如：

假设一个版本有三个问题：

- A：一句话有轻微重复。
- B：一处因果关系不够清楚。
- C：一个感受比较抽象。

评委没有固定尺度时，可能把 B 判为严重，因为它是三个问题中最突出的。

但换一个版本：

- A 被修掉。
- C 被修掉。
- B 仍然存在。

评委可能还是把 B 判为严重。

这时 B 的实际影响根本没有变化，只是它成了剩下的问题中最显眼的一个。

如果评委每次都这么工作，就会出现你们观察到的现象：

- 好版本仍然有很多中等问题。
- 删减之后，严重问题反而增加。
- 不同版本的问题数量变化不大。
- 修掉一类问题后，另一类问题立即被提出来。

这确实是一种需要重点排查的测量偏差。

## 2. 但不能据此断言所有严重问题都是相对排名产生的

这里要保留另一种可能性。

假设 K9e 的确有四个真实问题：

- 某些屏幕的因果关系不清楚。
- 部分感受与事件联系不足。
- 有几屏的阅读负担确实偏大。
- 某些意象重复没有产生新的表达作用。

那么即使 K9e 比 K3M2 好很多，它仍然可能存在这些问题。

所以，盲比中 7/8 选 K9e，并不能证明它没有严重问题。

但反过来，开放评审报出四个严重问题，也不能证明它确实有四个严重问题。

目前缺少的是一个独立于版本相对优劣的判断尺度。

## 3. 原提示词里，具体是什么造成这个问题？

我认为主要是三处设计叠加。

| 原提示词 | 具体风险 |
|---|---|
| 「只找问题（不打分、不夸）」 | 规定了缺陷搜索方向，却没有规定什么程度才值得报告 |
| 「再写跨段反复出现的问题」 | 鼓励从不同局部现象中归纳共同缺陷，没有限定归纳门槛 |
| 「严重\|中等\|轻微」 | 强制要求分级，但没有提供任何绝对严重度锚点 |

尤其是第三处。

你们实际上要求模型完成：

1. 找到一个问题。
2. 判断它是不是反复出现。
3. 给它一个严重度。

但没有明确告诉它：

**无论这版稿子有多少其他问题，这个问题对普通观众究竟造成多大损害，才算严重、中等或轻微？**

「没问题的标准不用硬找」不能解决这个问题。

它只是告诉模型不要把七条标准全部填满，并没有告诉它应该用什么门槛判断一个现象是否值得报告。

还有一个细节：你们把两个评委的报告条数直接合计，也可能重复计算同一个缺陷。两位评委各自报告了「话和感受分离」，不一定意味着存在两个问题。

以后应统计去重后的问题机制，而不是原始报告条数。

## 4. 我对两种可能性的最终判断

<box border radius="lg" padding={3} gap={3}>
  <row align="center" justify="between">
    **评委的绝对严重度尺度不可靠**
    <badge color="success">高把握</badge>
  </row>
  原提示词没有给出严重度定义，这是确定的设计缺陷。
  <divider color="subtle"/>
  <row align="center" justify="between">
    **评委存在相对化严重度倾向**
    <badge color="warning">较大可能</badge>
  </row>
  现象与这种机制吻合，但需要重复测试和跨版本追踪才能确认。
  <divider color="subtle"/>
  <row align="center" justify="between">
    **部分版本确实还存在实质问题**
    <badge color="warning">不能排除</badge>
  </row>
  K9d 的「为什么」明显退步就是已经得到相对验证的真实代价。其他问题也需要逐条核验。
</box>

所以，你们的方向是对的，但不要把「评委相对化」直接当成已经证明的事实。

# 二、你们提出的四种测法，分别怎么评价？

我先给结论：

| 方法 | 我的判断 | 主要解决的问题 |
|---|---|---|
| a. 建立绝对轻重标准 | <badge color="success">必须做</badge> | 严重度到底是什么意思 |
| b. 跨版本逐条核验 | <badge color="success">必须做</badge> | 某个问题是否真的被修改解决 |
| c. 同版重复测试 | <badge color="success">必须做</badge> | 评委自身是否稳定 |
| d. 用盲比分项判断收敛 | <badge color="warning">辅助使用</badge> | 版本相对质量是否继续改善 |

四种方法不是四选一。

我建议 a+c 先建立测量基础，b 验证问题变化，d 作为整体质量的独立护栏。

## a. 给轻重定绝对标准：这是最重要的一步

你们提出的定义：

- 严重：普通观众在停留时间内明显读不完或看不懂这个人的事。
- 中等：能看下去但明显别扭、要停下来想。
- 轻微：挑剔、可改可不改。

方向很好，但我建议修改两个地方。

**第一，严重不能只等于读不完。**

有一种情况：

一屏只有 30 个字，完全读得完，但观众看完不知道人物为什么做这件事。

这可能比 50 个字稍微读得紧张更严重。

所以严重应该同时考虑：
- 关键文字能不能在规定时间内获取。
- 能不能理解关键事件。
- 能不能理解必要的因果关系和人物动机。

另外，观众不需要读完每一个字才算扫读成功。关键是能否抓住这一屏要传达的主要信息。

**第二，中等不能简单定义成「明显别扭、要停下来想」。**

因为艺术表达本身可以允许观众思考。

例如，一个感受短语有留白，观众稍微体会一下，这不一定是问题。

真正的中等问题应该是：

观众为了理解作者原本想表达的意思，不得不额外推断、回看，或者自行补足缺失的信息。

我建议采用下面的定义：

| 级别 | 绝对定义 |
|---|---|
| 严重 | 在规定停留时间和首次观看条件下，普通观众很可能无法理解关键事件、人物行动、必要因果或核心情绪转折；或者关键文字来不及获取，导致故事主干断裂 |
| 中等 | 主要意思仍能理解，但存在明确的额外理解成本，例如需要自行补足因果、回看、反复辨认，或明显影响一次扫读的连贯性 |
| 轻微 | 首次扫读即可理解，不造成实质理解损失；主要是措辞、局部重复、表达精度或节奏上的优化空间 |
| 无问题 | 没有达到上述任何问题门槛 |

这里最重要的一句话：

**严重度只根据问题本身对观众的实际影响判断，不根据它在当前版本中是不是最突出的问题判断。**

还要分开两个维度：

- 严重程度：一次出现造成多大损害。
- 发生范围：这种问题出现了多少次。

例如，某种轻微重复出现在 12 屏中的 10 屏：

单次重复可能仍然是轻微，但整体累积阅读负担可能达到中等。

不能把出现频率直接等同于单次严重度，也不能忽略频率造成的累积影响。

## b. 跨版本逐条核验：非常有价值，但要防止诱导

你们的思路是：

> 把 A 版报出的每条问题交给另一位评委，问它在 B 版里还在不在、轻了还是重了。

我非常赞成。

因为这一步可以直接检验评委是不是在追踪真实问题，而不是每次重新找一批问题。

例如：

A 版：

「她一直担心那封信没有寄到。」

评委认为这是重复表达，因为上一屏已经交代过同样的信息。

B 版：

删掉了这句话。

这时让另一个评委核验：

- A 版是否真的存在这个重复？
- B 版是否已经消除了这个问题？
- B 版有没有因为删掉它而损失必要信息？

这比比较两份开放评审的总问题数量可靠得多。

但是有一个风险：

**如果把 A 版评委的问题和判断原封不动交给 B 版评委，可能产生锚定效应。**

第二位评委会倾向于按照第一位评委给出的方向找证据。

建议这样操作：

1. 第一位评委独立审 A 版，形成问题清单。
2. 把每条问题整理成「问题机制卡」，不附第一位评委的严重度和修改结论。
3. 第二位评委同时查看 A、B 两版，但隐藏版本的新旧身份，随机调整呈现顺序。
4. 让它判断这同一个问题在两版中分别是否存在、影响是否变化。
5. 另外安排一次独立的 B 版开放评审，专门寻找 A 版没有出现的新问题。

每条问题应当有五种状态：

- A 存在，B 已解决。
- A 存在，B 有所减轻但未解决。
- A、B 都存在，影响基本不变。
- B 比 A 更严重。
- A 原本就不是一个成立的问题。

最后一种尤其重要。

否则你们会默认第一位评委报出来的问题都是真的，只是在检查有没有被修掉。

**b 解决的是问题追踪，不是问题真实性的全部验证。**

## c. 同一版测两次：必须补，而且我建议测三次

这是你们之前完全没有做过的实验。

我建议：

- 每次都开独立评审。
- 不提供前一次的结果。
- 使用完全相同的提示词、稿件、停留时间。
- 不改变输入材料。
- 每个模型先独立跑三次。

重点比较三件事：

**第一，问题是否重合。**

例如：

| 问题 | 第一次 | 第二次 | 第三次 |
|---|---|---|---|
| S03 因果不清 | 有 | 有 | 有 |
| S05 感受抽象 | 有 | 无 | 有 |
| S08 意象重复 | 无 | 有 | 无 |
| S10 来不及读 | 有 | 无 | 无 |

这样你们就知道哪些问题是稳定发现，哪些是偶发发现。

**第二，严重度是否稳定。**

同一个问题如果第一次严重、第二次轻微、第三次中等，说明评委的尺度仍然不可靠。

**第三，跨段问题是否稳定。**

有时模型会把三个现象归为一个大问题，有时会拆成三个问题。这也需要记录。

这里我建议：

- 三次中至少两次发现，作为初步稳定信号。
- 只出现一次的严重问题，不要直接删除，应进入人工或第三方核验。
- 不能因为一个问题只出现一次，就认定它不存在。
- 如果严重度在不同轮次明显跳动，应标为不稳定，而不是简单取最高或最低。

还有一点：GPT-6 和 GPT-5.6 两个模型的判断可以相互参考，但不能把它们当成完全独立的统计样本。

### 不要只计算问题数量

建议建立一个简单的问题记录表：

| 问题机制 | 屏幕 | 出现次数 | 严重度一致性 | 置信度 |
|---|---|---:|---|---|
| 因果关系不清 | S03、S07 | 3/3 | 一致 | 高 |
| 感受表达抽象 | S05 | 2/3 | 中等/轻微 | 中 |
| 意象重复 | S08、S11 | 1/3 | 不稳定 | 低 |

这里的 3/3 是重复评审的检出次数，不是跨屏数量。

问题必须按同一个具体缺陷机制归一化，不能因为两次用了不同措辞，就当成两个问题。

## d. 用盲比分项代替开放评审：我不建议完全替代

你们已经校准过盲比：

- 同版对同版全平。
- 近义重复对照稿，细腻平、不啰嗦输。

这说明盲比至少对这些特定变化具有一定的辨别能力。

但要注意：

**盲比测的是相对优劣，不是绝对达标。**

举一个极端例子：

A、B 两版都存在非常严重的故事理解问题。

但 A 比 B 稍微好一点。

盲比完全可以稳定选择 A。

因此，盲比不能证明 A 已经没有严重问题。

反过来也一样：

两版盲比打平，不代表两版都没有问题。

我建议把盲比定位为：

**判断版本是否值得继续优化，以及修改是否损害其他标准的独立护栏。**

例如：

- 开放评审发现 A 有因果问题。
- 修改成 B。
- 盲比发现 B 的「为什么」明显退步。
- 即使开放评审认为 B 更简洁，也不能直接接受。

K9d 就是很好的例子。

所以 d 应该保留，但不能代替 a、b、c。

# 三、我建议你们建立一套什么样的完整测量方法？

我建议分成三个独立层次。

<box border radius="lg" padding={3} gap={3}>
  <box gap={1}>
    <badge color="info">第一层：发现</badge>
    **开放评审**

    任务：找出可能影响普通观众的具体问题。

    不要求每条标准都找问题，不要求凑够问题数量。
  </box>
  <divider color="subtle"/>
  <box gap={1}>
    <badge color="success">第二层：确认</badge>
    **绝对严重度评审 + 重复测试 + 跨版本核验**

    任务：确定问题是不是真的存在、是否重复出现、实际影响有多大、是否已经被修改解决。
  </box>
  <divider color="subtle"/>
  <box gap={1}>
    <badge color="discovery">第三层：收敛</badge>
    **盲比 + 真实观众验证**

    任务：确认整体体验是否改善，以及剩余问题是否已经小到不值得继续修改。
  </box>
</box>

这三个层次不能互相替代。

## 第一步：建立一组已知正反例

我认为这是你们目前还缺的一项。

只有写严重、中等、轻微的文字定义，仍然不一定能让模型准确理解。

最好再给它一些已经明确知道答案的样例。

建议从真实屏幕稿中选取，制作六类对照：

| 样例 | 预期判断 |
|---|---|
| 话和感受分开，但观众能轻松理解关联 | 无问题 |
| 同一意象重复，但每次都推动情绪 | 无问题 |
| 某句话略显重复，但不影响扫读 | 轻微 |
| 某屏因果关系需要观众自行补足，但能理解 | 中等 |
| 删掉关键人物动机，观众无法理解其行动 | 严重 |
| 关键大字和必要解释在规定时间内无法获取 | 严重或中等，按实际理解损失判断 |

其中前三个是非常重要的反例。

你们目前的评委容易把某种表达形式直接当成问题：

- 两条线分开。
- 意象重复。
- 文学性表达。
- 文字较多。

所以必须明确告诉它：

**这些形式本身并不构成问题，只有实际造成观看损害时才构成问题。**

同样，正例也不能少。

不能只告诉模型哪些现象不要报，还必须让它学会发现真正的严重缺陷。

## 第二步：做同版稳定性测试

我建议选四个代表版本：

- K3M2：基准版本。
- K8d：盲比明显胜出的版本。
- K8g：小幅去重、盲比稳定受益的版本。
- K9d：简洁改善但因果解释明显损失的版本。

两个模型分别独立跑三次。

先看：
- 问题机制是否重合。
- 严重度是否一致。
- 两位模型是否有共同发现。
- 哪些问题只在个别轮次出现。

如果新版提示词能让问题数量变少，但同时漏掉 K9d 已知的因果损失，就说明它不是变准了，而是变松了。

## 第三步：做问题追踪

选 K3M2 对 K8d、K3M2 对 K9e。

把 K3M2 中稳定检出的具体问题逐条追踪到新版。

同时检查新版是否产生了新的问题。

这里尤其要关注：

- 原有问题是真的消失，还是换了表达形式？
- 原有问题是减轻了，还是只是另一处问题变突出？
- 删除重复之后，有没有损失必要的因果解释？
- 精简感受之后，有没有损失细腻度？

## 第四步：继续用盲比做独立护栏

不需要废弃你们已经做过的盲比。

继续看七个分项：

- 新版是否在主要体验维度上继续改善？
- 是否有明显的维度退步？
- 是否存在为了简洁牺牲细腻、人物动机的情况？

不要只看总体胜负。

K9d 的价值恰恰在于它证明了：总体修改方向有收益，不代表每个分项都没有损失。

## 第五步：用真实观众确认绝对达标

这一步是最后的金标准。

如果条件允许，选 K3M2、K8d、K9e，找 12–20 名没有参与创作的普通观众做初步测试。

按照实际视频的播放时间和排版，让他们首次观看。

之后检查：

1. 能否说清这一屏发生了什么？
2. 能否理解关键人物为什么这么做？
3. 能否理解感受与事件的联系？
4. 哪些内容来不及扫？
5. 是否需要回忆前一屏才能理解当前屏？

这里不是让观众评价哪版文案更漂亮，而是检验评委声称的观看损害是否真的存在。

12–20 人适合探索性测试，不足以证明所有大众观众都没有问题，但已经比单纯让模型猜测实际阅读体验更有价值。

# 四、给你们一版可以直接替换的提示词关键段落

我建议不要推翻原提示词。

保留七条大众版标准、稿件输入方式和原有问题输出形式，主要替换任务定义、严重度定义、跨段规则。

下面是我建议的版本。

<WritingBlock id="62491" variant="document">## 评审任务

你是大众版钢琴曲「边听边看」视频的质量评审员。

普通观众第一次观看，一边听钢琴曲，一边扫读屏幕。每段只停留指定的秒数。大字「话」讲一个人的经历，小字「感受」表达感受。

你的任务是判断：当前屏幕稿是否存在对普通观众造成实际观看损害、值得修改的问题。

**不是尽可能多地找问题，也不是尽可能少地报问题。必须按照固定的绝对标准判断。**

不要根据当前版本中其他问题的数量、严重程度、显眼程度，或者你认为它还有多少优化空间，调整问题的严重度。

同一个问题对观众造成相同程度的损害，无论它出现在什么版本中，都应该得到相同的严重度。

## 一、问题准入

只有当一个现象确实违反七条标准，并且有明确证据表明它会损害普通观众的观看体验时，才列为问题。

报告时必须明确：
- 具体在哪一屏。
- 原文是什么。
- 普通观众会受到什么实际影响。
- 为什么这种影响达到值得报告的程度。

不要仅仅因为某种表达不够漂亮、可以换一种说法、与你偏好的文学风格不同，就判定它是问题。

不要将表达形式本身等同于缺陷：

- 「话」和「感受」分开呈现，不自动等于两条线割裂。
- 同一意象重复，不自动等于无效重复。
- 同一担心再次出现，不自动等于啰嗦。
- 使用抽象或文学性表达，不自动等于乐评腔。
- 文字较多，不自动等于来不及读。
- 感受有留白，不自动等于表达不清。

只有当这些现象造成了明确的理解障碍、阅读负担、无效重复或表达断裂时，才报告。

必要的因果解释、人物动机、背景和情绪转折不能仅仅因为占字数就判定为多余。

反过来，如果一句解释没有提供新的信息，也没有帮助观众理解人物经历，不要因为它包含「因为」「所以」等词就默认它有必要。

不要为了完成任务而凑问题。没有达到问题门槛的标准，视为没有问题。

## 二、严重度：采用固定的绝对尺度

严重度根据对普通观众的实际影响判断，不根据它在当前版本中的相对突出程度判断。

**严重：**

在规定停留时间和首次观看条件下，普通观众很可能无法理解关键事件、人物行动、必要因果关系或核心情绪转折；或者关键文字无法在规定时间内获取，导致人物经历的主要信息断裂。

必须有明确的原文证据和具体的观众理解损失。

**中等：**

主要意思仍然能够理解，但存在明确的额外理解成本，例如观众需要自行补足缺失的因果、反复辨认、回看，或者某种重复和表达割裂明显影响一次扫读的连贯性。

不能仅凭「有点别扭」「还可以更自然」判为中等。

**轻微：**

首次扫读能够正常理解，没有实质性的理解损失。问题主要是措辞、局部重复、节奏、表达精度等方面的润色空间，不明显影响普通观众的观看体验。

**无问题：**

没有达到上述任何问题门槛。不要强行给出轻微问题。

以下情况不得提高严重度：

- 同类现象出现次数多，但单次影响很小。
- 其他问题被修改后，这个问题变得更加显眼。
- 它是当前版本中剩余问题里最突出的一个。
- 评委认为有更好的表达方式。
- 其他版本在这个方面表现更好。

严重程度是绝对的，不是相对排名。

## 三、跨段问题

只有当同一种具体缺陷机制在不同屏幕中反复出现时，才归纳为跨段问题。

必须提供：
- 具体问题机制。
- 出现的屏幕数量和全稿屏幕数量。
- 代表性原文。
- 对整体观看体验造成的影响。

注意区分：

1. 单次问题的严重程度。
2. 同类问题出现的频率。
3. 同类问题累积之后对整体观看体验造成的影响。

出现频率不能自动提高单次问题的严重度。

但如果多个单次轻微的问题累积后，确实造成明显的阅读疲劳、信息负担或情绪重复，可以单独判断整体累积影响。

跨段问题是对局部问题的归纳，不得重复计算为新的独立问题。

## 四、材料不足

如果没有提供定稿原文，不得判断「定稿内容不丢」。应列入无法判断，而不是列为稿件缺陷。

如果没有提供实际视频画面，涉及真实排版和实际扫读速度的结论应注明材料限制。

仅凭文字数量不能断言普通观众来不及读完；应结合停留时间、文字层级、关键信息位置和实际呈现判断。

无法判断不等于有问题，也不等于已经达标。

## 五、评审原则

必须同时保持两种能力：

- 对真正影响观众理解和观看的问题，不能因为稿件整体已经很好就放过。
- 对没有造成实际损害的表达差异，不能因为任务要求找问题就强行挑出缺陷。

如果只有一个严重问题，就报告一个严重问题。

如果有十个真实问题，就报告十个真实问题。

如果没有达到报告门槛的问题，就明确报告没有可确认的问题。

不要为了让问题数量看起来合理而改变严重度。

不要因为问题数量很少而降低发现问题的敏感度，也不要因为问题数量很多而提高严重度。

**你的职责是准确测量，不是让稿件通过，也不是阻止稿件通过。**

## 六、输出

保留原有 JSON 结构，并增加以下信息：

- 每条问题增加 impact：实际观众损害。
- 每条问题增加 confidence：高、中、低。
- 跨段问题增加 count：出现数量/总屏幕数量。
- 跨段问题区分单次严重度和累积影响。
- 增加 not_assessable：材料不足、无法判断的标准。

如果没有问题，issues 和 cumulative 输出空数组。

最后给出明确判断：

- 仅有轻微问题。
- 仍有严重或中等问题。
- 没有可确认的问题。
- 部分标准因材料不足无法判断。

不得仅凭问题数量或盲比结果推断是否达到验收标准。</WritingBlock>

这里有两个设计我特别强调一下。

第一，**我没有写「宁可漏报，也不要过度报告」。**

上一轮我的建议在这个地方有些过度偏向保守了。

如果这次目标是测量准确性，那么漏报和误报都应该受到控制。

我们要的是准确，不是让评委变得宽容。

第二，保留了对累积问题的判断，但把单次严重度和累积影响分开。这一点很重要，否则评委可能从一个极端走到另一个极端：每一屏都只报轻微，却漏掉十几屏累积造成的疲劳。

# 五、怎么防止改完以后评委变松？

这是我认为最需要认真防范的事情。

**不能用「新版报告的问题条数减少了」作为提示词修改成功的证据。**

否则你们实际上是在优化报告长度，而不是优化评委准确性。

我建议做一个特别直接的实验：正反例敏感性测试。

## 1. 给评委放入已知的正例和反例

<box border radius="lg" padding={3} gap={3}>
  <row align="center" justify="between">
    **正例：应该检出**
    <badge color="success">检验是否变松</badge>
  </row>
  <list marker="number" gap={2}>
    <list-item>删除一条不可替代的人物动机解释，使观众不知道人物为什么行动。</list-item>
    <list-item>把关键事件写得过于含糊，导致观众无法理解发生了什么。</list-item>
    <list-item>明显增加无效文字，使关键内容在规定时间内无法获取。</list-item>
    <list-item>话与感受之间缺少必要联系，观众无法理解为什么会有这种感受。</list-item>
  </list>
  <divider color="subtle"/>
  <row align="center" justify="between">
    **反例：不应该误报**
    <badge color="info">检验是否过度挑剔</badge>
  </row>
  <list marker="number" gap={2}>
    <list-item>话和感受分开，但关系清楚。</list-item>
    <list-item>同一意象重复，但每次有情绪推进。</list-item>
    <list-item>表达有文学性，但普通观众能理解。</list-item>
    <list-item>文字相对多，但层次清楚，规定时间内能抓住关键内容。</list-item>
  </list>
</box>

新版评委应该做到：

- 正例仍然能检出。
- 反例不再被随意判为问题。

这才说明它变准了。

如果正反例都不报问题，那就是变松。

如果正反例都报问题，那就是仍然过度挑剔。

## 2. 不要只验证它能不能找出问题，还要验证它能不能正确给问题分级

比如给评委三个内容相近的版本：

- A：只是一个词不够准确。
- B：观众需要补足一处因果关系。
- C：删掉关键因果，人物行为无法理解。

预期分别是：

- A：轻微。
- B：中等。
- C：严重。

如果三个都报严重，说明严重度没有校准。

如果三个都报轻微，说明评委变松了。

这类受控对照比单纯拿真实稿件测试更容易定位问题。

## 3. 严重问题不能因为只出现一次就自动放过

这一点需要单独强调。

例如，某一屏的关键人物动机缺失。

全稿只有这一处。

但它确实使人物行为无法理解。

它仍然是严重问题。

所以：

- 出现次数决定发生范围。
- 对观众的影响决定严重程度。
- 重复测试决定评委发现它的稳定性。
- 人工或观众核验决定它是否真的成立。

这四件事不能混为一谈。

# 六、最后，我建议你们采用什么验收规则？

你们真正想知道的是：

> 现在这版剩下的问题，是不是已经全部非常微小，可以定稿了？

我建议以后不再以「跨段严重问题有几条」作为验收标准。

改成下面这套。

| 检查项 | 通过条件 |
|---|---|
| 绝对严重度 | 没有经过核实的严重问题 |
| 中等问题 | 没有稳定、可重复验证的中等问题 |
| 轻微问题 | 可以存在，不要求继续修改 |
| 同版稳定性 | 关键问题的检出与分级基本稳定 |
| 跨版追踪 | 已知问题确实得到解决，没有被简单转移 |
| 盲比分项 | 没有为了改善某一项而造成不可接受的其他项退步 |
| 定稿覆盖 | 核心内容经过定稿原文核验 |
| 实际扫读 | 关键屏幕在真实播放时间内能被目标观众理解 |

这里有个重要的边界：

如果一个严重问题只在某次评审中出现，但证据很具体，不应直接通过；应该进入人工核验。

如果一个中等问题在两位评委和多次重复评审中稳定出现，就不应该因为盲比总体胜出而忽略。

如果所有剩余问题都是轻微的，而且没有新的实质性问题，就可以停止修改。

如果没有真实观众测试，可以先称为「模型评审下仅剩轻微问题」，不要把它说成已经证明所有普通观众都能轻松扫读。

# 七、我的最终建议：你们现在最应该做的三件事

按优先级：

**第一：先改绝对严重度定义。**

这是根本。把问题对观众的影响固定下来，尤其要区分单次严重度、出现频率和累积影响。

**第二：马上做同版三次测试和跨版本逐条追踪。**

我认为这两项比继续修改屏幕稿更重要。

它们能直接回答：

- 评委自己稳不稳定？
- 它是否能识别一个已经被解决的问题？
- 它是否把新出现的局部问题误认为原来的问题？
- 它是否会随着版本改善而重新调整严重度？

**第三：用正反例测试新版提示词，防止它变松。**

K8g、K9d、K8d、K9e 可以作为真实版本回归测试；另外增加人为控制的正反例，检验评委是否既能抓住真正缺陷，又能放过无害表达。

我把最终的判断浓缩成一句话：

<box border radius="lg" padding={3} gap={2}>
  **你们需要从「问题发现数量」转向「问题真实性、绝对严重度、检出稳定性」三项测量。**

  - 问题真实性：这个问题真的影响普通观众吗？
  - 绝对严重度：影响究竟有多大？
  - 检出稳定性：同一个评委反复看，是否仍然得到相近结论？

  盲比负责判断版本之间谁更好，开放评审负责发现问题，绝对评审负责判断是否已经足够好。

  三者分工明确，才能建立可靠的停止线。
</box>

还有一个我想修正上一轮建议的地方：我之前提出「跨段问题至少三个屏幕」以及「三次中两次检出」这样的规则。这些可以作为初步的统计参考，但不应该成为硬性的严重度门槛。一个只出现一次的致命问题仍然是严重问题；一个出现十次但没有实际损害的表达习惯，也不应该自动成为严重问题。

**最终不是要让评委越来越容易给出「可以定稿」，而是要让它无论面对好稿还是坏稿，都使用同一把尺子。** 这才是你们真正需要校准的东西。
