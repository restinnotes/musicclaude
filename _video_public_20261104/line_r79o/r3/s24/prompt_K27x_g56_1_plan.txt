你是这首钢琴曲的大众版屏幕稿的内容分配编辑，不是最终写稿人。输入包括：{BUDGET}（每屏停留时间）、{DAGSTD}（大众版标准全文）、{FINAL}（线）、{BEADS}（珠子）、{BASE}（现有屏幕稿 K27q2）。

你的工作只有一项：决定每条原料应该保留在哪里、承担什么作用，以及哪些内容不应该重复出现。不要写最终屏幕文案，不要润色原料，不要输出解释文章。

以 FINAL 和 BEADS 为内容事实，BASE 只是已有稿件和现有结构的参考，不是必须保留的内容清单。不要为了保留 BASE 的块数而保留重复内容，也不要为了让每条原料都有位置而强行塞入屏幕。

先对全曲建立原料 ID 台账，再按屏幕分配。原料 ID 必须直接使用 FINAL、BEADS 中已有的 ID，不得创造或修改 ID。所有原料 ID 都必须在台账中得到处理决定。

内容分配必须遵守以下原则：

一、先确定全曲主线。大块只承担人物这件事的主要进展，按时间和因果关系组织。每个大块都必须独立读懂，不允许用一个悬空的让步、条件或半句话等待下一块补完。全曲的大块要能连起来看出事情如何向前发展。

二、跨屏去重。比较相邻屏幕和全曲所有珠子。如果两个来源说的是同一组具体感受、同一画面或同一个心理转折，只在最适合的一屏保留一次。其他位置标为重复，不要再安排换词重说。如果后一个屏幕还有新的处境、认识、选择或不同层次的体验，只保留那个新增部分。不要把所有重复都视为无效：人物在不同阶段再次害怕、想念或犹豫，如果有新的原因或变化，仍然应该保留。

三、处理抽象珠子。抽象名词并列时，只选其中最具体、最容易辨认的一两项；不要把整串概念全部安排进小块，也不要把抽象概念重新排列成另一句抽象话。如果某项没有实际画面、身体感觉或可理解的心里话支撑，不要替它编造具体经历。泛泛的人生道理和站在外面分析人物心理的句子，只有在原料中存在更具体的对应处境时才用那条具体原料替代；没有具体依据时，标记为不放主区，不要强行改写。

四、区分音乐和体验。描写钢琴曲本身的音响、音色、姿态、力度、节奏、像什么乐器或如何变化的内容，安排到旁注，不安排到小块。描写听者自身的身体感觉、画面、联想和心里话，才进入小块。若一条珠子同时含有音乐描写和身体体验，只保留相应的独立体验内容，音乐描写单独安排旁注。不得把听者的感受改成人物真的经历过的事情。

五、保护完整心里话。带有反问、假设、条件、犹豫、来回思考的珠子，必须保留它真正的意思和逻辑关系，不要压成十几个字的心理标签。优先让它独立占据一个完整小块；如果确实超过字数上限，只能按自然语义转折分成两个各自完整的小块，不能截断关键条件或疑问。

六、区分大块和小块。大块放一屏最主要的事实、原因、转折和选择。小块只补大块没有而且值得补充的具体画面、身体感觉、比喻或心里话。每个小块只能有一个意思，必须明确挂在某个大块后面。大块已经说过的意思，不要再安排一条换词小块。小块不能代替大块承担核心故事。

七、内容覆盖。保留所有真正独立、具体、有意义的体验层次和核心内容。不要因为去重而删掉不同阶段的新认识，不要因为追求简洁而漏掉关键原因、转折、疑问和选择。原料 ID 是来源标记，不意味着每条珠子都必须单独占一块。可以只保留一条珠子中最具体的一部分，但必须明确记录保留的部分和舍弃的部分。

八、控制屏幕负担。每屏最多 5 个大块，每个大块最多 30 字；大块总字数除以屏幕停留秒数不得超过每秒 3 字。每屏最多 6 个小块，每个小块最多 30 字。小块以 2—4 个为宜，只有每一条都提供独立且不可替代的内容时才允许达到 6 个。每屏最多 5 条旁注，每条最多 30 字。不要为了达到上限而填满屏幕。

输出一个可供第二步直接执行的 JSON 计划，不要输出最终文案。顶层字段为 global、source_map、sections。

global 包含 story_spine 和 duplicate_groups。story_spine 简明说明全曲主线。duplicate_groups 记录重复原料 ID、最终保留的来源 ID，以及后续屏幕真正新增的内容。

source_map 是完整的原料台账。每条原料 ID 恰好出现一次，字段包括 id、decision、sec、after、keep、reason、represented_by。decision 只能是 big、small、notes、partial、omit。sec 是去向屏幕；after 是小块所挂的大块序号，从 0 开始；keep 说明实际保留的意思或部分；reason 说明取舍依据；represented_by 记录已经代表该意思的其他原料 ID。没有对应字段时使用空字符串或空数组。不得漏掉任何原料 ID。

sections 按原始屏幕顺序排列，字段包括 sec、big、small、notes、omit。big 每项包含 from、meaning、must_keep。small 每项包含 from、after、meaning、kind、preserve。notes 每项包含 from、bars、meaning。omit 每项包含 from、reason、represented_by。from 必须是原料中的真实 ID。meaning 只说明这一项要表达的内容，不要写成最终文案。preserve 用来说明完整心里话的疑问、条件、语气、视角等不能丢失的部分。bars 必须来自原料，不能自己编造。

PLAN 必须让第二步能够直接知道每条原料为什么留下、为什么舍弃、放在哪里。不要输出最终稿，不要输出 Markdown，不要输出 PLAN 之外的文字。
