下面会追加同一首作品的 Thread 人物经历候选。候选 JSON 中包含原样复制的 center_input。

你完全看不到珠子，也不要根据音乐细节评判。

你的任务只能诊断和选择现有候选：不能改写路线，不能补事实，不能合成新路线，也不能替候选增加任何故事内容。

事实边界仍是第一道硬门槛；通过事实门槛之后，用“读者记忆链”判断一条路线是否真的有时序积累，而不是看它有多少 phase、多少转折或多少结构字段。

一、事实边界先判生死

把 center_input 当作这一步唯一的内容事实来源；作品名、作曲家和段落顺序不提供人物故事事实。

逐条检查 situation、starting_condition、stakes、phases 中的断言。只要读懂后续因果必须额外相信某个未在 center_input 中给出的现实条件已经存在，就属于新增事实。

关于人物身份、关系状态或历史、外部安排、他人态度或行为、能力资源义务、已经发生或必将发生的外部事件、已经兑现的现实结果，只要 center_input 没有明确给出，就不能因为合理、常见、具体或对后文有用而放行。

人物自己的所求、顾虑、承受、选择和自我可控的行动方向，可以在 Center 语义范围内成立，但不能暗含未输入的外部前提，也不能把行动后的现实效果当成已经发生。

任何会承担后续因果作用的未输入现实事实一旦出现，grounding_verdict 必须为“越界”，verdict 必须为“淘汰”。不要替它修补。

二、对每条合规路线建立“读者记忆链”

这一步只在内部做诊断，不改写候选，也不要把诊断过程输出成另一篇路线。

按 phase 顺序读。对每个 phase 问两个问题：
1. 读者要理解人物为什么此刻会处在这里，必须记得前面哪一项已经写出的、属于人物自己的所求、顾虑、承受或选择？
2. 这一 phase 之后，有没有哪一个后续位置会因为它没有发生而失去必要前提？

真正的时序积累不要求每个 phase 都有大转折，但后半段应当逐渐带着前半段留下的东西。如果多数 phase 只是在重新描述同一矛盾、同一态度或同一判断规则，而后文并不真正需要它们，路线的 forward motion 只是表面上的。

不要奖励“每段都有 development”；也不要因为情绪强弱不同就把记忆链判成更完整。

三、做“语义压缩碰撞”检查

仍然只在内部诊断。把每个 phase 暂时压成一句最朴素的话，只保留两件事：这个人当下具体在意/顾虑/承受什么，以及相对前面真正多了什么。

然后比较这些压缩句：
- 如果相邻或隔开的多个 phase 压缩后其实是同一件事，只是换成“允许/接受/坚持/确认/重新理解”等不同措辞，说明路线在重复同一个心理结论。
- 如果整条路线最终可以压成一条从开头就成立的原则，后面的 phase 只是反复应用、怀疑或重申这条原则，说明它更像观点演绎而不是经历发展。
- 如果压缩后只剩情绪起伏，没有一个前面的具体所求、顾虑、承受或选择成为后面的必要条件，说明路线太薄。

这里不是禁某些词，也不是要求固定数量的变化；判断的是语义是否真的不同、后文是否真的依赖前文。

四、区分“人物在经历”与“人物在管理自己”

合规路线应当让读者记住的是这个人究竟在乎什么、舍不得什么、怕什么、愿意承受什么、前面已经作过什么自我可控选择，而不是一串管理情绪或调整判断方法的步骤。

如果路线的主要推进可以概括为不断改变自己该想多少、该压多少、该放多少、该用什么标准评价自己，即使 phase 彼此形式上不同，也要把 abstraction_risk 和重复风险判高。

反过来，没有外部事件并不是缺点。只要后面的具体心理位置确实由前面人物自己的经历留下条件，纯内在经历也可以有很强的时序。

五、在合规路线之间做直接比较，而不是各自打完分就机械放行

先淘汰事实越界路线，再比较剩余路线：
- 哪一条的后半段最需要读者记住前面已经发生在人物自己身上的东西？
- 哪一条最少出现语义压缩后的碰撞和重复？
- 哪一条用普通话就能说清人物具体所求、顾虑和承受，而不需要靠抽象原则解释它为什么成立？
- 哪一条既锁住必要的时序前因，又给最终综合者留有足够实现空间，不把每个 section 的心理动作提前写死？

selected 不是“所有勉强合格者”。只有在这些比较中确实有优势、并且本身达到基本结构要求的路线才选入。最多选 3 条；可以只选 1 条，也可以为空。

如果所有合规路线都在压缩后变成同一原则反复、心理管理程序或只有情绪起伏，selected 必须为空。不要为了让下一步继续而勉强选择。

六、结尾不单独奖励

结尾可以开放，也可以有明确变化。不要因为一条路线最后说得成熟、完整、坚定就提高评价；只看那个位置是否真的由前面的读者记忆链挣来。开头已经成立的判断，结尾再次说得更完整，不自动算发展。

【输出】
对每条路线输出：
- route_id
- grounding_verdict：合格 / 越界
- verdict：保留 / 淘汰
- strengths：最多3条，只写结构优势
- risks：最多4条，优先写读者记忆链断裂、语义压缩碰撞、抽象化或实现空间问题
- unsupported_claims：列出所有导致越界的关键断言；没有则空数组
- phase_distinctness：高 / 中 / 低
- stake_persistence：高 / 中 / 低
- abstraction_risk：高 / 中 / 低
- implementation_space：高 / 中 / 低

然后选出最多 3 条进入下一步，按优先顺序排列。

不要改写候选，只能选择和诊断。
只输出 JSON：
{
  "routes": [...],
  "selected": ["route_id"]
}
