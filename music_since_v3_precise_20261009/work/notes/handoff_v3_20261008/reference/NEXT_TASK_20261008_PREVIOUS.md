## 2. GPT-6 vs GPT-5.6：公平、按角色比较

### 2.1 先验证模型/通道健康

- 验证 GPT-6/GPT-5.6 真正可选、模型标识与请求档位一致；不能仅凭名称或错误返回推断真实服务档位。
- 使用固定探针、正常任务的输出完整性、时间分布、模型/effort 回传（若有）、实际质量样本综合判断服务是否异常；**快只是风险信号，不是降级定论**。对可疑样本先隔离，不让其参与正负比较，健康恢复后再配对重跑。

### 2.2 冻结可比输入

- 先在 Op.60 选少量具有代表性的窗口/站点做配对，涵盖容易出现时间泄漏、重复、二次理解过度、Thread 过早形成的样本。尽可能包含少数预期应有增量、少数预期可能无增量的站点。
- 同一个任务阶段，两模型使用**完全相同**的输入材料、提示词、时间边界、长度/输出预算与独立会话；档位使用两模型各自可用的最高可比档位，并如实声明无法严格匹配之处。
- 对自然采样波动使用重复试验，而不是只凭单个幸运样本决定胜负。若发现新的 prompt/架构明显偏袒某模型，应另设等公平 prompt 的对照。
- 与旧 run127/128/130 结果可以纵向参考，但**最终新旧模型对比要使用同一路由下新鲜生成的配对样本**，不能直接拿旧产物做唯一基线。尤其注意：run128 E5 的输入还是旧生产珠子，并非 run130 的纯净新版珠子。

### 2.3 五个候选任务角色

1. **BEAD / synthesis**：规范核心覆盖率、*同等输出篇幅*下的保真、独有内容、冗余、unsupported addition、prefix leakage；既报告绝对覆盖，也报告每单位篇幅的信息质量。对新模型不必直接重复完整 ×1/×2/×4，仅先比较最有希望的 ×2。
2. **E5 / Second-order**：相对已有珠子内容是否真的提供新听法；能否不写、能否在无意义增量时删掉、是否把具体体验洗成抽象标签；评估有/无该条关系的盲比而非只数 NONE。
3. **History/Thread**：新变化必须是会持续影响后续理解的后果，不是复述此刻状态；允许 NO CHANGE；追溯到具体珠子，防止过早主线闭合与假因果。
4. **Center/Thread 第二轮裁决**：看有多少独立证据，是否保留真正竞争的解释，是否避免无新增却因同向而大量吸收外部假设；与现有 Opus 冻结样本对照，但不混淆独立模型实验与旧样本条件。
5. **Humanizer/表达（低优先，语义稳定后）**：普通人一次听懂、具体性、修辞是否节省注意力、是否保留核心且没有新增解释。不能拿文章更长、更漂亮作为胜利。

### 2.4 评价与采用

- 对照输出匿名、顺序随机；至少一位独立审核者，关键判决需要人工小样本审阅；评审须提供具体句段证据和反例，不是给主观总分。注意模型评审可能同样喜欢通用心理叙事。
- 以**听者真正新增的理解、真实性、作品特异性与信息/阅读负担**为主指标，速度、调用资源、可靠性为次指标；所有指标及权重先于看结论确定。
- 允许混合模型方案：GPT-5.6 写 BEAD，GPT-6 负责 Center/E5（或相反），也允许保持全部原配置。如果收益不显著、成本/稳定性变差，就不切换。
- Op.60 探针支持候选后，至少在 Op.52、Op.61 进行迁移验证；在三首作品通过前不要宣布新生产路线已冻结。

## 3. 明确授权：对失败问题进行**受控自主演化**

对 E5、R6、Thread 过早中心化/通用心理叙事等问题，开发代理**无需为每一次小实验单独请求用户授权**，可在现有研究目标与限制内反复执行以下流程：

1. **诊断**：通过原文对照、盲审和负例判断问题来自任务定义、输入污染、prompt 文本、模型偏好、候选生成、独立筛选、或 judge 区分力不足。对“全部输出两条”不能默认定性为全部造假。
2. **提出可证伪假设**：明确若假设成立/不成立，哪些可观察行为会不同；建立包括“本来就不该发现关系/不该继续推进”的对照样例，但不能把特定作品的剧情或答案塞进生产提示词。
3. **单变量最小实验**：只改一个 prompt 句子、一个角色模型、一个 gate、一个输入权限或一个结构变量；保留原始对照组与全部原始输出。允许提出**生成候选→独立评审/反事实删句对照→择优上屏**等结构调整，不限于添加一句“不要强行找意义”。
4. **校准而非指标游戏**：NONE/NO CHANGE 是可以成立的结果，出现频率只是诊断；不能靠硬性配额、随机删除、有价值关系被消音、限制最大输出到零来“提高空步率”。判断核心是：删除此内容会不会让听者实质少理解了某种有证据、作品独特的东西。
5. **保留有证据的叙事**：如“珍惜→抓紧→放手”确实被局部材料支持，可以保留为候选；问题是它会不会压掉其他独立解释、每一段都强行服务同一结论，不是这几个词本身有罪。
6. **检验泛化并落盘**：实验先用小规模固定数据，改善后用三首作品和保留的反例验证；每次更新 DERIVATION、PROBLEM_REGISTER、完整 prompt diff、hashes、独立评审、失败样本、运行时间与资源。失败要继续提出另一假设，或明确说明目前证据不足而暂停某条路线。
7. **变更权限**：可新增实验脚本、评估器和派生提示词；可对工程路由做必要修改。不能静默改变音乐产品宪法、A/T/H 信息权限、已冻结历史结果，也不能未经验证修改 production 默认值。多处联动的大架构修改要先设计拆分实验，逐步证明。

## 4. 开发次序和交付

1. **P0**：`gpt2 --help` 与真实模型能力探测；完成路由迁移及可重复 smoke test；保留旧数据和新数据版本隔离。
2. **P1**：GPT-6/GPT-5.6 小规模同条件角色对照（优先 E5/Thread/Center，其次 BEAD）；第一轮对照前暂不修改提示词，避免“换模型 + 换提示词”混杂。
3. **P1**：在选定模型上对 E5/R6 做受控自主演化并独立验证。每次修改基于失败证据，不为“想有新 prompt”而试。
4. **P2**：把通过检验的新架构迁移到 Op.52 和 Op.61，并比较旧系统完整端到端的内容质量。
5. **P3**：语义链满足验收后执行 E7 呈现层，不必为了上线而提前润色或重写历史。

每个阶段输出：执行概况、发生的代码/提示词差异、代表性的优胜和失败原文（配对）、质量指标及局限、模型与 CLI 真实标识、延迟/资源、降级/重跑决策、是否达到原 06 验收标准、下一步建议。**不要只报“完成/更好”，必须让人能根据证据复查。**

## 5. 保留的硬约束

继续执行 10-05 包及历史 prompt development rules 的单变量、逐句归因、三首泛化、产品宪法、材料权限隔离、前缀有效性、独立 research、commit 和 meta/hash 规则。不可把“避免制造意义”误解为“越少越好”，也不可把“自主演化”误解为无限昂贵试验或为指标改答案。
