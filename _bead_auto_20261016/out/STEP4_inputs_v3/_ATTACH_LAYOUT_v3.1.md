# STEP4 附件收纳决策 v3.1（2026-10-17，字节上限下的取舍）

**触发证据**：STEP3 复核 A 车道 init 失败 `native_body_size_invalid`（gpt2 实测 67,003B 预提交体被截断），
而 B 车道 60,111B 通过 → 判定门槛 = UTF-8 字节数（非字符数），上限在 60k–67k 之间。
初版 14 份 STEP4 prompt 为 107–136k 字节，全部超出。

**决策（按影响排序）**：
1. **GLOBAL 55 条不随任何车道收录**。理由：全局条目按评审定义"不进读者正文"，只作写作底色；
   每车道全文收录需 59k+11k 字节/场，单它就爆上限。全量逐字文本保留在 `A_POOL_MAP_v3.json` 的
   `global` 部分（未删、未改）。车道内第五部分只留指针与硬约束（珠子引用必须出自车道可见条目，
   禁止引用未收录正文、禁止自行编造整曲总述）。
2. **WIDE 跨段条收纳**：覆盖 ≥4 段的交叉单元（23 条）全文只进其首个覆盖段（按 S01–S14 序），
   其余覆盖段仅留头行标记（含"不得引用或扩写该单元正文"硬约束）；覆盖 ≤3 段者维持每段全文逐字重复。
   单车道超 60,000B 时对该车道降级为 ≥3 段即 WIDE（触发者：S02、S13）。
3. **来源清单去长磁盘路径**（交付文档 §2 已含全部路径+SHA），车道内保留 model｜channel｜run｜SHA12。

**尺寸结果**：14 份 prompt 全部 ≤59,301B（max S02），低于实证通过点 60,111B。

**对溯源的影响**：珠子输出若涉及 WIDE 条而该车道只见头行 → 该珠子必须在溯源表标记
"仅头行可见"（扫描输出时核对）。GLOBAL 条目本轮未进任何珠子（车道不可见）。
