# Claude 主控 × T3Code 免费 Muse：已确定的调用契约

## A. 必须遵守的 Muse 路由

用户已确认：T3Code Claude Custom 内部的 `delegate_task` 可以调用 Muse。**这件事视为已知配置，不安排重复“证明能不能调用”的研究任务。** 真正调用失败才排障。

为每一个新的委派构造 `delegate_task` 调用，按当前实际工具 schema 填写 target：

```json
{
  "providerInstanceId": "claude-proxy",
  "model": "muse-spark-1.3-contributor-free",
  "options": {"effort": "xhigh"}
}
```

上面仅是 **target 值**，不是对整个 `delegate_task` 工具签名的猜测。`clientRequestId`、任务内容等其他字段应按实际 T3 工具 schema 传。每次新任务/独立 review 使用**新的唯一 `clientRequestId`**；**不要通过 `childThreadId` 续聊上轮 review**。如需要后续核查，新开 Muse 任务，提供上轮输出文件路径与待验证问题。

禁止：`providerInstanceId = "muse"`（禁用的 Muse Code provider，必失败）、自动转 OpenCode、静默用 Claude/Opus 顶替廉价 Muse。若工具真的报错才检查配置/上游，并将故障报告为故障；不要为“验证”先消耗 Claude 大量 token。

## B. 资源原则（本轮最重要变更）

- 用户授权按 **Muse 货币成本近似为 0** 规划：无需设“最多调用 N 次 Muse”的预算，也不需要为了少创建子代理牺牲搜索、工程测试、反事实验证或独立探索。
- 但**免费 ≠ 无并发/耗时/上下文代价**：并行量由实际工具限制、机器/后端稳定性、互斥写入和实验依赖决定；别让数十个子代理争写同一文件或回传长篇废话。
- 要省的是 Claude 主会话的重复理解、读取、漫长 review、模型调用和错误决策。Claude 保留足够注意力给作品鉴赏与研究判断，而不是兼做日志分析员。
- 相互独立的 Muse 任务可大量并行：代码搜索、历史基线索引、GPT2 移植、测试自动化、样本抽取、全量覆盖核算、质量反例挖掘、对抗评审、实验报告质控。结果归档后再统一投喂 Claude **信息差异**，而非所有代理全文。
- 可让多个 Muse 对同一假设提供**彼此隔离的不同证据/反例**。但不能把多个 Muse 同意当作独立的高质量审美裁决。

## C. 主会话保留与下放

**Claude 亲自做**：理解宪法/历史好稿、确立用户目标；选择下一个高价值可证伪问题；冻结比较条件；批准研究提示词/架构差异；审关键原文；解释成功/失败；决定 production 是否可切换；更新项目状态与任务优先级。

**Muse 做**：任何不依赖最后审美裁决的工程、数据、资料定位、候选方案探索、反例搜索、评审材料匿名化、生成任务排程、实测结果归档、HTML 查看页（若适合也可调用既有 Gemini 路由）、运行恢复、发布打包。Muse 可以提出改法，不能自行宣布内容系统“成功”。

**其他模型**：GPT-6/5.6 网页模型经 `gpt2` 产内容/对照，Opus 可作为实质内容候选或深度评审，Luna 可做独立严肃资料检索。主 Claude 不亲自写参评综合稿；同一输出不由其生成模型自身宣称获胜。若某旧 runner 不健康，隔离相关调用并说明，不要默认今天所有旧路由还可用。

## D. 两层回传，不占 Claude 主上下文

1. Muse 每个任务必须把完整实验/日志/生成原文/代码 diff 写磁盘，提供文件路径、运行 ID、哈希与通过状态。
2. 一个子代理正文回传**优先 ≤8 行**，至少覆盖：做了什么、测试/完成状态、最重要的可验证数字、最关键失败或反证、下一动作与具体文件路径。
3. 多个 Muse 回来后，可再开一名免费 Muse 做**证据索引/去重/差异汇总**，输出一个短 decision packet；Claude 只审这个 packet 和 2–3 组真正能改变选择的原文（如果出现分歧就加样本）。
4. Muse 不可用不带原始路径的口头断言替代证据；Claude 不需要先通读所有子代理的 log 才能裁决。
5. 长任务必须有可恢复的命令、检查点和 DONE/FAILED 状态，不能假设随 `delegate_task` 子会话结束，`go.py` 等后台任务仍存活。需要时按本机已验证的持久进程启动方法重启并写明 PID/日志/结束判断。

## E. 正确并行与唯一写入

- 给代理分派工作包时明确可写的目录和只读输入；相同生产提示词、runner 核心和 manifest 只允许单一 owner 写入，其他代理用隔离分支/目录提出 patch。
- 对同一关键问题并行创建相互独立的“找支持”和“找反证”任务，减少确认偏差。禁止不同代理共享上一名的结论后再冒充独立盲审。
- 真正需要审美综合时，Claude 自己读少量原文；若判断不稳，再让不同模型分别评审，评审规则应一致。

## F. 一轮研究怎样结束

Claude 每次最终输出一个决策：**采用 / 未通过、继续新假设 / 暂缓且有证据 / 需要外部授权**。再由 Muse 更新 run 清单、DERIVATION、问题表、状态短文件和 ZIP。下一个实验在同一会话自主启动；不要到每个阶段都等待用户指定下一步。没有理由的“做完这组实验了，我还可以继续吗？”不可接受。
