# 大众版视频流程（11-05）

从已定稿的线和珠子生成给大众看的版本。全程只用脚本和 gpt3，没有人工选择。要做到什么看 `大众版标准.md`，用户原话在 `用户判定.md`。

## 现在的做法

| 步骤 | 做什么 | 谁做 | 命令 |
|---|---|---|---|
| 音乐数据 | 已对齐的 MIDI、小节表、录音 → 音符数据，再校正起音 | 脚本 | `prep_music.py`、`align_music.py` |
| 拆要点 | 珠子按句拆开，对回局部时间 | 脚本 | `pub2.py prepare`（新作品 `op52_up.py src`） |
| 独立排序 | 只看原文，定“不能掉” | gpt3 ×4 | `pub2.py rank` |
| 分组和情绪 | 每段几组、每组情绪色 | gpt3 | `pub4.py` |
| 拆词 | 只从定稿的珠子拆词 | gpt3 | `pub11.py` |
| 词做减法 | 同一感受只留一个说法，不新写 | gpt3 | `pub14.py` |
| 补丢的要点 | 两位评委都判“没有”的要点，从已拆的词里补回 | 脚本 + 覆盖评审 | `pub17.py`、`pub_cover.py` |
| 线 | 逐字用定稿，一条线一组，顺序不动；词按已有匹配放到线旁边 | 脚本 | `pub19.py` |
| 明确指向 | 只有词本身指向某个声音才动音乐 | gpt3 | `pub18.py explicit` |
| 交界 | 哪些词块同时属于相邻两条线 | gpt3 | `pub9.py` |
| 渲染 | 音乐画法同 `film_pub.py`，用 `*_music_aligned.json` | 脚本 | `film_v6.py render` |

## 新作品的上游

`seg.py research` → `pick_upstream.py seg`（按每段时长选公开分段）→ `op52_a.py`（24 份 A 稿）→ `chain.py production`（珠子）→ `center_from_A.py`、`center_dag.py`（注意：Center 归纳要 `THREAD_ROUTE=gpt3`，默认路由会丢附件）→ `pick_upstream.py center` → `op52_up.py lines`（N05a–d 写线）→ 上面的流程。`public_flow.sh` 串起其中大部分。

没跑的步骤：N03i 珠子语言（Argon 走的代理连不上）、N05e–g 线的成品修补。Op.52 的线是 N05d 首稿，比船歌、幻想的 r78a 少修很多轮。

## 测什么

- 对原稿（珠子+线）的覆盖率：`pub_cover.py`。
- 有时间压力的读者：`pub16.py timed`。
- 直接测异质、压缩、独立、和珠子关联：`pub18.py four`。
- 人话：N09 开放评审和句式统计，和定稿同样测：`pub18.py lang`。人称不是指标。
- 词读得懂吗：按屏幕分块盲读再比对原稿：`pub12.py test`。

## 试过没用的

- 把线拆成多条（w8）：零碎。
- 让模型修长读不懂的词（w8）：更难懂。
- 整篇给模型重拆词（w7）：字少但不比现有的好懂。
- 按秒数压线（w16–w21）：字数压到 54–71%，但单独读、人话、对定稿 8 票都输，用户看了也觉得不如 r78a。
- 情绪配色、脉动、光柱、方框（film_v5）：用户说太花哨、意义不明。
