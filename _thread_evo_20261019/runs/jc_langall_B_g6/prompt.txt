评审分成三个步骤：

第一步：连续阅读整篇。

先从头到尾阅读，把它当作一段完整的叙述，而不是一组需要逐句批改的句子。

注意实际的阅读体验：哪些地方自然流畅，哪些地方读着费劲，整篇读完后有没有留下明显的不舒服、不顺畅或者单调的感觉。

此时先不要着急改写句子，也不要预设问题类别。

第二步：检查局部语言。

逐处指出真正读起来不通顺、不像人话、让人别扭或需要停下来想一想的表达。

每处引用原文，说明为什么不自然，并给一个更自然的说法。

只指出实际存在的问题。没有问题的地方不用提，不要为了凑数挑毛病。

改写时尽量保留原句的意思、人物的心理区别和前后关系，不要为了让句子好听而擅自改变人物经历。

第三步：独立检查整篇的累积效果。

这一步很重要。请暂时放下第二步挑出的具体问题，重新从头到尾看整篇。

检查是否存在这样的情况：某一种写法单独出现时并没有明显错误，甚至完全自然，但在多处反复出现之后，让整篇的阅读体验变差。

不要只寻找单句中的错误，也不要只把第二步的问题重新归纳一遍。要真正检查连续阅读时产生的效果。

对于发现的每一种累积性问题：

1. 引用多处原文作为证据。如果问题跨越全文，尽量选取不同段落的例子；如果问题集中在同一小节，可以引用几句相邻的原文。
2. 解释为什么这些表达连起来会造成问题。不能仅仅因为某种写法出现次数多，就认定它不好。
3. 区分这种写法在哪些情况下本来是自然、必要或有效的，哪些地方才是真正多余或影响阅读的。不要把所有相似表达一律判错。
4. 说明这种累积问题的实际影响有多大，是轻微、中等还是严重。
5. 如果值得修改，提出具体的改进方向，并选择一两个代表性位置示范改写。不必机械地修改所有同类表达。

不要预设必须找到多少种累积性问题。某一种写法反复出现也可能完全合理，甚至是叙述所需要的。如果没有充分证据，就不要把它列为问题。

最后作出整体判断。

给语言质量打 1–10 分。

说清楚最影响阅读体验的是什么，哪些是次要问题。不要因为某类问题比较容易统计、比较容易举例，就高估它的重要性。

请特别注意：局部语言问题与全文累积问题是两种不同的判断。前者需要证明那句话本身不自然；后者需要证明多处表达连起来产生了不理想的效果。一种表达即使单独没有问题，也可以成为累积问题的证据，但必须讲清楚累积影响。

# 1. 究竟是评委的问题，还是我们的预期错了？

## 1.1 先看两种可能分别有哪些证据

<badge color="success">我的判断：提示词错配是主因</badge>

但评委并非完全没有发现真实问题。

### 可能一：评委确实发现了真实的语言问题

有些例子，我认为评委的怀疑是合理的。

例如：

- 「身体先记起舞步 / 隐约记起步子」
- 「雷鸣般铺满全场 / 声势一下占满」
- 「忽然能喘口气 / 胸口忽然松开 / 只是一瞬喘息」

这些表达之间确实存在较高的语义重叠。

如果两颗珠子在同一个簇内，表达同一瞬间、同一个体验，且后一颗没有增加新的感受、意象、身体反应或强度变化，那么它们可能是冗余的。

还有一种值得注意的情况：线和感受碎片重复解释同一件心理事情。

例如：

- 线：「难受慢慢缓下来，这回他没再用受过的委屈压住想念。」
- 感受：「不用解释难过 / 不用维持坚强 / 压住的愿望 / 没说出口的委屈 / 藏着的思念 / 终于浮现出来」

这里确实有可能出现两层文字都在解释同一件事的问题。

所以，不能因为盲比喜欢保留碎片，就认为所有重复表达都是好的。

### 可能二：评委把有价值的叠加误判成重复

这一点，我认为目前的证据更强。

看几个例子。

**例子 A：S01**

「心里堵着 / 说不清是愤怒 / 还是遗憾 / 又像怀念 / 找不到说法」

评委将其概括为多个近义短语解释同一种心理状态。

但实际上，这里面至少包含：

- 心理上的压迫感；
- 对情绪性质的不确定；
- 愤怒；
- 遗憾；
- 怀念；
- 无法准确表达。

愤怒、遗憾、怀念不是同义词。

而且，这个簇可能正是在表现一种复杂、混杂、无法准确命名的情绪。

其中「说不清」和「找不到说法」可能存在重复，但不能因此把整个簇定性为表达过密。

**例子 B：S07**

「寒意刺骨 / 像寒风灌进来 / 窗户被猛地吹开 / 甜梦一下碎了 / 被拽回严寒 / 后颈一阵凉」

这组文字并不只是重复表达寒冷。

它有一定的感受发展：

- 寒冷的强度；
- 寒风侵入的画面；
- 突然发生的变化；
- 梦境破碎；
- 被拉回现实；
- 身体上的凉意。

这可能是一组有意构成的意象链。

如果把它全部理解为「连续换词表达寒冷」，就丢失了这些表达之间的功能差异。

**例子 C：S07**

「颤音不断 / 思绪翻来覆去 / 身体还不信已结束 / 心里仍在发颤 / 想冲出去 / 惊醒后的紧张 / 迟迟平复不了」

这里至少涉及：

- 音乐本身的声音特征；
- 思维状态；
- 身体的残留反应；
- 情绪状态；
- 行动冲动；
- 持续时间。

它们并不都是同一个维度的重复。

评委似乎把它们都抽象成了「紧张」，再据此判断表达过满。

这是一种重要的误判机制：

**先把多种不同的具体体验归纳成一个抽象情绪，再把这些具体体验之间的相似性当成重复。**

而感受碎片本来就可能需要从多个角度表现同一个时刻。

## 1.2 盲比结果说明了什么？

你们的实验提供了一个非常重要的外部证据：

原来新版在盲比中有优势；按照评委的意见删除同簇近义碎片后，新版被选中的票数从16降到了9。

我认为这至少说明：

1. 这些碎片并不只是无用的文字冗余。
2. 它们可能提供了丰富度、情绪层次、意象密度和阅读节奏。
3. 评委所认为的「更精简」，不一定对应观众认为的「更好看」。

但这里也需要保持谨慎。

盲比结果不能证明每颗珠子都应该保留。删除操作可能同时减少了信息量、视觉丰富度和情绪层次，不一定是某个具体近义词导致了偏好变化。

所以，这个结果支持的是：

**不能根据评委识别出的语义相似性，直接执行批量删珠。**

而不是「所有叠加都是好事」。

## 1.3 同一个 w23 在0—2条之间跳，是一个更严重的问题

我认为这条证据甚至比前面的盲比更值得重视。

假设：

| w23 某次评审 | 中等以上问题数 |
|---|---:|
| 第一次 | 0 |
| 第二次 | 2 |
| 第三次 | 1 |
| 第四次 | 0 |

那么，如果新版有1条问题：

- 拿第一次的 w23 比，新版不通过；
- 拿第二次的 w23 比，新版通过。

这意味着当前的门槛有相当一部分取决于评委这次怎么组织语言、怎么归纳问题。

而不是取决于屏幕稿真实发生了什么变化。

尤其是你们使用的是「问题条数」，而不是某种稳定的评分。

这里有三个不稳定来源：

- 同一种现象可能被归纳成一个问题，也可能拆成两个问题。
- 严重程度没有可操作的判定标准。
- 模型可能一次把某种现象看作有价值的变化，另一次把它看作重复。

因此，当前的评委不仅存在误判，还存在测量重复性不足。

## 1.4 最终判断

我会这样划分：

| 判断事项 | 我的结论 |
|---|---|
| 某些珠子存在真实语义重复 | 是 |
| 近义表达反复出现必然是累积问题 | 否 |
| 评委能准确识别有害的累积重复 | 目前证据不足 |
| 盲比支持保留一定的情绪叠加 | 是 |
| 删除近义珠子一定提高语言质量 | 否 |
| 当前问题条数适合作为硬门槛 | 否 |

**核心判断：你们的预期有一部分错了，但更主要的问题是评委把「连续散文的累积重复」错误地套用到了「分簇感受碎片的叠加」。**

# 2. 提示词的根因在哪里？

我认为有五个具体问题。

## 根因一：任务对象的定义错了

原文：

> 请阅读下面这段中文。
>
> 它是一条跟随音乐发展的“线”：写的是一个人在这首曲子里经历的一件事，按段写成条目。

这段话实际上是在描述「线」，不是在描述整屏。

但是你们现在把线和感受碎片拼在一起交给评委。

评委收到的任务定义仍然是：

「这是一条跟随音乐发展的线。」

它并不知道自己正在评审的是：

- 一条主要叙事线；
- 几组并列的感受碎片；
- 不同听众的感受；
- 按珠子聚集的视觉结构；
- 供观众一边听音乐一边扫读的屏幕稿。

这不是小问题。

因为不同结构的语言，应该采用不同的质量标准。

连续叙述中，连续使用三个近义短语，可能显得啰嗦。

但在一个感受簇里，三颗短珠可能分别提供身体感受、情绪变化和具体意象。

不能使用同一个判断标准。

## 根因二：「连续阅读整篇」与实际观看方式不一致

原文：

> 把它当作一段完整的叙述，而不是一组需要逐句批改的句子。

这是整个提示词中我认为最需要修改的句子之一。

你们的实际观看方式是：

- 观众同时听音乐；
- 线提供主要的故事发展；
- 感受碎片是散开的；
- 观众在音乐进行中扫读；
- 每个小块都很短；
- 不要求观众把所有小字连起来读成一段话。

而提示词要求评委把所有文字作为完整叙述连续阅读。

这会产生一个非常自然的偏差：

评委会将空间上分开的珠子，转换成语言上连续排列的短语。

于是它容易认为：

「这些表达连起来有点重复。」

但观众实际看到的可能是一个视觉上丰富、可以分别感受的簇。

**评委评审的文本阅读方式，与观众实际使用屏幕的方式不一致。**

## 根因三：第三步给累积问题过强的注意力

原文：

> 第三步：独立检查整篇的累积效果。
>
> 这一步很重要。

以及：

> 某一种写法单独出现时并没有明显错误，甚至完全自然，但在多处反复出现之后，让整篇的阅读体验变差。

我认为这是造成当前症状的直接诱因。

它实际上要求模型专门寻找：

「单独看没问题，但重复出现后可能有问题的现象。」

这本身是合理的设计。

问题在于，它没有给模型一个足够明确的正向判定标准：

**什么情况下，反复出现是有价值的？**

虽然原文有：

> 不能仅仅因为某种写法出现次数多，就认定它不好。

但这只是一个消极约束。

它没有要求评委逐一分析每颗珠子增加了什么信息。

于是模型很容易采用一种简化判断：

- 这些表达有相似含义；
- 它们出现在多个位置；
- 它们都能归纳为同一种情绪；
- 所以形成了累积问题。

这正是 g6 和 g56 的共同表现。

## 根因四：没有规定线与感受碎片的功能分工

原提示词没有定义：

- 线应该承担什么；
- 感受碎片应该承担什么；
- 两者之间允许有多少语义重叠；
- 什么样的重叠是补充；
- 什么样的重叠是重复解释。

这就导致 g6 和 g56 都出现了一个问题：

把线与感受表达同一情绪，直接视为双重说明。

但两者本来就可能有合理的重叠。

例如：

- 线：描述一个人想起过去的经历。
- 感受：表现这段音乐让听众产生的怀念、温暖、刺痛。

两者主题相近，但功能不同。

当然，如果感受碎片只是在换词复述线里的心理解释，也可能确实冗余。

需要评委判断的是功能，而不是只判断语义相似程度。

## 根因五：严重程度和问题条数没有校准

原提示词要求：

> 说明这种累积问题的实际影响有多大，是轻微、中等还是严重。

但是没有定义什么叫中等。

例如：

- 一个簇里有三颗近义珠子；
- 全文有四个不同簇都出现情绪叠加；
- 多个段落都使用同一种表达结构。

这三种情况不应该自动得到同样的严重程度。

另外，提示词要求模型归纳问题，却没有明确规定同一根因只能算一条，也没有规定跨段证据和单簇证据的权重。

这会导致问题条数不稳定。

还有一个次要但值得修正的细节：

提示词要求打1—10分，但 JSON 示例里 `"score": 0`，存在形式上的冲突。虽然不一定是本次问题的根因，但最好一起修正。

# 3. 怎么改？

我建议不是给旧提示词打补丁，而是把整屏评审重新定义为：

**整屏扫读体验评审，而不是整屏连续文本的人话评审。**

原来的「线的人话」评委可以保留，继续评审线。

整屏评委则应当专门判断：

1. 线与感受碎片的分工；
2. 感受簇内部的表达质量；
3. 不同簇之间的累积效果；
4. 观众扫读时是否产生实际负担。

## 3.1 直接替换的提示词关键段落

下面这段可以作为整屏评委的核心提示词，替换原提示词中的对象定义、第一步和第三步。

<WritingBlock id="63182" variant="document"># 评审对象与观看情境

请评审下面这份供大众观看的钢琴曲「边听边看」视频屏幕稿。

它不是一篇连续散文，而是一种配合音乐、供观众边听边扫读的屏幕表达。

每个段落对应音乐发展的一个时间段，包含两种不同的文字：

**1. 线**

用较大的文字呈现，写一个人在这首曲子里经历的一件事，按音乐发展推进。

线承担主要叙事功能，让观众能够理解这个人的经历和心理变化。

**2. 感受碎片**

用散开的小字呈现，是几位听众在这一刻产生的感受。每颗珠子都很短，同一簇的珠子在视觉上挨在一起，每块不超过8个字。

感受碎片不要求组成完整句子，也不要求所有珠子连起来构成一段连续叙述。

它们可以分别提供情绪、身体感受、声音联想、具体意象、瞬间反应和心理变化。

观众一边听音乐，一边扫读屏幕，不一定会按照文本顺序逐字读完所有碎片。

**评审时必须尊重这种表达形式。**

不要把整屏文字当成一篇连续散文。

不要因为几颗珠子表达了相近的情绪，就自动认定它们是重复。

不要把短语、意象、身体反应和心理感受都抽象成一个宽泛的情绪词，再以它们表达了同一种情绪为理由判定冗余。

如果没有提供音乐或实际听感记录，不要自行推断某种重复是否对应音乐中的重复乐句。

# 第一步：模拟真实观看体验

先从头到尾理解整份屏幕稿。

请分别理解：

- 线如何随着音乐发展；
- 感受碎片在各个时间段提供了什么；
- 线与感受碎片如何配合；
- 不同感受簇之间是否形成了有意义的变化。

评估时要模拟普通观众边听边看的体验，而不是模拟读者阅读一篇连续文章的体验。

特别注意：

- 线是否自然、清楚；
- 感受碎片是否容易扫读；
- 感受碎片是否提供了有价值的补充；
- 不同的珠子是否共同形成了丰富而具体的体验；
- 整屏是否存在真正影响理解或扫读的文字负担。

# 第二步：检查局部语言

分别评审线和感受碎片。

对于线，检查是否自然、像人平常会讲的话，是否存在不通顺或表达别扭的问题。

对于感受碎片，允许使用短语、意象、名词性表达、省略句和不完整句。

不要因为感受碎片不是完整句子而判定它不自然。

只有在表达本身确实难以理解、措辞不自然、意义含混，或者读者需要停下来反复猜测时，才指出局部问题。

# 第三步：独立检查整屏的累积效果

这一部分要检查真正影响观众整体观看体验的累积问题。

但必须区分以下三种情况，不能混为一谈。

**A. 同一个感受簇内部的重复**

检查同一簇中的几颗珠子是否表达了相近的内容。

判断时，先分别考虑每颗珠子是否提供了新的信息或体验，例如：

- 不同的情绪细节；
- 不同的身体感受；
- 不同的感官通道；
- 不同的具体意象；
- 情绪或动作的发展变化；
- 强度、时间或心理状态的变化；
- 对同一时刻不同角度的观察。

如果几颗珠子虽然意思接近，但各自提供了不同的感受层次、具体画面或表达节奏，不应仅因语义相似而判为重复。

只有当几颗珠子实际上反复表达同一个意思，后面的珠子没有带来有意义的新信息或体验，并且这种叠加确实增加了阅读负担时，才构成问题。

**B. 不同感受簇、不同段落之间的重复**

检查是否存在一种表达方式反复出现，导致整屏的感受变得单调、模式化或缺少变化。

但是，不能因为不同段落出现相近的情绪或意象，就自动判定为累积问题。

音乐发展中可能自然出现情绪的延续、回归和重复；不同听众也可能在相似的音乐时刻产生相似感受。

必须证明这种重复已经影响了整屏的变化、丰富度或扫读体验，而不只是指出相似表达出现了多次。

**C. 线与感受碎片之间的重复**

检查线与感受碎片是否各自承担了不同的表达功能。

线主要讲述人物经历，感受碎片主要提供音乐带来的感受和体验。

两者可以涉及相同的事件或情绪，但应当尽可能提供不同的表达价值。

如果感受碎片只是在换一种说法复述线已经完整表达的心理内容，没有增加新的感受、意象、身体体验或音乐体验，才构成真正的重复说明。

# 累积问题的判定标准

对每一种候选累积问题，都必须回答：

1. 具体哪些表达存在重复？
2. 每处表达分别提供了什么信息？有没有新增的感受、意象、角度或变化？
3. 为什么这些表达连起来会影响真实的观看体验？
4. 这种影响究竟是轻微、中等还是严重？
5. 哪些相似表达其实是合理的，不能一并删除？

特别注意：

- 语义相似不等于功能重复。
- 表达同一种情绪，不等于没有提供不同体验。
- 感受丰富不等于表达过满。
- 同一个情绪在不同时间反复出现，不等于整屏单调。
- 不能为了追求简洁而损失感受的层次、画面和音乐体验。

**严重程度标准：**

轻微：存在少量真实重复，但基本不影响扫读和整体体验。

中等：重复已经形成比较明确的负担，例如同一个簇内多颗珠子没有新增信息，或者同一种无效表达模式在多个独立段落反复出现，明显削弱了体验的丰富度或阅读节奏。

严重：重复已经明显妨碍理解、扫读，或者实质性破坏整屏的表达效果。

中等及以上问题必须有明确的实际影响，不能仅凭表达相似、出现次数多或可以合并，就判为中等问题。

同一种根因只归纳为一条累积问题，不要因为涉及多个段落而重复计数。

如果只能证明表达相似，却不能证明它损害了观看体验，就不要列为累积问题。

如果证据不足，允许没有任何累积问题。

# 最终判断

综合考虑线的自然程度、感受碎片的表达质量、线与感受的分工、感受簇的丰富度以及整屏的实际扫读体验。

不要把文字越少、重复越少直接等同于质量越高。

不要为了找到问题而寻找问题。

请判断哪些问题真正影响整体观看体验，并区分主要问题与次要问题。</WritingBlock>

## 3.2 我建议再增加两个输出字段

现在的 JSON 结构不足以帮助你们分析误判。

建议在每个累积问题中增加：

- `scope`：问题发生的范围。
- `confidence`：评委对问题判断的置信度。

例如：

```json
{
  "scope": "同一簇内部",
  "phenomenon": "同一瞬间的身体记忆被近义表达重复说明",
  "confidence": "高",
  "severity": "轻微",
  "evidence": [],
  "effect": "后两颗珠子没有增加新的体验信息",
  "boundary": "不同身体反应或动作记忆的变化不属于此问题",
  "suggestion": "考虑删减其中一颗"
}
```

`scope` 可以限定为：

- 同一簇内部；
- 跨簇、跨段；
- 线与感受重叠。

这样你们就可以知道评委到底在批评什么，而不是只看到一个宽泛的「情绪表达过密」。

另外，我建议不要再把所有中等以上问题都等价处理。

例如：

- 高置信度、中等问题：可以进入修改候选。
- 低置信度、中等问题：先人工复核。
- 轻微问题：不应仅因为出现次数多就批量修改。

# 3.3 怎么验证提示词真的改对了？

这里我建议做三个层次的实验。

## 实验一：同一版本重复评审，检验稳定性

<badge color="success">必须做</badge>

先用 w23。

保持以下条件完全一致：

- 模型版本；
- 提示词；
- 输入文本及其结构；
- 生成参数；
- JSON 输出格式。

连续独立评审10次。

不建议只测两次。两次只能发现特别明显的不稳定，不能充分判断问题归纳是否可靠。

重点统计：

| 观察指标 | 希望看到的结果 |
|---|---|
| 同一问题是否反复出现 | 高置信度问题应较稳定 |
| 严重程度是否变化 | 不应频繁在轻微和中等之间跳动 |
| 中等以上问题数量 | 不应出现大幅波动 |
| 具体证据是否一致 | 不应每次换一批完全不同的例子 |

我建议先采用一个实用的试运行标准：

- 明确的真实问题，在10次中至少8次能够识别；
- 已知的合理叠加，不应频繁被判为中等以上；
- 同一问题的严重程度应基本一致；
- 同一版本的中等以上问题条数最好控制在相差1条以内。

这不是普适的统计学标准，而是你们可以先采用的工程验收标准。

如果修改后的评委仍然不能稳定评价 w23，就不要急着拿它做新版门槛。

不要只用 w23 一个版本测试。

从已有屏幕稿中挑出20—30个片段，由你们自己或几位熟悉产品的人先做人工标注。

重点建立两种对照。

3. 能否区分线与感受的功能。

这里最好让人工标注者先独立判断，再讨论达成一致。

评委不能自己定义什么叫正确，否则只是自己验证自己。

## 实验三：做一次真正有针对性的盲比

你们已有的16票降到9票的结果值得保留，作为一个重要的历史对照。

但下一次建议不要直接比较：

- 原始版本；
- 删除所有近义珠子的版本。

因为这种改动太大，很难知道究竟是什么造成了偏好变化。

我建议准备三个版本：

| 版本 | 处理方式 | 要验证的问题 |
|---|---|---|
| A | 原始完整版本 | 基准 |
| B | 按旧评委意见大幅删减 | 验证旧评委的修改方向 |
| C | 只删真正没有新增信息的重复珠子 | 验证精准去冗余是否有益 |

盲比时：

- 音乐完全相同；
- 视频时长相同；
- 文字位置、字号、出现时间尽量一致；
- 观看顺序随机；
- 不告诉观众哪个版本是新版。

除了整体喜欢哪个版本，我建议再记录三个维度：

1. 哪个版本的感受更丰富？
2. 哪个版本更容易边听边看？
3. 哪个版本更自然，不觉得文字在刻意解释情绪？

这样才能区分「丰富」和「拥挤」。

如果 C 比 A 更好，而 B 比 A 更差，说明你们真正需要的不是减少近义珠子，而是减少没有新增价值的珠子。

## 3.4 最终门槛怎么设？

我建议保留「新版不能明显差于 w23」的原则，但修改判断方法。

不要再使用：

> 某次新版中等以上问题条数 ≤ 某次 w23 中等以上问题条数。

改为：

**先看评委稳定性，再看相对差异。**

具体：

1. w23 和新版分别重复评审10次。
2. 统计各自的中等以上问题数量分布，而不只是单次结果。
3. 对每一种问题归纳具体根因，比较两版是否存在真正的质量差异。
4. 对高置信度问题进行人工复核。
5. 最后结合盲比判断。

另外，你们已经有「原稿覆盖」「珠子严格覆盖」「精细体验」等其他评委。

这些评委应该继续各自承担自己的任务。

尤其是删珠子时，要确认没有损失原稿中的重要信息和体验。

**整屏人话评委不应该拥有单方面否决一组感受碎片的权力。**

# 4. 改完以后可能出现什么新偏差？

新提示词并不是没有风险。

我认为至少需要防范五种。

## 4.1 从过度删减变成过度宽容

原来是：

「相似就是重复。」

修改后可能变成：

「不同角度就是有价值的叠加。」

这同样不对。

有些珠子确实只是换个词再讲一遍。

例如：

「身体先记起舞步 / 隐约记起步子」

即使允许多角度表达，也不能无限为这种重复找理由。

**防范办法：要求评委明确说出后一颗珠子新增了什么。**

如果说不出来，就不能仅凭「感受碎片允许叠加」放过它。

## 4.2 为了避免重复，反过来鼓励刻意求异

模型可能开始认为：

同一个簇里的珠子必须分别表达不同的东西。

结果可能出现：

- 强行制造不同意象；
- 为了不重复而使用不自然的词；
- 原本连贯的情绪被拆得支离破碎；
- 过度追求每颗珠子都有独特含义。

这会让屏幕稿变得刻意、花哨。

感受碎片可以有一定程度的叠加，不需要每颗都承担完全不同的功能。

## 4.3 忽视真实的视觉拥挤

这是一个容易被忽略的新问题。

「不是连续散文」不等于「可以无限增加碎片」。

即使每颗珠子都不重复，如果一个簇有太多文字，观众仍然可能扫不过来。

例如：

- 每块都不超过8字；
- 每块都提供不同感受；
- 但同一时刻出现了十几块。

这仍然可能有问题。

所以需要保留一个独立的判断维度：

**单个感受簇的视觉信息密度和扫读负担。**

如果评委只收到拼接后的文本，最好再提供实际排版截图或位置、数量信息。否则它很难准确判断屏幕上的视觉拥挤。

## 4.4 低估线与感受之间的真正重复

如果过分强调线和感受的功能不同，模型可能不敢指出它们的重复。

但实际中，有些感受确实只是在重复线里的心理解释。

所以要继续保留第三步 C 类判断。

区别是：

不再问「两者是不是在讲同一件事」，而是问「感受碎片有没有提供线之外的体验价值」。

## 4.5 评委自行脑补音乐合理性

如果评委没有听到音乐，也没有获得准确的音乐听感记录，它不能因为某种感受反复出现，就假设这是音乐主题回归造成的。

反过来，它也不能假设重复一定是文字问题。

因此必须明确：

没有音乐证据时，只判断文本本身；有音乐证据时，才判断重复是否对应音乐发展。

你们的感受碎片不是一段需要尽可能精简的文章，而是一种配合音乐的、多角度的感受呈现。
