# 1. PROJECT PURPOSE

这个产品长期想创造的，不是一条“这段悲伤、这段激动”的音乐情绪字幕，也不是一篇听完整首以后才成立的结构分析。它想让一个人**一边听音乐，一边在正确的时刻抓住现在真正发生的体验；同时又记得已经发生过什么，因此逐渐听懂：为什么同样或相似的东西，到这里已经有了不同意义。** 它应该陪着作品往前走，而不是站在结尾回头替听众宣布答案。

它也不满足于把很多局部观察做对。用户反复要求最终体验能让人——尤其是本来已经熟悉作品的人——获得一种**以后再听会自动想起来的、作品特异的理解**。用户对 Op.52 的直接反馈是：内容“讲的都挺多”，但如果“听过就听过了”，没有形成更深刻认知，就还没达到真正价值。 但这种长程理解又不能变成唯一正确故事：用户明确说自己“很讨厌 anchoring”，之所以坚持多种情感和 alternatives，就是为了防止把音乐锁死为“就是这样”。

因此，长期目标实际上一直在保护一个张力：**局部必须真实、鲜活、多义、时间正确；整体必须有记忆、有历史、有方向；展示必须克制，不淹没音乐；压缩可以很强，但不能把真正不同的听法和体验维度静默磨掉。** 这几个目标并不是互相替代，而是这个产品之所以不同于普通音乐解说的共同条件。

# 2. STRONGEST CONSTITUTION CANDIDATES

## CANDIDATE P-01

### Plain-language principle

**实时内容只能用“现在 + 已经听过的过去”来理解现在；不能拿未来发生的事反过来定义当前。**

这不禁止全曲结构分析，也不禁止 recap 使用 hindsight。禁止的是：在实时聆听的当前节点，作者因为知道后面会发生什么而提前告诉听众“随后会……”“现在还没有 X”“这是后来 Y 的前兆”，除非这种期待本身已经由过去真实建立。

### Product consequence

违反它，听者不再是在陪着音乐经历，而是在听一个已经知道结局的人做事后解说。当前体验会被未来污染；真正的悬念、期待、误判和意义生成都会被提前夺走。

### Why this appears constitutional

它跨作品、模型、schema、pipeline 都成立；而且历史中最早就是用户直接提出，后来又不断以 future-negative、future-target residue、WHY_NOW 泄漏等不同 bug 形式复发。它约束的是**产品的时间视角**，不是某个 stage 的实现。

- **2026-09-03 / History L652 — USER_DIRECT**：用户进一步修正：不是结构分析不行，而是“把后面的东西扯进来现在很诡异”，并质疑“某某东西尚未建立”到底有什么信息增量。

## CANDIDATE P-02

### Plain-language principle

**有新事实，不等于值得打断听众；每次主动更新都必须赚到注意力。**

底层可以知道很细的 onset、局部变化和证据边界，但 viewer-facing 内容只有在不更新会造成独立的理解损失时，才应该真正抢一次注意力。

### Product consequence

违反它，产品会变成逐小节讲解或“乐句解剖字幕”：每个技术变化都触发新文字，音乐被说明文字淹没。反过来，如果重要断裂不更新，听者又会继续拿已经失效的解释理解当前。

### Why this appears constitutional

它从“当前信息增量”问题发展到“viewer granularity / attention budget”，并且成功解释了两类相反 bug：Op.60 第一乐句过碎，以及 Op.52 m.195 即使很短也必须更新。它不依赖 atom、scene、field 等架构名。

### Evidence chronology

- **2026-09-03 / History L652 — USER_DIRECT**：用户质疑“尚未建立”有没有任何信息增量，说明“时间上没说错”不足以让一句话值得显示。
- **2026-09-03 / History L1301 — USER_DIRECT**：用户明确问“颗粒度会不会太小了”，认为 Op.52 m.195 的短切合理，但《船歌》第一句拆成多个 viewer 单元很怪。
- **2026-09-10 / late history — USER_REPEATED/accepted refinement**：后期把 `viewer_update_value` 独立于 semantic state，并明确 strong boundary 只是触发 re-evaluation，不自动要求切字幕。

### Repeated or one-off

**反复出现。** 最初来自局部 granularity 直觉，后期已经扩展为 scene economy、strong-boundary merge、attention slot 等多轮回归问题。

### Counterevidence

早期曾强调“小段尽量原子”，甚至认为底层 over-segment 比 under-segment 好。这个并不冲突：后来历史明确区分了**语义/证据粒度**和**viewer update 粒度**。原子化是内部可组合性；主动打断是产品注意力决策。

### Superseded implementations

- `atom = viewer update`。
- 每个 activation onset 都必须生成一个新显示单元。
- 用“最少几小节”这种固定长度判断是否切分。
- strong musical boundary 自动等于新 scene。

### Generalized meaning

**底层可以高分辨率；上层必须有 attention economy。主动更新的门槛是独立 listener-value change，而不是“发生了一个可检测事件”。**

### Must NOT generalize

- 不能推出“更新越少越好”。
- 不能推出短事件都不重要。
- 不能把 Op.52 m.195 或 Op.60 m.4/m.6 当长度模板。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

## CANDIDATE P-03

### Plain-language principle

**不要把已经具体、可感、像人真实经历的东西，重新翻译成抽象心理学总结。**

语言可以准确、克制、研究驱动，但最终应尽量保留动作、身体感、说话动作、空间/关系变化等“lived concreteness”。鲜活不是加词藻，而是不把具体体验降维成 therapy-speak 或论文摘要。

### Product consequence

违反它，内容虽然“都看得懂”，却像一个训练过的心理分析系统在做总结：所有作品都会变成“允许自己、完整存在、内在过程、感情事实”等同一种心理模型。听者不会形成即时可感的音乐经验。

### Why this appears constitutional

用户从最早阶段就明确说“鲜活性一直在强调”，并反复拿 Op.52 与 Op.60/61 比较。后来发现 RAW 本身往往已有鲜活表达，问题是抽象化过程把生命力压掉。这说明鲜活性不是装饰偏好，而是**产品保真维度**。

### Evidence chronology

- **2026-09-03 / History L213 — USER_REPEATED**：用户把“语言的鲜活性”称为“一直在强调”的要求，并直接问当前产物“在说人话吗”。
- **2026-09-03 / History L1301 前后 — USER_ACCEPTED/generalized**：历史把 Op.52 的优势概括为“不要把具体 lived experience 压成抽象心理总结”，而非复制具体措辞。
- **2026-09-07 / later regression — BEHAVIOR_REJECTED**：后期 contract 仍把“RAW 中鲜活体验被压成抽象心理术语 / therapy-speak”列为需要持续保护的旧问题。

### Repeated or one-off

**高度反复。** 从 Op.52 calibration 到 Op.60/61 generalization，再到 VNext Affect/Surface 回归都在出现。

### Counterevidence

用户也曾问“会不会应该稍微文学化一些”。但后续讨论没有把目标定成“越文学越好”，而是要**解释压缩更有形象和穿透力**。因此“鲜活”不能等同 decorative prose。

### Superseded implementations

- “普通读者第一遍可懂”作为唯一语言门槛。
- 把 vividness 当 cosmetic style，因此 convergence 不允许为它重写。
- 为了显得文学而加入无证据的剧情、人物、人生哲理。

### Generalized meaning

**在证据允许的范围内，优先保留体验的具体形状；语义归一化不应自动导致语言/现象学归一化。**

### Must NOT generalize

- 不要求复制某个 RAW 比喻。
- 不要求所有句子都身体化或比喻化。
- 不允许为鲜活性编造作品没有支持的具体人生剧情。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

## CANDIDATE P-04

### Plain-language principle

**最终文案应直接告诉听者“这里是什么”，不要长期用“先纠正你错在哪里”的老师/辩论者姿态说话。**

真正要限制的不是词语“不是”，而是高频 correctional stance：先虚构一个错误理解，再否定它，再宣布正确答案。

### Product consequence

违反它，即使每句话语义准确，整首作品也会像 AI 在不断校正一个假想听众：`不是 A，而是 B / 并非 / 不再只是 / 真正重要的是 / 可以留意是否……`。听者会感觉被解释、被纠正，而不是被带进音乐。

### Why this appears constitutional

用户直接指出“不是而是”的 AI 味，后期在 VNext 即将收口时还专门追问“我们之前消除不是而是的努力呢”“修好了吗”，说明这不是一次性措辞偏好。历史进一步把它从 literal syntax 升级为 rhetorical stance。

### Evidence chronology

- **2026-09-04 / History L3009 — USER_DIRECT**：用户明确说“‘不是 而是’的 ai 味太重了”，并问什么时候才应使用。
- **2026-09-04 / same episode — USER_ACCEPTED/generalization**：统计显示真正问题不是固定模板本身，而是大量内容采用“否定 A → 校正 B”的思维方式。
- **2026-09-10/11 / late history — USER_REPEATED**：用户在 VNext 尾段再次追问此前 anti-`不是而是` 的成果；历史明确恢复原则：内部 distinction 可以保留，Surface 必须消化成自然直接表达。
- **2026-09-11 / late regression — BEHAVIOR_REJECTED**：只做 regex 删除，把“不是 A 而是 B”换成“是否 A 还是 B / 可以留意”等教师式模板，仍被判为 regression。 

### Repeated or one-off

**反复且跨多轮。** 至少从 09-04 到 09-11 一直作为已批准 Surface 行为被保护。

### Counterevidence

历史明确承认某些 contrast 本身有独立认知价值，例如真正改变听法的类别重解释。这说明**并非所有否定句都错**。

### Superseded implementations

- 全局 blacklist “不能用不是”。
- regex 删除 `不是 / 而是 / 听见 / 可以` 等触发词。
- 把旧模板统一替换成“可以留意 / 可以听见 / 从……到……”的新模板。
- 用整曲 1–3 次之类固定数字当最高法；这是曾建议的 style budget，不是产品本体。

### Generalized meaning

**产品 voice 应以直接、肯定、体验性的讲述为默认；只有当“纠正一个已经真实成立且有诱惑力的理解”本身就是 insight 时，才值得显式对照。**

### Must NOT generalize

- 不能禁止所有否定词。
- 不能规定全曲固定允许几次 contrast。
- 不能把任何某种句式本身写成 Product Constitution。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

## CANDIDATE P-05

### Plain-language principle

**真正不同、都有依据的听法要能共存；不要先决定一个漂亮解释，再回头把所有局部都改成它的证据。**

整体理解、标题或 editorial lens 可以很有穿透力，但它必须从已经独立形成的证据和局部体验中长出来，而不是成为上游 evidence filter。

### Product consequence

违反它，产品会把一首多义的作品锁死成一个故事：所有 ambiguity、alternative 和“暂时跟中心无关但很重要”的局部体验都会被重写成 thesis 的例子。听者得到的是一个漂亮而过拟合的解释，而不是更丰富的听法。

### Why this appears constitutional

这是用户最明确陈述过的产品动机之一：他直接说明之所以保留多种情感、alternatives，就是为了抗 anchoring。它后来又解释了为什么 Center 不能进入 Affect/Generator 的早期形成阶段；当前 Architecture 的隔离只是该产品法的工程体现。

### Evidence chronology

- **2026-09-04 / History L3223 — USER_DIRECT**：用户明确说“很讨厌 anchoring 的效应”，并解释多种情感、alternatives 的目的就是防止“将某音乐就是解释成这样”。
- **同一轮 — USER_ACCEPTED**：方向被明确为“RAW → 完整异质 Canonical → 人理解整体 → 选择标题/主线”，绝不能先有标题再去 RAW 找证据；后者被称为 confirmation bias machine。
- **后续 / USER_REPEATED**：历史继续要求 Situation/whole-work 不要为了 coherence 强行合一；如果有多个真实 readings，可以保留多个 realization。
- **Current Architecture — current embodiment**：Center 不参与 Affect Distillation / Affect Boundary Review；Situation JOIN 才是 Center 与 Affect 第一次正式结合。

### Repeated or one-off

**高度反复。** 贯穿 Canonical、Center、Title、Alternative、Situation、Affect 多轮讨论。

### Counterevidence

后期用户明确接受：若两条内容高度冲突、很接近、异质性低、占同一注意力槽位，可以选一个，不必为了“零丢失”全部保留。 这不是对 plurality 的否定，而是把“独立 proposition”收敛为“独立 listener value”。

### Superseded implementations

- 所有 `role=ALTERNATIVE` 都默认等权左右并列。
- 所有不同措辞都必须同时存活。
- 先定标题/Center，再把 RAW/Canonical 修成支持它。
- 一个全曲 lens 被当作 canonical thesis。

### Generalized meaning

**整体解释可以组织，但不能垄断证据；真正独立的多义性必须有生存空间。**

### Must NOT generalize

- 不要求每个微小分歧都成为 visible alternative。
- 不要求所有研究者意见都等权。
- 不把 Op.52 的 memory/wish 或 Op.61 某个 ending reading 当通用模板。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

## CANDIDATE P-06

### Plain-language principle

**局部体验必须先独立成立；全曲解释可以重新组织和照亮它，但不能反过来制造、替换或削弱它。**

### Product consequence

违反它，某一段音乐不再被按它自己听起来是什么来描述，而被写成“全曲 thesis 在这里的第 N 个例子”。作品的局部生命会消失，Center 变成一个解释独裁者。

### Why this appears constitutional

它和 anchoring concern 同源，但更具体：不仅要保留 alternative，还要保护**local truth 的因果独立性**。后期架构数次变化，用户保护的始终是“新 whole-work 能力应当加在旧局部内容旁边/后面，而不是重写前置内容层”。

### Evidence chronology

- **2026-09-04 / USER_DIRECT motivation**：用户担心主线/标题会与多情感、alternatives 的努力相反。
- **History ~L22.7k — USER_ACCEPTED boundary**：Whole-work audit 可以因发现真实漏项而 targeted repair Canonical，但不能“因为喜欢某个 center，所以回头把 Canonical 改得更支持它”。
- **2026-09-07 / repeated contract**：Situation 必须同时读取已经完成的真实 Affect，不能只拿 Center 自己推演；后期又反复审查“center 单方面推演情绪”是否出现。 
- **Current Architecture — current embodiment**：Center 被明确隔离在 Affect Distillation / Affect Boundary Review 之外。

### Repeated or one-off

**反复，跨数代架构。**

### Counterevidence

历史允许 whole-work audit 发现 local content 真漏了以后回修。这是 evidence-driven correction，不是 thesis-driven overwrite，因此不构成反证。

### Superseded implementations

- Center 作为 Generator/Affect 的上游提示。
- Whole-work Model 为了“连得上”直接改写局部情感。
- Situation/Center 成为 local experience 的唯一来源。

### Generalized meaning

**全局理解是 additive / recontextualizing，不是 substitutive / generative authority。**

### Must NOT generalize

- 不要求产品永远存在叫 `Center` 的 JSON。
- 不要求当前 `Situation JOIN` 这个 stage 永远存在。
- 不禁止全曲理解对局部产生新的“已听历史下的意义”；禁止的是改写局部事实本身。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

## CANDIDATE P-07

### Plain-language principle

**一首作品要让人听出“它一直在往前走”：当前体验既受作品持续处理的核心困扰影响，也受此前真实经历影响；但不能为了连贯性把每一段都编成因果链。**

换言之，历史必须有后果；因果必须有证据。

### Product consequence

如果只有局部情感，没有历史组织，内容会变成“一堆漂亮情绪句散着放”，甚至比 RAW 更云里雾里。反过来，如果每段都被迫成为 `problem → failed solution → next solution`，音乐又会变成过度理性的心理流程图。

### Why this appears constitutional

这条原则最能体现“原则是怎么长出来的”：

1. 用户先拒绝了有 Center 但只是按时间排列的流水账，要求真正的“必然性”；
2. 中期 schema 把这个要求机械化成每段 mandatory residue / next_pressure，产生伪因果；
3. 后期又修正成 sparse condition changes；
4. 最后用户亲自把 WHY_NOW 收敛为两个 prerequisite：**Center + History**，但强调不要写成“因为所以”。

这不是一句话突然出现，而是从多轮失败中形成的更高层 law。

### Evidence chronology

- **2026-09-04 / History L19160 — USER_DIRECT**：用户批评全曲描述只是“把所有东西揉在一起写成流水账”，完全没有必然性。
- **2026-09-07 / later repair — SUPERSEDED implementation**：历史发现 mandatory `next_pressure` 会把每段硬写成 `A → 所以必须 B → B 逼出 C`，最后成为一直不想要的 `problem → solution → failed solution → next solution`。
- **2026-09-07 / generalized rule — USER_ACCEPTED**：必然性被重新定义为“来自经历，不来自 schema”；真正强的关系是前面发生过后，体验条件已经不能完全回到之前，而不是“A 失败，所以系统转向 B”。
- **2026-09-10 / History L92157 — USER_DIRECT / strongest late formulation**：用户亲自说明 WHY_NOW 自始至终有两个 prerequisites：“一个是 center…一个是历史”，两者共同决定当下；可以有“一缕不安 → 裂缝不断加大”，但不要写得非常“因为所以”，否则各种情感没法 organize 在一起。
- **Current Architecture — current embodiment**：WHY-NOW 当前输入同时包含 Situation/Center 与 Prefix History。

### Repeated or one-off

**高度反复，并且经历了明确升级。** 这是历史中最典型的“局部规则成长为高层原则”。

### Counterevidence

早期用户曾用“为什么上一段逼出下一段”来表达必然性，似乎更偏强因果；后期则明确接受不是所有相邻段都必须有 causal relation。这不是目标被推翻，而是**实现语义被修正**：真正要的是 path dependence / changed conditions，不是 mandatory causation。

### Superseded implementations

- 每个 stage mandatory `residue` / `next_pressure`。
- 每段都必须解释为什么下一段出现。
- Whole-work 统一性 = 一条完整 problem-solving chain。
- Sparse/History 本身作为剧情作者。

### Generalized meaning

**作品的过去必须真实改变后来的可听意义；全曲连贯来自少数真实的 condition changes + 持续核心关系，而不是人为补齐每个箭头。**

### Must NOT generalize

- 不要求每段都有 WHY_NOW。
- 不要求所有作品都有单一“问题—求解”结构。
- 不要求使用 `Center + History` 这些字段名；这是当前职责表达。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

## CANDIDATE P-08

### Plain-language principle

**一个意思“存在于作品里”还不够；它必须在正确的音乐时刻成立。明显的音乐换气/分句不能被一个过宽的体验状态无检查地吞过去。**

强边界的产品职责是：强迫重新问一次“现在的体验有没有变、有什么新成立”；它不自动要求新字幕、新 scene 或新情绪。

### Product consequence

违反它，用户会在音乐已经明显进入新阶段时，屏幕仍然显示上一段的体验；或者后面才成立的“悬问/转向”被投射回一个大范围开头。内容语义即使“总体没丢”，时间上仍然会听错。

### Why this appears constitutional

这是后期历史中最明显的**隐式产品法被工程长期漏保**的例子。用户先从“正常分句怎么跨这么多”发现问题，随后明确要求 strong boundary 至少触发 re-evaluation；Architecture 最终也把 Articulation 放在 Affect Review 和 WHY-NOW current-event evidence 上，而不是直接控制 UI。

### Evidence chronology

- **2026-09-10 / History L89652 — USER_DIRECT**：用户同时提出两个关键问题：WHY_NOW 历史组织变弱，以及《船歌》“正常乐理上的分段”被内容跨过去很多，导致成品“甚至比 RAW 更云里雾里”。
- **后续 generalized conclusion — USER_ACCEPTED**：strong 分句两边“不一定要变成两个 Affect Field”，但不能未经检查就默认相同体验。
- **late VNext formulation — USER_ACCEPTED**：Strong musical boundary → trigger re-evaluation → 再看 current / Center + History / newly_true → 最后才决定是否 update viewer；明确“不是强边界就必须切字幕”。
- **Current Architecture — current embodiment**：Articulation 主要 review Affect，同时给 WHY-NOW 提供 current-event evidence。

### Repeated or one-off

**后期高频反复。** m.24/m.32/m.51 等只是不断暴露同一类问题的 test precedents。

### Counterevidence

用户早期反对过度切碎，因此“音乐有边界”绝不能自动推出“viewer 必须切”。这恰恰是本原则的一部分：**boundary = re-evaluation obligation，不是 rendering obligation。**

### Superseded implementations

- 同一 macro Affect Field 内默认可以跨越所有分句。
- strong boundary 自动切 scene。
- `same Affect => safe HOLD`。
- semantic coverage = 只要某个 ID 在某处出现就算时间正确。

### Generalized meaning

**产品必须尊重音乐本身的时间组织：局部意义的 onset/offset 与显著边界需要被重新判断，而不能由大范围抽象状态替代。**

### Must NOT generalize

- 不把 m.24、m.32、m.51 作为通用规则。
- 不规定强边界一定产生新 Affect。
- 不规定某种形式分析标签必须显示给 viewer。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

## CANDIDATE P-09

### Plain-language principle

**完整性要以“独立的听者价值”计，不以句子数、atom 数、字符数或 proposition 数计。**

压缩、改写、同槽位合并、删除 defensive/analyst-only 内容都可以；但如果删除后，听者确实少了一种不同的听法、听觉目标、动态关系或有价值的不确定性，那就是产品损失。

### Product consequence

如果把完整性理解得太松，重要 FACET、alternative、身体/关系/动态信息会在“压缩”中静默消失；如果理解得太严，每一个 clause 都必须上屏，产品会被分析噪音和近义重复淹没。

### Why this appears constitutional

历史在这个问题上经历了最完整的自我纠正：

- 先保护“完整异质信息”；
- 后来为了防漏走到几乎所有 clause ACTIVE；
- 用户再明确说低异质、冲突且同槽位的内容可以选一个；
- 最终标准收敛为 **Independent Listener Value / Unique Listener Information Retention**。

这说明最高法不是某一代 coverage schema，而是“什么才算真正产品损失”。

### Evidence chronology

- **2026-09-04 / History L1968 — USER_DIRECT**：用户阻止 assistant “砍掉”核心知识层，强调“完整异质信息 去重合并 这就是最关键的”。
- **2026-09-10 / History L76460 — USER_DIRECT**：用户说聚合可以，但“丢信息才是关键问题，必须检查”。
- **2026-09-09/10 / refinement — USER_ACCEPTED**：目标被明确重写为“只让真正具有独立 listener value 的 semantic obligations 成为产品义务；然后保证这些义务一个都不丢”。
- **2026-09-10 / History L83045 — USER_DIRECT corrective evidence**：用户明确表示高度冲突、很接近、异质性低的两条“只能选一个”，这种丢一点信息自己“不太在乎”。
- **后期 stable definition — USER_ACCEPTED**：真正 LOSS 被定义为删除后听众少了一种不同听法/目标/动态关系，并且没有在其他 viewer surface 获得等价表达。

### Repeated or one-off

**高度反复，且后期有明确收敛。**

### Counterevidence

早期 “Canonical 一条没丢 / 100% coverage” 的实现口径比后期更严格。后期用户已经明确放松到 listener-value 层，因此 proposition-level zero-loss 应视为**被泛化、被替代的实现**，不是现行最高法。

### Superseded implementations

- 每个 Canonical atom / clause 都必须 viewer-visible。
- `85/85 ACTIVE` 之类数量零丢失 = 产品完整。
- 字符数恢复到 Op.52 2039 才算不丢。
- 只要内部 WHY_NOW/CSO 还存着，就算用户已经获得该价值。

### Generalized meaning

**允许强压缩，但必须对独立 listener value 负责；压缩的是表达冗余，不是听法维度。**

### Must NOT generalize

- 不能把某一代 ILVU schema 或阈值写成 Constitution。
- 不能要求所有 qualifier/defensive clause 上屏。
- 不能以 Op.52 的 atom 数、字符数或 scene 数为通用密度基准。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

## CANDIDATE P-10

### Plain-language principle

**最终产品不应只让人“跟得上现在”，还应逐渐给出一两种真正会留下来的、作品特异的重新聆听方式。**

这种长期理解必须足够有记忆力、能让熟悉作品的人下次再听时听见新的关系；同时它只能是一种有证据的 interpretive compression，不能自封为唯一真相。

### Product consequence

违反它，产品会“讲得很多”，每句都正确，却没有形成更深的认知；听过就过去。另一极端则是强行用一句 slogan 解释整首，造成 anchoring。

### Why this appears constitutional

这是项目从“内容正确”升级到“产品价值”的关键转折。它随后驱动了 whole-work center、movement、recap、title/lens 等大量探索。具体机制多次改变，但“要让听者形成可记忆的重新听法”始终没有被撤回。

### Evidence chronology

- **2026-09-04 / History L2509 — USER_DIRECT**：用户引用熟悉 Op.52 的同学反馈：“讲的都挺多的，但是感觉听过就听过了，并没有形成多么更深刻的认知”。
- **same discussion — USER_ACCEPTED direction**：目标被明确为让已经很熟作品的人形成一个“以后再听会自动想起来的理解”。
- **History ~L3000 — USER_ACCEPTED**：系统价值被表述为“不只是帮助用户理解眼前一分钟，而是在逐渐改变他如何理解整首作品”，对熟悉 Op.52 的人后者才是真正应追求的价值。
- **Counterbalancing USER_DIRECT**：紧接着用户又明确担心 anchoring，要求多义性和 alternatives 不被主线吞掉。

### Repeated or one-off

**反复，且之后数万行 whole-work / center / title / recap 探索都围绕此目标展开。**

### Counterevidence

用户拒绝标题/主线成为“作品就是这样”的唯一 thesis；因此“可记忆”不能等同“单线统一”。这不是反证，而是该原则的必要边界。

### Superseded implementations

- 标题就是全曲唯一主线。
- 固定 1–3 条 thread 数量。
- 所有局部都必须显式提 Center 才算 coherence。
- “Center 问题 + 最终答案”固定 Q&A 模式。

### Generalized meaning

**产品应产生 durable re-hearing：少数高价值的长程关系把局部经验重新组织成可记忆认知，但不取消作品的多义和局部独立性。**

### Must NOT generalize

- 不能把“旧梦，咫尺，永隔”推广为其他作品的解释模型。
- 不规定所有作品都必须有三段式标题、问句或单一 Center。
- 不规定 recap/title/right rail 必须用当前形式实现。

### Classification

**STRONG_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

# 3. POSSIBLE / UNCERTAIN CANDIDATES

## CANDIDATE P-11

### Plain-language principle

**产品应该只有一个最终完整体验，而不是靠“精简版 / 完整版”两个产品模式解决信息负荷。**

### Product consequence

如果重新拆成两个模式，团队会再次把“当前最值得看什么”和“哪些独立价值必须存活”错误地绑定到产品模式选择：精简版可能变成 semantic deletion，完整版又变成信息爆炸。

### Why this appears constitutional

用户对此有非常明确、很晚期的直接否定：First Listen / Focus Mode “已经被我们完全摒弃”。后续历史多次把“一套最终完整产品”写成硬约束。

### Evidence chronology

- **2026-09-08 / History L39468 — USER_DIRECT**：用户纠正 assistant：“我们什么时候有两产品思想，first listen 已经被我们完全摒弃了。”
- **后续 USER_ACCEPTED/repeated**：历史明确“当前只有一个最终产品模式”，信息负荷通过 hierarchy/lifecycle/recall/grouping 等机制处理，而不是恢复两个产品。

### Repeated or one-off

**反复且明确。**

### Counterevidence

更早历史确实存在 First Listen / Guided Full 双模式，并一度被 assistant 重新提出。用户后来明确否定，因此属于真正 superseded product idea。

### Superseded implementations

- First Listen / Guided Full。
- Focus Mode。
- selective simplified product。

### Generalized meaning

**不要用产品分叉来逃避“完整但不淹没音乐”的核心设计问题。**

### Must NOT generalize

- 不规定必须使用某种 sidebar / lifecycle UI。
- 不意味着所有用户永远不能有显示偏好；历史只明确否定了把“完整性”拆成两个核心产品模式。

### Classification

**POSSIBLE_CONSTITUTION_CANDIDATE**

### Confidence

**HIGH**

> 放在 Possible 而不是 Strong，是因为它更接近产品形态/模式约束，而不是跨任何未来产品 surface 都必然成立的内容法。

## CANDIDATE P-12

### Plain-language principle

**最终的高阶 editorial compression / 标题 / taste selection 需要保留人类判断，但这种人类判断应发生在证据和局部理解之后，不能前置成 anchoring source。**

### Product consequence

完全去掉人类 taste gate，AI 可能稳定地产生“合理但缺乏品味”的标题/主线；把人类 taste 放太早，又会让后续研究变成 confirmation bias。

### Why this appears constitutional

用户明确说标题是从候选中人工筛选，并认为当前 AI 的 taste 仍不足，“人工是必须要进 loop 的”。但后续历史把人工作用逐渐收窄到高阶选择、异常/审计，而不是每个内部判断都手工批准。

### Evidence chronology

- **2026-09-04 / History L3223 — USER_DIRECT**：用户明确说标题需要先对作品有理解，自己是人工筛选句式，并判断“人工是必须要进 loop 的”“AI 做这个品味目前还缺一些”。
- **同一轮 — USER_DIRECT boundary**：用户同时担心人工选择的句子成为 anchoring，因此 human taste 不能成为上游解释原则。

### Repeated or one-off

**有持续影响，但关于人工介入范围并未完全冻结。**

### Counterevidence

后续多轮努力都在减少人工逐段审核，倾向自动化 discovery + 最终 taste / exception review。因此“人工必须审核每一层”明显不成立。

### Superseded implementations

- 每个 Center/semantic decision 都必须人工批准。
- 人工标题反向指导 RAW/Canonical。

### Generalized meaning

**在高压缩、高品味、低可验证性的 editorial choice 上保留人类责任；但人类偏好不能污染证据发现。**

### Must NOT generalize

- 不规定人类必须审核哪些具体 JSON/stage。
- 不规定标题必须人工写。
- 不把当前 AI 能力判断永久化为“AI 永远不能做 taste”。

### Classification

**POSSIBLE_CONSTITUTION_CANDIDATE**

### Confidence

**MEDIUM**

## CANDIDATE P-13

### Plain-language principle

**“当前体验是什么”与“为什么现在具有这个意义”是两种互补价值，后者不能把前者挤掉。**

### Product consequence

如果只剩 WHY_NOW / 历史解释，产品会像在讲一个关系模型，却没有告诉听者此刻究竟听到/感觉到什么；如果只剩 WHAT，内容又会成为散落的情绪卡片。

### Why this appears constitutional

它长期隐含在项目原始目标里，后期又因 Surface 出现 `WHAT = 空、WHY_NOW = 有` 的具体回归而被重新显性化。但历史更多是通过实现 bug 证明它，用户直接抽象成“最高法”的次数少于前十条。

### Evidence chronology

- **早期 product purpose — USER_ACCEPTED behavior**：当前体验 + 历史重新语境化一直是内容目标的双轴。
- **2026-09-10 / USER_DIRECT**：用户说 WHY_NOW 应回答“为什么这种情感的运动会在这个时刻出现”，否则各种情感是散落的。
- **2026-09-11 / regression evidence**：历史明确拒绝 `WHAT=空 / WHY_NOW=有 → retention 100% PASS`。

### Repeated or one-off

**隐式反复，后期显性。**

### Counterevidence

某些 viewer unit 可以把 WHAT 与 WHY_NOW 自然融合成一句，不必永远显示两栏或两行。因此不能把字段分离本身升格为 law。

### Superseded implementations

- WHY_NOW 文本代替 current semantic obligations。
- “有一条解释关系”就算当前体验已被表达。

### Generalized meaning

**产品必须同时交付即时体验和历史/整体语境带来的附加意义；可以融合表达，但不能语义替代。**

### Must NOT generalize

- 不要求永远存在 `WHAT` / `WHY_NOW` 两个字段。
- 不要求 UI 同时显示两块。

### Classification

**POSSIBLE_CONSTITUTION_CANDIDATE**

### Confidence

**MEDIUM**

## CANDIDATE P-14

### Plain-language principle

**解释必须始终能落回这首具体作品、这个具体听觉阶段，而不能漂成通用心理治疗、人生哲学或漂亮寓言。**

### Product consequence

违反它，不同作品会听起来像同一套“接受—防御—完整存在—继续生活”的心理模型换皮。熟悉作品的人也无法把文字对应回实际音乐，因此没有真正增加听法。

### Why this appears constitutional

它反复出现在 vividness、audible locator、music phrase boundary、作品特异 Center/title、Surface grounding 等问题中。但“需要多少音乐理论显性展示”仍未完全定案，所以把它列为 Possible。

### Evidence chronology

- **USER_REPEATED**：用户长期反对 therapy-speak 和泛心理模型，要求“说人话”但仍忠于作品实际体验。
- **USER_DIRECT late evidence**：用户要求检查《船歌》的正常分句，并指出当前成品比 RAW 更云里雾里。
- **BEHAVIOR_REJECTED**：后期 Surface 增添“民族尊严 / 神圣纯净 / 终极回答”等未经充分 grounding 的剧情时，被明确视为越权 amplification。

### Repeated or one-off

**反复。**

### Counterevidence

用户并不想把最终产品变成乐理课；formal/texture 可以作为内部证据和边界控制，而非 viewer 必须看到的术语。因此“音乐 grounding”不能泛化成“显示更多理论”。

### Superseded implementations

- 用 generic therapy vocabulary 统一各作品。
- 用作品外的 programmatic / national / biographical narrative 增强戏剧性。
- 把 formal label 本身当 viewer insight。

### Generalized meaning

**人话可以高度体验化、解释性甚至有文学压缩，但必须能由这首作品的可听事件和已建立证据托住。**

### Must NOT generalize

- 不要求展示和声分析、主题标签或小节号。
- 不禁止抽象层面的心理语言，只禁止失去作品特异支撑。

### Classification

**POSSIBLE_CONSTITUTION_CANDIDATE**

### Confidence

**MEDIUM**

# 4. IMPLICIT LAWS

这些不是历史里始终以一句固定 contract 出现，但团队不断“修好又回退”，说明产品一直在保护它们。

## I-01 — “存在于内部模型”不等于“用户已经得到”

后期多次 audit 报告把 `LOCAL_WHY_NOW` model / CSO 等内部存在当作 retention，随后又被纠正：真正的 listener value 如果最终没有 viewer-facing prose 或明确产品去向，不能称为已交付。历史曾明确区分“链路里保住 ≈98–100%”与“当前真正写成视频 surface prose 的比例”。

**隐式产品法：** 对每个独立 listener value，必须存在真实用户可获得的 fate；不能靠“JSON 里还有”自我安慰。

## I-02 — Attention budget 是内容质量，不只是 UI 性能

“值不值得把听者注意力从音乐上抢过来”贯穿 granularity、scene economy、WHY_NOW frequency、recall、secondary surfaces。它不是 presentation 最后再优化的 cosmetic issue；说得太勤本身就会改变产品体验。

**隐式产品法：** 文字必须服务聆听，不能把音乐降成文字的背景音。

## I-03 — 历史可以改变意义，但不能改写事实

过去发生过的事会让一个回返、停顿、柔和或爆发获得新意义；然而历史/Center 不能把当前实际听到的体验改造成另一个更方便全曲叙事的状态。P-06 与 P-07 的交叉处长期靠 bug 修复维护，却从未以一句稳定 contract 完整写出。

## I-04 — “时间正确”与“语义还在”是两个独立的完整性维度

后期团队才明确意识到 semantic coverage=0 missing 仍可能出现 broad-window backward projection、强边界吞没、onset/offset 错位。VNext 当前 Architecture 已显式把 Coverage 拆成 Semantic / Temporal / Relational / Boundary 四维。

**隐式产品法：** 一个意思如果在错的时候出现，仍然是产品错误。

## I-05 — 表达层只能重写表达，不能增强 interpretation

后期 anti-correctional Surface 修复多次出现：为了让句子更鲜活，自行加入 collective/national triumph、sacred certainty、终极哲学答案；历史明确把这类行为视为 amplification regression。

**隐式产品法：** polish 不拥有新的解释权。

## I-06 — 强边界必须被“看见”，但不必被“展示”

这是 P-08 在实现中反复缺失的能力：boundary 不是 UI 切点，却是 semantic recheck obligation。它从“正常分句被跨过”这个用户问题一路长成 VNext 的 Articulation→Affect Review 职责。

## I-07 — 作品的复杂性不是噪音；但 analyst 的防御性解释可以是噪音

历史反复保护 heterogeneous affect / real alternatives / qualifiers / dynamic micro-facets；同时后期又允许 retrospective-only、internal analytic support、defensive qualifier 退出 active。真正边界从来不是“信息多/少”，而是**是否改变听者能怎么听这首作品**。

# 5. REPEATED REGRESSION PATTERNS

## R-01 Timing 修复 → “未来的 absence”填充当前

原始 bug：不能把 m.6 才成立的东西从 m.4 开始说。  
过度修复：m.4 改成“歌唱尚未建立”。  
结果：时间没说错，但当前信息增量接近零，还偷偷用未来定义现在。用户直接指出这个问题。

**背后缺少的高层 law：P-01 + P-02。**

## R-02 语义归一化 → 鲜活性被压成心理模型

RAW 有动作、身体、说话和空间关系；中间层为了稳定 proposition 把它们转成“允许感觉存在 / 内在过程 / 防御 / 归属”等抽象术语。

**背后缺少的 law：P-03。**

## R-03 精确 timing → viewer 粒度碎裂

发现每个 onset 后，系统自然把每个 onset 变成一次更新；Op.60 第一乐句就是典型。后来又反向有 deterministic post-processing 把 semantic state 强制拆成 scene。

**背后缺少的 law：P-02。**

## R-04 全曲 Center → anchoring / local overwrite

为了获得“整首为什么是一个整体”，系统多次让 Center 过早参与情感生成，结果局部被写成中心命题的例子、alternative 被吞、作品变成统一故事。

**背后缺少的 law：P-05 + P-06。**

## R-05 解决“流水账” → 强制每段因果

用户要求 whole-work 有“必然性”；schema 把它实现成 mandatory residue/next_pressure，结果每段都变成 solution attempt/failure/next solution。后期才收敛到 sparse condition changes。

**背后缺少的 law：P-07。**

## R-06 防语义丢失 → over-preservation

早期 zero-loss 是为防 silent pruning；后来变成几乎所有 clause ACTIVE，defensive qualifier、retrospective note、internal support 也都被产品化。用户最终把标准修正为 independent listener value。

**背后缺少的 law：P-09。**

## R-07 Scene economy / “少更新” → listener value 被埋进内部模型

系统成功把 scene 数压下去，却把 alternatives、local WHY_NOW、部分 substantive content 只留在 metadata / model 中，用户实际拿不到。

**背后缺少的 law：P-09 + I-01。**

## R-08 Semantic coverage PASS → temporal flattening

ID 仍被引用，所以 coverage 说 PASS；但 m.32 才成立的悬问被投回 m.24–32，或者显著音乐边界被一个大 state 跨过去。

**背后缺少的 law：P-08 + I-04。**

## R-09 历史关系被削弱 → “漂亮情绪珠子”重新散开

为防强制因果，Local WHY_NOW / 历史关系一度被削得太少；用户随后直接说情感散落、成品甚至比 RAW 更云里雾里。

**背后缺少的 law：P-07。**

## R-10 anti-`不是而是` → literal regex / replacement-template collapse

系统把禁用理解成删字符串或换成“可以留意 / 是否 A 还是 B”；句法坏了、stance 没变，甚至出现“亲密成为的共享呼吸”一类删除产物。

**背后缺少的 law：P-04。**

## R-11 WHY_NOW / context 越做越强 → WHAT 消失

某些 Surface artifact 出现 `WHAT` 为空、WHY_NOW 有内容，却仍宣称 retention 100%。这说明上下文解释很容易吞掉当前体验本身。

**背后缺少的 law：P-13（Possible）+ P-03。**

## R-12 “证明修好了” → 指标/报告替代真实用户价值

历史中多次出现报告 `PASS`、100% retention、zero style regression，但实际 JSON/Surface 与报告直接矛盾。虽然这主要是工程问题，它反复说明：**任何 metric 都必须映射到真正 listener value / actual viewer prose，否则不能证明产品目标。**

# 6. SUPERSEDED IDEAS

以下内容在历史里出现过，甚至一度是重要实现，但**不应被下一轮误认成 Product Constitution**。

## S-01 — First Listen / Focus Mode / 两产品模式

**SUPERSEDED。** 用户在 2026-09-08 明确纠正：First Listen 已经完全摒弃，现在只有一个最终完整产品。

## S-02 — proposition/atom/clause 级 100% viewer survival

**SUPERSEDED AS LAW。** 早期是防止 content pruning 的有效修复；后期用户明确接受低异质、同注意力槽位、很冲突的近义内容择优保留。现行更高层标准是 independent listener value。

## S-03 — atom / Current State = viewer update / scene

**SUPERSEDED。** 内部 semantic granularity 与 viewer attention granularity 必须分开。Op.60 第一乐句是负例，Op.52 m.195 是短但必要的正例。

## S-04 — 每个 stage 都必须 residue / next_pressure

**SUPERSEDED。** 为了实现“必然性”产生了伪因果。后期明确改成 sparse condition change；没有强关系时允许 weak/unlinked。

## S-05 — Center = 一个从头提出、最后回答的问题

**SUPERSEDED / narrowed。** 用户明确纠正：Center 更接近无时间剧情的“核心困扰/核心矛盾/根本处境”；时间属于作品怎样处理它，不应塞进 Center 本身。

## S-06 — 标题 / editorial lens 反向指导 evidence

**SUPERSEDED。** 用户担心 anchoring；后期明确只能从完整独立内容向下游选 lens，不能先定标题再找证据。

## S-07 — “强边界 = 必须切字幕 / 新 Affect”

**SUPERSEDED。** 当前更高层职责是“强制重新计算当前体验”；之后仍可以得到 legitimate continuity。

## S-08 — same Affect = safe HOLD

**SUPERSEDED。** 后期历史明确废掉：同一 macro Affect 内仍可能有独立 newly_true / History / WHY_NOW 变化。

## S-09 — WHY_NOW 全局只出现 3–5 次 / 只做 long-range reflection

**SUPERSEDED。** 为减负曾把 WHY_NOW 限成极少数，结果 local historical motion 消失，用户说情感变散。后期转为语义上每个 meaningful checkpoint 可评估，是否显式显示再是 presentation decision。

## S-10 — literal ban “永远不能用不是”

**SUPERSEDED AS FORMULATION。** 真正的目标是去 correctional stance；必要 contrast 仍允许。

## S-11 — exact Op.52 字数/scene count/atom count 作为质量目标

**SUPERSEDED。** 后期明确：若 1400 字能无损表达过去 2000 字内容，是升级不是 loss；真正指标是 unique listener information retention。

## S-12 — 两字标题元素 / 固定 UI 颜色 / 1-1、1-2 编号 / persistent rail 具体形态

**ENGINEERING/PRESENTATION PRECEDENT ONLY。** 这些历史机制有参考价值，但用户多次把它们作为可改的呈现形式，而不是产品最高法。

## S-13 — `Center Thread / Situation JOIN / Sparse / Canonical / Prefix History` 这些 stage 名称

**ENGINEERING ONLY。** 当前 Architecture 明确使用这些结构，但它们只是当前实现载体。 Product Constitution 应写“局部真相不被全局覆盖”“历史影响当前”“长程关系应稀疏而有证据”等职责，不应冻结 JSON/stage 名。

# 7. OPEN CONFLICTS

这些问题历史里仍然没有真正定案。本报告不替用户拍板。

## O-01 — 长程解释到底应该多“文学化”

用户曾主动问“是不是应该稍微文学化一些”，并认可像“过去时突然变成现在时”这类 interpretive compression 的穿透力；同时一直反对脱离证据的漂亮文学和 generic metaphor。当前可以确定的是：**允许有形象、有压缩；不允许装饰性诗化和无证据剧情。** 但可接受强度没有冻结。

## O-02 — Center 在实时 viewer surface 应该多显性

Center 作为内部组织 context 已非常稳定；但 viewer 是否持续看到固定 Center 主句、right rail、阶段编号，还是大多融入 prose，历史仍有多种方案。不能把当前 UI/rail 选择写进 Constitution。

## O-03 — WHY_NOW 多少应该显式说出来，多少应该融进 CORE

后期已明确 WHY_NOW 语义不能被全局 quota 削掉，但 viewer surface 可以：融进 CORE、独立 history reflection、long-range recall。具体比例仍属于 presentation/editorial judgement，不是已经定案的法。

## O-04 — 强 musical boundary 到 viewer update 的阈值

“必须 re-evaluate”已经很稳；“什么时候 re-evaluation 后值得新 viewer slot”仍需依赖独立 listener value、history delta、Center delta、current-affect delta 等判断，没有一个历史上被接受的简单阈值。

## O-05 — Human in loop 的长期范围

人工 taste gate 对标题/高阶 editorial compression 有明确支持，但未来 AI 能力提升后，人应介入到哪一级、是否每首都必须人工选标题、是否只审异常，历史没有最终法。

## O-06 — Alternative 的最终显式程度

“真正异质的 alternative 不能被 thesis 吞掉”非常稳定；但它究竟必须同时可见、可轮换、secondary surface、recap，还是有时可只保留一种最有净增益的表达，取决于独立 listener value 和 attention slot。具体 routing 尚未冻结。

## O-07 — 形式/乐理信息在 viewer 层的可见度

音乐分句/结构证据越来越被证明是重要控制信号，但用户并未要求把最终产品做成乐理课。内部利用 formal evidence 与外部显示 theory label 的边界仍属开放 presentation 问题。

# 8. PRODUCT VS ENGINEERING SEPARATION

## Product-level

这些是本报告认为真正可能进入未来 Product Constitution 的职责：

| Product-level law | 当前最强候选 |
|---|---|
| 实时现在不能被未来知识污染 | P-01 |
| 主动文字更新必须赚到注意力 | P-02 |
| 保留具体、可感的人类体验，不把它压成抽象心理模型 | P-03 |
| 默认直接讲体验，不采用持续纠正听众的作者姿态 | P-04 |
| 保护真实多义性，整体解释不能变成 evidence filter | P-05 |
| 局部体验独立成立，全局理解只能组织/重语境化 | P-06 |
| 历史要改变后来的听法，但因果不能被强制制造 | P-07 |
| 语义必须落在正确音乐阶段，显著边界不能无检查跨过 | P-08 |
| 完整性按独立 listener value 衡量，不按 clause/atom 数 | P-09 |
| 最终要形成可记忆、作品特异、能改变以后听法的长程理解 | P-10 |

## Engineering-level

下面这些可以很好地承载产品法，但**不应写进 Product Constitution 本身**：

- `Center 不参与 Affect Distillation / Affect Boundary Review`：当前 Architecture 的重要隔离约束。 其背后产品法是 P-05/P-06，而不是“永远必须有这两个 stage”。
- `Situation JOIN` 作为 Center 与 Affect 第一次正式结合：工程 embodiment，背后是“先独立形成 local truth，再全局组织”。
- `Prefix History Extract`：工程 embodiment，背后是 P-01/P-07。
- `Sparse Transition`：工程 embodiment，背后是“只保留有证据的 condition changes，不强制全段因果”。
- `Articulation Map / Affect Boundary Reviewer`：工程 embodiment，背后是 P-08。
- `Coverage / Routing Gate` 的 Semantic / Temporal / Relational / Boundary 四维：很有价值的审计实现，背后分别对应 P-09 / P-08 / P-07 / P-08。
- ×8、2–3 路 research、某模型 thinking effort、具体 validator、ledger、hash/provenance schema：工程策略，不是产品法。
- 当前 `Realtime Recomposer`、`WHY-NOW Consolidator`、`Whole-work Model` 等名称和 DAG 位置：当前 architecture，不应冻结到 Constitution。

## Precedent/example-level

这些案例非常有价值，因为它们帮助解释原则，但不能推广为作品法：

- **Op.52 m.195**：短但必须更新，是 P-02 的正例；不是“一小节 rupture 都必须切”的法。
- **Op.60 第一乐句 m.4/m.6**：底层 onset 很细但不应连续抢 attention，是 P-02 的反例；不是“第一乐句永远只能一个 scene”的法。

# Closing assessment

如果只看最终 Architecture，很容易把“Center / Prefix History / Situation / Sparse / Articulation / Coverage”误认为产品的最高法。完整历史显示，更稳定的东西其实在这些名字下面：

1. **陪着音乐第一次发生，而不是用结局重写现在；**
2. **局部体验必须鲜活、真实、独立，多义性不能被全曲 thesis 吞掉；**
3. **已经发生的历史必须让后来获得新的意义，但不能伪造一条完美因果链；**
4. **内部研究可以很密，用户注意力必须极其克制；**
5. **压缩可以很强，但真正独立的听法不能静默消失；**
6. **最终价值不只是“这一刻讲对了”，还要让人以后重新听这首作品时真的多听见了一层。**

这六点解释了历史中大量看似不同的 bug：hindsight、therapy-speak、atom chatter、Center anchoring、mandatory causality、coverage over-preservation、strong-boundary flattening、WHY_NOW 丢失、Surface correctional voice。它们也比任何一代具体 schema 更能约束未来尚未出现的实现方式。

本 dossier 到此停止：**不把这些候选直接写成最终 Product Constitution，不提出新的 pipeline 设计。**
